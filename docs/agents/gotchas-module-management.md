# Gotchas: Module & Dependency Management + Release

> Extracted from AGENTS.md (2026-09-08 indexed-split). Edit HERE; AGENTS.md carries only the index.

### Module & Dependency Management

- **`testModules` ↔ `lintModules` coupling** — `testModules` in `flake.nix` feeds BOTH `nix run .#test` AND `nix run .#lint`. Adding a new module requires adding its path to `testModules` — otherwise it's silently never built, tested, or linted. Meta-test: `TestEveryGoModDirIsInTestModules`.
- **API-surface changes require golden regen in the same edit** — Whenever you add/rename/remove an exported symbol, immediately regenerate: `cd cmd/api-stability && GOWORK=off go run -tags "goexperiment.jsonv2" . --update`. Don't rely on the `#verify` gate — it catches it but wastes a 3-4 min cycle.
- **BuildFlow owns `.git/hooks/pre-commit`; two hook installers fight** — `buildflow precommit install` REGENERATES the hook file and wipes any manual edits; `nix run .#install-hooks` (copies `scripts/pre-commit.sh`) overwrites it the other way. Only one system can own the hook. TWO gates are wired BOTH in canonical `scripts/pre-commit.sh` AND appended post-BuildFlow in the installed hook — the api-stability golden check and the staged-`.go` syntax gate (`scripts/check-staged-go.sh`, blocks concurrent-session mid-write corruption). The appended blocks are wiped by the next `buildflow precommit install`; `scripts/install-hooks.sh` is the canonical restorer of BuildFlow-hook + both appended gates — re-run it after reinstalling.
- **Every directory with a `go.mod` must be in the api-stability modules list** — Meta-test `TestEveryGoModDirIsInModulesList` enforces this. Add new modules to `cmd/api-stability/main.go` `modules` slice in the same change.
- **Verify module version exists before requiring it** — Before adding `require .../module/v4 v4.x.y`, ALWAYS check the tag exists: `git tag -l '<module>/v4.x.y'`. Commit `169b5d42` shipped a broken go.mod because a tag was assumed but never created.
- **Private Go module auth (non-interactive fetch)** — devShell sets `GOWORK=off`, so `go mod download` fetches internal modules from VCS. `GOPRIVATE` uses HTTPS which fails without credentials. The flake `shellHook` exports `GIT_CONFIG_*` to redirect HTTPS → SSH. Symptom: `git ls-remote -q origin ... exit status 128` inside `~/go/pkg/mod/cache/vcs/`.
- **Auto-commit daemon can break the build** — Always run `go build -tags "goexperiment.jsonv2" ./...` after a daemon commit, not just `nix run .#build` (which uses `allPaths` — verify cmd/* modules actually compile).
- **Version-sequence breaks in published tags** — tags must be monotonically increasing in BOTH semver AND commit ancestry. Always tag with NEXT semver above all existing: `git tag -l '<module>/v4*' | sort -V | tail -1`.
- **Nested cmd modules need `/v4` in go.mod for v2+ tags — `tag-release.sh` now enforces it (2026-09-01, issue #20)** — `cmd/cqrs-lint` shipped v4.2.0–v4.7.0 over the suffix-less module path; the proxy refuses such tags, so they never appeared in `@v/list` and `go install ...@latest` silently resolved to v0.2.0 (60 rules). The guard rejects any tag whose major version mismatches the module path at the tag (v0/v1 require NO suffix — the guard branches, it does not compare `""` to `"0"`). Binary name is UNCHANGED by the suffix: Go strips `/vN` when naming a module-root main package (verified: `go install .../cmd/cqrs-lint/v4@latest` → binary `cqrs-lint`). `cmd/cqrs-bench` had the identical latent bug, fixed in the same wave (v4.3.0). `cmd/cqrs-lint/v0.2.1` is a DELIBERATE deprecation-stub tag on the dead suffix-less path (one-off branch commit; root package replaced by a stub that prints the new install command and exits 1 — no go.mod requires, so it builds standalone). **`cmd/cqrs-lint/v4.8.0` is POISONED**: the tagger's const-bump sed had broken shell quoting (embedded quotes closed the double-quoted string) and shipped `const version = 4.8.0` unquoted — a syntax error caught by the clean `go install` check, not by the tagger (its build check ran BEFORE the bump; now after, plus a post-bump assertion). v4.8.1 supersedes it. Verification lesson: `git show <tag>:<file> | grep const` showed the line and I missed the missing quotes — grep for the exact quoted form, and always finish a release with a clean-dir `go install ...@latest` + run, which is what actually caught this.
- **Retracts are inert until a TAG carries them (2026-09-11)** — a `retract` directive sitting on master changes nothing for consumers: `@latest` resolution walks the proxy's tags, so the retract must ship inside a NEW tag of that module. Precedent: storage v4.7.0, then cmd/cqrs-lint v4.10.1 (poisoned v4.8.0) and badgerengine v4.2.1 (retracts v4.0.0–v4.1.0 for the restart-seeding data loss — ADR-0118 incident addendum). Tag a patch even when the code is identical to the current release; the reason comment above the directive survives `go mod tidy` and is what pkg.go.dev displays. `cmd/cqrs-bench/v0.1.1` completes the dead-path stub treatment (mirrors v0.2.1; one-off detached-worktree commit, never merged). The issue-#20 class is now mechanically guarded: `tag-release.sh --audit` replays the path-vs-tag guard (`path_matches_major`, shared with the release flow) over every tag of every module — one-shot run 2026-09-11: 1078 tags checked, 24 historical violations, all in dead/example paths; `--smoke` follows the proxy check with a clean-dir `go install module@version` + run for main-package modules — `go list -m` proves the proxy SERVES a version, only the install probe proves it COMPILES (that distinction is exactly how v4.8.0 shipped poisoned); fixture tests in `scripts/test-tag-release.sh`. The release flow's version-const bump block is GONE (cqrs-lint reports its version from build info: real tag under `go install …@vX.Y.Z`, `dev-<sha>` in-repo, `dev` + ldflags commit/date under Nix) — a cut mutates no source files, and `bump-cqrs-lint.sh` is tidy + vendorHash only.
- **Multi-module tag waves have four hard mechanics** (2026-08-22 wave: 8 tags, 66-module pin sweep; 2026-08-29 wave: 39 tags, zero-replace finish): (1) `go mod tidy` does NOT bump require pins — it resolves at PACKAGE level, so a pin on an older tag that lacks new SYMBOLS only fails at BUILD time; pre-bump every dependent module's pin (`go mod edit -require=...@<tag>`) BEFORE running `scripts/tag-release.sh`, or its standalone-build verify aborts the tag. (1b) `go build` alone does NOT validate a pin — TEST files can use sibling symbols production code never imports (event's BDD tests needed `schema.UpcastSourceTransform`; integration's tests needed `middleware.CommandActorContext`); verify with `go test -run ZZNONE -count=1 ./...` per module. (2) `GOPRIVATE=github.com/larsartmann/*` means siblings resolve via DIRECT VCS fetch from origin — a tag must be PUSHED before any dependent module's tag-time tidy can see it; interleave cut→push→next. (2b) When a concurrent session keeps the tree dirty and blocks `tag-release.sh`'s clean-tree check, run the script from a DETACHED WORKTREE (`git worktree add --detach /tmp/wt HEAD`; re-`git -C /tmp/wt checkout --detach master` after each main-tree pin commit; push only the tag ref) — the tag captures exactly the committed state, identical to the normal flow. (3) A published consumer of a changed API can strand OTHER consumers: published storage v4.6.0's timer twin predated branded TimerID, so consumers bumping scheduling v4.3.0 failed standalone until storage was re-tagged v4.8.0 and their storage pins bumped — always run the GOWORK=off build matrix over ALL swept modules after a wave. The api-stability golden is unaffected by go.mod sweeps, but cqrs-lint's taskmanager golden pins the version set (V006) — refresh it in the same wave. (4) In shell one-liners, `go mod edit`/`go build` act on the CURRENT directory's module — sweeping N modules requires `cd` into each; a sweep loop that skips the `cd` reports vacuous GREENs while changing nothing.
- **Bash maps keyed by module use plain paths, never `/` spaces — and slashed keys MUST be quoted** — `check-module-layers.sh` LAYER/DEP_BUDGET keys MUST be literal module dirs (`LAYER["storage/memory"]`, `LAYER["cmd/cqrs-gen"]`). ROOT CAUSE of the recurring mangling (4 occurrences through 2026-08-15): the buildflow pre-commit hook runs `shfmt` on staged `.sh` files, and shfmt formats unquoted slashed subscripts (`LAYER[storage/memory]`) as arithmetic (`LAYER[storage / memory]`), silently disabling the budget/layer checks. Fix: quote every slashed map key (`LAYER["storage/memory"]=4`) — shfmt leaves quoted subscripts untouched and bash semantics are identical. The api-stability meta-tests (`normalizeLayerKey`) accept both forms. EXCEPTIONS deps also use plain `/` (`storage/memory`). Test-infra modules (`event/v4/eventtest`, `testutil`, `testutil/pgtestcontainer`) are exempt from layer ordering via `TEST_INFRA_MODULES`.
- **WithoutGlobalRegistration for isolated OTel providers** — `otel.Setup(cqrsotel.WithoutGlobalRegistration())` skips global calls. Use in tests and multi-service setups where global state would conflict.
- **Codec-critical methods require a consumer-pin sweep in the same wave** — 2026-08-17: `id.ActorID.MarshalBinary` (what keeps CBOR from silently zeroing the actor) shipped in `id/v4.5.0` while all 59 consumer modules still pinned `v4.4.0`; workspace greens (go.work resolves local source) hid that every `GOWORK=off`/published build silently lost the actor. Whenever a method that codecs/stores depend on lands in a tagged module, bump every consumer pin in the same wave (`grep -rl 'module/v4 vX' --include=go.mod .` + `go mod edit -require` + `go mod tidy`), and gate with a round-trip test run under `GOWORK=off`.
- **Pin bumps WITHOUT a per-module tidy leave go.sum missing `/go.mod` hashes — production `go build` stays green, tests go red (2026-09-11 wave)** — the record v4.5.0 / id v4.6.0 / pgtestcontainer v4.2.0 pin bumps landed with incomplete go.sum files in 5+ modules (`metaengine/badgerengine`, `metaengine/mysqlengine`, `idempotency/sqlstore`, `projectionhost`, `stack/bench`, `stack/postgres`, `testutil/pgtestcontainer`): the module `h1:` hash is present but the `/go.mod h1:` hash is missing, so every `GOWORK=off go test` (CI Module-matrix, verify-ci, VM legs) fails with `missing go.sum entry for go.mod file` while workspace builds AND `go build ./...` (which skips test-only deps) stay green — exactly why it shipped unnoticed. Detection: per-module `GOWORK=off go vet -tags "goexperiment.jsonv2 integration" ./...` (vet type-checks tests; build alone is blind to test-only deps). Repair: `GOWORK=off GOFLAGS=-mod=mod go mod tidy` (or the suggested `go mod download <module>`) per failing module — never hand-edit go.sum. Iterate: fixing one missing hash unmasks the next (mysqlengine needed pgx → record → id, three rounds).
- **Unpublished-symbol sibling replaces (middleware/encryption/signing, 2026-08-17)** — these three modules reference event/metadata symbols that exist only on disk (`metadata.BrandedString`/`ActorString`, `event.ErrInnerStoreNot*`, `event.Rejecting*`); without `replace ... => ../event` + the cascading `=> ../metadata` (replaces do NOT cascade), standalone `GOWORK=off` builds fail with `undefined:`. Drop these replaces in the existing replace-strip sweep once metadata/event tags carrying the symbols are cut.
- **Examples are self-lint exempt but kept v5-clean anyway (2026-09-06 policy, decision Q3 default)** — `IsLibrarySelfLint()` skips V007/F030 for all in-repo code including `example/`, because the library legitimately references its own deprecated surfaces while they exist. Policy: examples must not USE v5-removed APIs regardless — they are the copy-paste surface for every new consumer. `getting-started` now composes via `system.New` (DomainConfig + DeploymentConfig) + metaengine folds (verified by its SQLite-path test); the V007 drift meta-test (`cmd/cqrs-lint/pkg/rules/version/v007_drift_test.go`) keeps the removal tables honest, and engine drivers self-register so a deployment's blank imports are part of the lesson.
- **KV-engine `ReadCosts` semantics (badger/bbolt/pebble, calibrated 2026-08-30)** — all 7 engines now set 4-field `ReadCosts` from per-pattern benches. For the KV engines: there is NO pushdown/aggregate backend, so `NsPerFilteredScan` ≈ `NsPerScan` (a Go-side filtered scan costs a full scan + predicate — pebble's bench drives `ScanRawValues`, its actual `executeFilteredScan` path). **`NsPerAggregate` = CounterGet per-row cost on EVERY engine (ADR-0133)**: `ReadAggregate` is declared only for ADTCounter queries and executes `CounterGet`; the typed `Sum/Avg` path (AggregateReader) bypasses the planner entirely, so SQL-SUM numbers must NOT price the pattern. Every engine now carries a live-measured CounterGet constant (G1 closed 2026-09-01: duckdb 420, pg 250, mysql 320, dgraph 2700 ns/row; raw runs in docs/benchmarks/calibration-2026-08-30.md). **Dgraph per-OP divergence CLOSED 2026-09-06**: `BenchmarkCalibration_DgraphScaled` (result sizes 100/1K/10K) measured per-row slopes ~2.2 µs/row; `NsPerScan`/`NsPerFilteredScan` re-shipped as 2_200 per-row — the single-RPC fixed cost (~0.5-0.7 ms) is the NetworkRTT prior's job, NEVER a per-row field (a per-RPC total there overstates a k-row estimate ~k×). Point-lookup constants (`XxxNsPerRead`) now feed `ReadCosts.NsPerPointLookup` — keep the exported constants (api golden) and re-anchor them from the Get benches, never assign the deprecated `NsPerRead` field (its SA1019 exclusion was deleted 2026-08-30). **Constants are single-sourced since 2026-09-06**: `scripts/calibration-drift.sh` reads the SHIPPED values live from each engine's `Profile().ReadCosts` (per-engine `TestCalibrationConstantsDump`, `CALIB_DUMP=1`) — the profile is the only place a constant is edited; the baseline doc is a dated measurement record, not a comparison table.
