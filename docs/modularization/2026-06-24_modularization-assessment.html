03Refinement 1 — kill the test-dependency leak

Failure mode #3 (test dep leak)

Core modules carry storage/memory as a direct production require

event, command, decider, watermill — each imports storage/memory only from _test.go

This is the textbook go-modularize failure mode: test-only libraries listed in production require. It manufactures a require-graph cycle (event → storage/memory → command → event) and means the leaf event module's advertised "3 production deps" is undercut by a Layer-4 test impl in its graph.

Fix Replace storage/memory usage in those tests with event/eventtest fakes (FakeStore/FakeBus already exist) or in-package stubs, then go mod tidy each. Verify go mod graph | grep shows no event → storage/memory edge.

04Refinement 2 — resolve the genproto conflict

Failure mode #4 (workspace conflict)

transport/grpc cannot join go.work today

ambiguous import: googleapis/rpc/status in both genproto (mono) and genproto/googleapis/rpc (split)

grpc v1.81.1 requires the split genproto/googleapis/rpc; the merged workspace also resolves the monolithic genproto, and both provide googleapis/rpc/status. Until aligned, transport/grpc must be built/tested with GOWORK=off.

Fix Coordinate a workspace-wide bump: drop the monolithic genproto, require only the split genproto/googleapis/{rpc,status} modules across the graph (go mod tidy each), then add ./transport/grpc to go.work + flake testModules.

05Replace / Workspace Strategy

Current strategy is correct and should be preserved: local replace => ../x directives inside each module's go.mod for sibling resolution, plus a root go.work for developer convenience. The two are not mixed for the same pair (no failure-mode #4 tangle). When publishing, go.work is ignored by consumers and the versioned requires take over. No change recommended.
