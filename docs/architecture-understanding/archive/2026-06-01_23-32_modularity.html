Architecture Quality Matrix

Dimension Grade Assessment
Module Isolation A Each module has its own go.mod. 3 leaf modules (id, dispatcher, codec) have zero internal deps. Layer dependencies flow strictly downward. No circular deps.
Interface Segregation A EventSink/EventSource/Journal/SeekableJournal is textbook ISP. CommandSink/CommandSource mirrors it. Each interface is 1-4 methods max.
Composability A- Consumers import what they need. No opinionated transport or message broker. Middleware chains compose. Branded IDs prevent mixing. Only gap: middleware 3x duplication reduces composability of new middleware.
Testability A- eventtest provides shared fakes and store suite. 84-100% coverage. BDD tests for critical paths. Gap: store suite doesn't cover all backends for edge cases. FakeStore duplicates MemoryStore.
Service Orientation B+ Library, not framework — correct choice. But some modules cross boundaries: command re-exports event types, storage errors duplicate pebble errors, middleware couples to all three domains. ADR-0003 (multi-module) is well-motivated.
Scalability A- Three store backends (Memory, SQL, Pebble) with consistent interfaces. Projection runner handles replay+live. Turso adds edge sync. Pebble adds embedded KV. Missing: no outbox pattern implementation yet (documented in CONTEXT.md but not built).
Dependency Hygiene A Minimal production deps: oklog/ulid, go-branded-id, go-error-family, samber/ro, go-faster/yaml (catalog only), otel (opt-in). No ORMs, no web frameworks, no database drivers in library modules.
Error Architecture B+ 5-family taxonomy (Rejection/Conflict/Transient/Infrastructure/Corruption) is excellent. Gap: decider uses unclassified fmt.Errorf, some modules bypass the taxonomy, three separate ErrHandlerNotFound sentinels.

Coupling Hotspots

command → event (tight coupling)

command/aggregate_ref.go re-exports event.AggregateType, event.AggregateRef, event.ParseAggregateType, event.NewAggregateRef. command.Metadata mirrors event.Metadata fields. These create a module boundary violation: command depends on event's type system.

Impact: Adding metadata fields requires updating both packages. errors.Is across module boundaries breaks.

middleware → command+event+query (3x coupling)

Every middleware function is triplicated for command/event/query. The module depends on all three domain modules simultaneously. Adding a new domain (e.g., "saga") requires updating every middleware file.

Impact: ~500 lines of duplication. Bug fixes must be applied 3 times. O(N×M) growth where N=concerns, M=domains.

storage ↔ pebble (error duplication)

pebble/errors.go and storage/sql/errors.go define semantically identical sentinels (ErrAggregateTypeMismatch, ErrAggregateIDMismatch, ErrVersionMismatch) with different error codes. Consumers must know which backend produced the error.

Impact: Cross-backend error checking is fragile. Migration from one backend to another may break error handling.

signing → signing/multisig (pattern duplication)

signing/middleware.go and signing/multisig/middleware.go implement the same extract→verify→next pattern. Error code strings duplicated as raw literals across both packages.

Impact: Adding a new signing scheme (e.g., threshold signatures) means duplicating the middleware again.

What works well

  • Consumers compose their own stack — no framework lock-in
  • Each module is independently importable and versionable
  • Interface-first design enables adapter substitution (MemoryStore in tests, SQLEventStore in prod)
  • Clean layering: domain modules (L0-L1) have no knowledge of infrastructure (L4-L5)
  • Replace directives allow local development while preserving GOWORK=off CI isolation

What could improve

  • Shared types package: AggregateRef, AggregateType, and Metadata live in event/ but are re-exported by command/. A shared types module (or accepting that consumers import event/ directly) would eliminate the re-export pattern.
  • Generic middleware: The 3x fan-out in middleware/ is the biggest architectural smell. Generic middleware[H] would collapse this to 1x and make new domains O(1) instead of O(N).
  • Unified store errors: Backend-specific sentinels should share a common base (e.g., event.ErrVersionConflict) with backend-specific wrapping for context.
  • Missing outbox: CONTEXT.md documents the Outbox pattern but no module implements it. This is the main gap for production-grade event publishing.
  • Schema/codec as optional: schema/ and codec/ are always imported transitively. Making them truly opt-in (behind build tags or interfaces) would reduce the minimum import surface for consumers who don't need schema evolution.

Composable ✅

  • • Store → any EventSink/EventSource implementation
  • • Middleware → chains compose via Use()
  • • Catalog → registry + N exporters
  • • Decider → pure functions, any State type
  • • Projection → builder pattern, On[T]() registration

Less Composable ⚠️

  • • Middleware → can't write once for command+event+query
  • • Storage backends → error types differ
  • • Dispatcher → 4 generic params, hard to extend
  • • Reactive → not wired into dispatchers
  • • Signing → single-sig/multi-sig middleware diverge

Recommendations

P0

Generic middleware[H] — eliminate 3x duplication

Write each concern once. Thin adapters for command/event/query backward compat. Reduces O(N×M) to O(N+M).

P0

Consolidate sentinel errors across modules

Single ErrHandlerNotFound in dispatcher/ (re-exported by command/query). Single ErrVersionConflict in event/ (used by all backends). Cross-module errors.Is works again.

P1

Remove command/ type re-exports

Consumers import event.AggregateRef directly. Eliminates the module boundary violation and reduces maintenance burden.

P1

Build outbox pattern implementation

Currently documented in CONTEXT.md but not implemented. Critical for production-grade at-least-once event publishing.

P2

Unify signing middleware pattern

VerifyFunc abstraction in signing/ — single-sig and multi-sig become configurations, not parallel hierarchies.

P2

Expand store test suite for all backends

Edge cases (concurrent writes, time-travel, identical timestamps, empty streams) tested once, run against Memory, SQL, and Pebble.

Overall Assessment

Grade: A- — A well-architected library with strong module isolation, clean ISP, and excellent composability. The main drag on quality is middleware duplication (P0 fix). Secondary concerns are cross-module error sentinel fragmentation (P0) and command/ type re-exports (P1). The architecture is fundamentally sound — these are fixable refinements, not structural problems.
