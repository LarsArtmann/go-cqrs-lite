Architecture Layers Reconsidered

A first-principles audit of go-cqrs-lite's module dependency architecture. The trigger: "Why is kv/ Layer 0?" — the question that exposed a broken layering system built on a god module conflating three distinct architectural concerns.

Root cause: event/errors.go is a 1:1 re-export of go-error-family. Every module that needs error classification pulls in the entire event domain model + store/bus contracts as baggage. The layer numbering is broken because it conflates domain model, error taxonomy, and infrastructure contracts into a single linear stack.

01 The Core Problem: One Package, Three Concerns

event/ is not a module — it's three modules in a trench coat. It contains domain types, error classification, and infrastructure contracts. Every consumer gets all three whether it needs them or not.

The coupling tax: A module like idempotency/ that only needs event.NewConflict() for error classification pulls in the entire event store/bus interface surface. It doesn't use events at all — it just wants to classify a duplicate-key error.

04 The Command/Query Coupling Problem

command/ lists event/ as a direct dependency. Some of that is legitimate (shared domain types), but most is artificial (error classification):

✅ Legitimate coupling

// Domain types — shared vocabulary
command/aggregate_ref.go:
  type AggregateRef = event.AggregateRef
  event.NewAggregateRef(...)
  event.ParseAggregateType(...)

AggregateRef is the shared domain type for targeting aggregates. This coupling is correct — commands target aggregates.

❌ Artificial coupling

// Error classification — re-export trap
command/errors.go:
  event.NewRejection(...)
  event.NewConflict(...)
  event.NewInfrastructure(...)
command/dispatcher.go:
  event.WrapRejection(...)
  event.Classify(...)

15+ error calls route through the re-export. command/ pulls in the entire store/bus interface surface to get event.NewRejection.

The most interesting case: query/. If the error taxonomy is extracted, query/ has zero dependency on event/. This means commands and queries don't need events — proving the CQRS separation. A consumer could use query dispatch without pulling in any event sourcing machinery. query/store.go already bypasses to go-error-family directly — the rest should follow.

06 Target: Four Tiers (Not Seven Layers)

Replace the misleading 7-layer system with four tiers that represent real architectural boundaries. Within each tier, modules depend on each other freely. Cross-tier dependencies flow upward only.

Composition Tier
Wire everything together for the consumer
stack/ stack/sqlite/ stack/postgres/ catalog/ scenario/ testutil/ cmd/ example/
Operations Tier
Cross-cutting concerns applied across the system
middleware/ + idempotency/ (sub-pkg) otel/ prometheus/ signing/ encryption/ projectionhost/ listing/ scheduling/
Infrastructure Tier
Implement the contracts for specific backends
storage/ storage/pebble/ storage/turso/ storage/memory/ transport/http/ transport/grpc/ watermill/
Domain Tier
Pure domain model + contracts. No backend knowledge.
id/ codec/ kv/ (raw) event/ command/ query/ decider/ deriver/ projection/ schema/ dispatcher/

07 Domain Tier: Internal Structure

The Domain Tier itself has internal layering — three sub-levels with clear dependency direction:

Primitives — zero internal deps
id/ — branded IDs (ULID, markers) codec/ — encoding contract (JSON, CBOR) kv/ (raw) — Store, Reader, Writer, Batch
Message Types — depend on primitives
event/ — ImmutableEvent, Metadata, Store/Bus interfaces command/ — Command, AggregateRef query/ — Query, Type (NO event/ dep!)
Domain Logic — depend on message types
decider/ — Decider[State], Repository[State] deriver/ — event→command derivation projection/ — Projection interface schema/ — upcasting, versioning dispatcher/ — generic dispatch

The kv/ split: Currently kv/ contains both raw byte-level types (Store, Reader, Writer) AND typed wrappers (TypedStore[T,K], Cache[T,K]). The raw types are true Layer 0 — zero internal deps. The typed wrappers need codec/ and otter. Split: kv/ (raw) stays Layer 0, kv/typed/ moves up.

08 Migration Path (Prioritized by Impact / Effort)

1

Extract Error Taxonomy

Replace all event.* error calls with errorfamily.* direct imports. Delete event/errors.go. Run go mod tidy in each module to drop indirect deps. Zero API change visible to consumers — same functions, different import path.

80% benefit ~50 files Low risk
2

Fix kv/ Layering

Move typed_store.go, cache.go, view_store.go to kv/typed/. kv/ keeps only raw byte-level types. kv/ go.mod drops codec/ and otter. kv/ becomes a true Layer 0 leaf module.

High clarity ~15 files Low risk
3

Merge idempotency/ into middleware/idempotency/

Move the Store primitive + KVStore adapter into a middleware/idempotency/ sub-package. Create a generic NewIdempotency[M] factory following the NewValidation[M] / NewTracing[M] precedent. See the dedicated merge plan.

Medium ~20 files Low risk
4

Clean Up event/ Test Deps

Move test-only deps (schema/, snapshot/, storage/memory/) out of the production require block. Go can't separate test-only deps natively — may need a separate test module or move affected tests to integration/.

Medium Go limitation
5

Document the Tier Model

Update AGENTS.md Module Graph to use the four-tier model. Update flake.nix testModules. Update cmd/api-stability/main.go to scan all packages including currently-missing ones.

09 What NOT to Change

Not everything is broken. These decisions are correct and should stay:

event/ contains Store/Bus interfaces

Interfaces are domain contracts, not implementations. Every event consumer needs both types and interfaces. The problem was never "Store is in event/" — it was "error taxonomy is in event/".

command/ → event/ for AggregateRef

Legitimate domain coupling. Commands target aggregates. AggregateRef is the shared vocabulary.

decider/ → event/ + snapshot/

Core ES pattern — the decider loads events from a store and snapshots state. This coupling is the architecture.

dedup/ as separate leaf module

True Layer 0 (zero deps). Different concern from idempotency (ring buffer vs TTL store). Correctly separate.

Multi-module workspace (go.work)

Each module having its own go.mod is deliberate — consumer import isolation. The workspace ties them together for development.

Import go-error-family directly

Not a wrapper module. go-error-family IS the taxonomy — it already has the right API. 8 modules prove it. A CQRS wrapper adds indirection without value.

10 The Verdict: Is This Worth It?

✓ Argument FOR

  • 30+ modules have artificial coupling to event/
  • Error taxonomy trap makes every new module carry event baggage
  • kv/ Layer 0 claim is false and misleading
  • Phase 1 is ~50 file mechanical change for 80% of the benefit
  • query/ could become truly independent of event/
  • Sets up clean v4 boundaries

✗ Argument AGAINST

  • It works today. The coupling doesn't cause runtime bugs.
  • Consumers don't see the coupling — they import what they need.
  • Just fix the AGENTS.md text, don't restructure.
  • 50 files is a lot of churn for "just change the import path."
  • query/ already works — who cares if it imports event/?
  • v4 is not planned.

Recommendation: Phase 1 (extract error taxonomy) is worth doing. The coupling is real, the fix is mechanical, and it unblocks independent use of query/command without event baggage. Phase 2 (kv/ split) is worth doing because the false Layer 0 claim will mislead contributors. Everything else can wait for v4.
