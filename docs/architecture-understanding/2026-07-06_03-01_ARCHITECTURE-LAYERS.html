go-cqrs-lite — Architecture Layers

Honest audit of the current 7-layer system and the proposed four-tier target. The core problem: event/ is a god module conflating domain model, error taxonomy, and infrastructure contracts — creating artificial coupling across 30+ modules.

PROBLEM 1 kv/ is NOT Layer 0

kv/ depends on codec/ (TypedStore serialization) and otter (Cache). It's actually Layer 1.

PROBLEM 2 event/ is a god module

Conflates 3 concerns: domain model, error taxonomy (1:1 re-export of go-error-family), and infrastructure contracts (Store/Bus interfaces).

PROBLEM 3 Error taxonomy trap

~129 files across 30+ modules import event/ ONLY for error classification. They pull in the entire event domain model as baggage.

What happens to event/?

event/ keeps its domain model + interfaces (ImmutableEvent, Store, Bus). Only errors.go is deleted — it was a 1:1 re-export that created the coupling.

What about command/ → event/?

Stays! command/ needs event/ for AggregateRef (shared domain type). Only the error-classification calls change from event.NewRejection() to errorfamily.NewRejection().

Why not a CQRS-specific errors/ module?

Option A (direct import) beats Option B (wrapper module): go-error-family already has the right API. The 8 modules that already import it directly prove the pattern. A wrapper adds indirection without value.
