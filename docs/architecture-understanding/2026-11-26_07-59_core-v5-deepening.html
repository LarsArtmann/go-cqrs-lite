Problem. Four hand-written bridges each re-map the same facts from two parallel metadata sources into record.Record, so cause has four homes, actor spans six files, and the precedence rules live in the bridges instead of in the type.

Solution. record.Record becomes the single implementation of a stored fact or intent; Event, Command and Query sit on it, and the bridges, the parallel metadata and the five twin fields are deleted.

  • One home per fact
  • Four bridges deleted
  • Precedence rules deleted
  • Five twin fields die
  • Tests hit one interface
  • Forks inherit the final shape
ADR-0123 §5 already decided this (2026-08-09): “Duplicate metadata types are deleted.” ADR-0166's status line and ruling A of the 2026-11-20 pack defer it to T26, inside a module that has never shipped. The M03–M09 typed surface survives; only the twins and the bridges go.

Problem. core/v5 carries v4's deprecated names so that the codemod needs no rename table, which makes v5 a second copy of v4 and schedules a second breaking cut at T26 for every consumer that migrated onto a twin.

Solution. v5 ships with zero deprecations and zero aliases; cqrs-upgrade carries the v4 names in a rename table and proves its output compiles against core/v5.

  • One migration, not two
  • v5 ships clean
  • Codemod output provably builds
  • Twin count only goes down
  • v4 debt stops being copied
Ruling A (2026-11-20 pack) chose “twins stay until T26” to keep the import rewrite mechanical. The fleet plan's own codemod-v2 row already lists a rename table, and that same plan forks storage, schema and encryption minus their deprecated shells while the nine forked with theirs. Veto is one sentence per the pack; M03–M09 survive.

Problem. Nine packages export 657 symbols because they were nine v4 modules, not because anything outside the module needs them: the composition root and both companions touch 151 identifiers, go-appkit, the first migration target, touches 30, and metadata and dispatcher reach none of the three.

Solution. Re-derive the public interface from the three real importers (apps through the composition root, drivers, tooling) and fork the remaining packages by demand instead of by tier.

  • Interface sized by importers
  • One interface for apps: system
  • Zero-importer packages stop forking
  • READMEs stop selling v4
  • Plumbing becomes internal
ADR-0152 set the target; copy-forward set the pace. The target is one core module of about 30 packages; nine exist, all Tier 0–1, and the fleet plan's stated result is “import-parity for the whole fleet”. ADR-0123 §7 names the interface apps are meant to see: developers declare domain types only. One constraint stays: drivers remain modular, so event, id, record, command and query stay importable.
