go-cqrs-lite: Can It Scale?

A deep review of modularity, coupling, composability, and scalability across 48 Go modules. The library has excellent patterns and serious god-module debt. This report identifies what breaks at scale and provides a concrete roadmap to fix it.

◆The Bottom Line

go-cqrs-lite has genuinely excellent design patterns — ISP-honest interfaces, a composition-root Bundle, generic middleware, functional deciders, three projection tiers. These are the right abstractions, well-executed. The library is usable today for single-process applications.

However, three structural problems will block production scale: (1) event/ is a god module coupling 17+ modules to unrelated concerns. (2) storage/ is a god module mixing every persistence concern in one package. (3) The kv/ interface has zero context.Context parameters — 11 I/O methods with no cancellation or timeout.

Verdict: Production-ready for single-process. Needs 3 focused refactors before multi-node deployment. The error taxonomy extraction (Pareto: 80% benefit, 20% effort) is the single highest-impact change.

◆What's Already Excellent

Before the criticism: these patterns are genuinely best-in-class for a Go CQRS library.

+
ISP applied aggressively EventSink ≠ EventSource, Publisher ≠ Subscriber. Consumers depend on exactly what they need. event/store.go, event/bus.go
+
Generic middleware factory Middleware[M] + MessageAdapter[M] + AsCommand/AsEvent/AsQuery bridges. One pattern, 9 concerns × 3 types = 27 middleware factories. middleware/generic.go
+
Functional decider pattern Pure Apply(state, event) → state + impure Repository.Execute shell. Singleflight load coalescing. decider/decider.go
+
Three projection tiers KV (document per key), Relational (multi-table SQL), Graph (nodes + edges). Each with atomic writes, dialect-portable, correct abstraction level. storage/relational/, graph/
+
Bundle composition root ~20 ISP-honest fields, functional options, nil-able optional capabilities. The deployer picks a backend; the app never touches a storage driver. stack/bundle.go
+
Branded IDs with phantom markers id.Of[T] makes impossible states unrepresentable. UserMarker, CommandMarker, EventMarker all exported. id/
+
Multi-module workspace 48 independent go.mod files. Consumers import exactly what they need. A consumer wanting just branded IDs imports id/v3 (0 internal deps).
+
Managed projection host Crash-restart lifecycle, dead-letter queue, checkpoint persistence, OTel tracing, bounded dedup ring, graceful drain. The "last loop every consumer rewrites" is now a module. projectionhost/host.go

01God Module #1: event/

event/ is the most impactful structural problem. It conflates nine distinct concerns into one package with 130+ exported symbols, imported by 17 modules across 84 files.

Critical · Blocks modularity

event/ mixes 9 unrelated concerns

event/ — 39 non-test files, 3,617 lines, ~130 exports

What's in event/ today:

# Concern Key Symbols Belongs In
1 Core domain types Event, ImmutableEvent, Type, Version ✅ Correctly here
2 Persistence interfaces Store, EventSink, EventSource, Journal ✅ Arguably fine
3 Pub/sub interfaces Bus, Publisher, Subscriber ✅ Arguably fine
4 Checkpoint tracking CheckpointStore, CheckpointSink ❌ Projection concern
5 Tombstone/soft-delete DetectTombstone, MarkTombstone ❌ Aggregate lifecycle
6 Command causality CommandCausalityEnricher ❌ Cross-module bridging
7 Shared metadata plumbing CustomData[K], Tracing ❌ Creates command→event dep
8 Codec utilities DecodeBase64String, ExtractCustomBytes ❌ Utility functions
9 Replay mode ProcessingMode, IsReplay ❌ Infrastructure concern
Fix: Keep concerns 1-3 in event/. Extract concerns 4-9 into their own modules or into the consumers that actually use them. This is the Pareto fix — 80% of the coupling benefit from ~50 file changes.
Critical · 30+ modules affected

30+ modules import event/ ONLY for error classification

event/errors.go — 1:1 re-export of go-error-family

Modules like command/, query/, signing/, middleware/, schema/ import event/ solely for event.NewConflict() — which is a line-for-line re-export of go-error-family. They drag in the entire event domain model + store/bus contracts as transitive baggage.

8 leaf modules already bypass this and import go-error-family directly, proving the re-export adds no value. The error taxonomy extraction was identified in the ARCHITECTURE_LAYERS_RECONSIDERED.md analysis but never executed.

Fix: Replace every event.NewConflict(...) with errorfamily.NewConflict(...). Delete event/errors.go. ~50 files, mechanical find-replace. Zero API change visible to consumers.

02Hidden Coupling

Critical · Compile-time dependency

command/ has a hard compile dependency on event/

command/aggregate_ref.go, command/metadata.go

command/metadata.go embeds event.CustomData[MetadataKey], and command/aggregate_ref.go aliases event.AggregateType and event.AggregateRef. This means commands and events are not independent CQRS sides — every change to event.Tracing, event.CustomData, or event.AggregateRef forces a recompile of command/ and all 8 downstream consumers.

This violates CQRS separation: commands should be dispatchable without pulling in event sourcing machinery. A consumer who wants only command dispatch must import event/ transitively.

Fix: Extract AggregateRef and CustomData[K] into a shared shared/ or types/ module (Layer 0). Both event/ and command/ depend on it; neither depends on the other.
Important · Test deps leak as production deps

event/ declares test-only deps as production requirements

event/go.mod — requires schema/v3, snapshot/v3, storage/memory/v3

Three "direct production dependencies" (schema/, snapshot/, storage/memory/) are only imported in test and example files. Go's go mod tidy cannot separate test-only deps from production deps in a single module, so they leak into the production require block.

This makes event/ appear to be Layer 4+ when its real production deps are only codec/ and id/. The layer numbering is a lie.

storage/ mixes every persistence concern in one package

storage/ — 109 non-test files, 14,330 lines, 12 internal deps

04Scalability Gaps

Critical · Hung I/O blocks forever

kv/ interface has ZERO context.Context parameters

kv/kv.go — 11 I/O methods, 0 take context.Context

Get, Set, Delete, Has, Batch, Commit, NewIterator, Next, Close, SetIfAbsent — all contextless. No timeouts. No cancellation. No tracing propagation.

A slow Pebble Get or a hung Batch.Commit blocks the goroutine indefinitely with no way to cancel it. Every consumer of kv.Store (projectionhost checkpoints, idempotency store, view stores, SQL KV store) inherits this deficiency.

Contrast: The idempotency.Store interface DOES take context.Context — but its KVStore wrapper cannot pass it to the underlying kv.Store. The context is accepted then silently discarded.

Fix: Add context.Context as the first parameter of every kv.Store, kv.Reader, kv.Writer, kv.Iterator, and kv.Batch method. Breaking change — schedule for v4.
Critical · Single-process only

No persistent or distributed event bus

command/memory_bus.go, watermill/event_bus.go:86

MemoryBus.Publish() dispatches handlers inline on the caller's goroutine — fully synchronous, fully blocking. A slow handler blocks every subsequent publisher. No buffering, no queuing, no timeout, no backpressure.

The Watermill EventBus uses GoChannel with BlockPublishUntilSubscriberAck: true — still blocking, still single-process. Multi-node deployment requires external wiring (NATS, Redis, Kafka) that doesn't exist as a built-in adapter.

Important · No reliable publishing

No outbox pattern for atomic save + publish

decider/decider.go — Repository.Execute

Repository.Execute does: Load → decide → Save → Publish. If Save succeeds but Publish fails, events are persisted but not delivered. The comment acknowledges this: "Save-fail (nothing persisted) vs publish-fail (persisted but not published)." No outbox table, no retry queue, no compensation.

Mitigation available: The SeekableJournal + CatchUpSubscriber pattern can replay missed events from the journal — but this requires consumer-side recovery, not producer-side guarantee.
Important · Hash collisions

Pebble store: sharded mutex with 256 shards

storage/pebble/store.go:17-29

The Pebble event store uses a 256-shard mutex pool to serialize check-then-commit per aggregate. At ~50K aggregates, hash collision probability becomes significant — two unrelated aggregates sharing a shard serialize unnecessarily. And this is single-process only — no distributed locking.

05Composability Assessment

The composability story is the strongest aspect of this library.

Bundle: ISP-honest composition root

stack.Bundle has ~20 fields, each a segregated interface. EventSink ≠ EventSource. Publisher ≠ Subscriber. A consumer wires exactly what they need and leaves the rest nil. Presets (sqlite.New(), pebble.New()) assemble everything in one call.

Generic middleware: one pattern, 27 factories

Handler[M any] + Middleware[M any] + MessageAdapter[M]. Each concern (Logging, Retry, Recovery, Validation, Metrics, Tracing, Circuit Breaker, Idempotency, Signing) has 3 typed wrappers. Adding a new concern = 1 generic function + 3 one-liner wrappers.

Mild concern: Bundle.db is untyped

Bundle.db any is an untyped escape hatch for SQL presets. Only preset-specific constructors know how to use it. This breaks type safety — but it's deliberate (avoids forcing a *sql.DB dependency on the base stack module).

Mild concern: Query middleware impedance mismatch

AsQuery() must capture a result from an any-returning handler inside an error-only middleware closure. This is forced by query.Handler returning (any, error) while the generic middleware only returns error. The deprecation hints confirm query.Handler is slated for replacement in v4.

06Target: Four Tiers (Not Seven Fake Layers)

The current 7-layer system is a lie — kv/ claims Layer 0 but depends on codec/; event/ claims Layer 1 but depends on Layer 2-4 modules. Replace with four real tiers representing architectural boundaries, not dependency order.

DOMAIN TIER — Pure domain model + contracts. No backend knowledge. Primitives: id/ codec/ kv/ (raw only) Message Types: event/ command/ query/ (NO cross-deps for errors!) Domain Logic: decider/ deriver/ projection/ schema/ snapshot/ dispatcher/ INFRASTRUCTURE TIER — Implement contracts for specific backends storage/event/ storage/command/ storage/kv/ storage/view/ storage/pebble/ storage/turso/ storage/memory/ transport/http/ transport/grpc/ watermill/ OPERATIONS TIER — Cross-cutting concerns across the system middleware/ idempotency/ otel/ prometheus/ signing/ encryption/ projectionhost/ listing/ scheduling/ COMPOSITION TIER — Wire everything together for the consumer stack/ stack/sqlite/ stack/postgres/ stack/pebble/ stack/memory/ catalog/ scenario/ testutil/ cmd/ example/
Key difference: Tiers represent architectural boundaries, not dependency order. Within each tier, modules can depend on each other freely. Cross-tier dependencies flow upward only. This is honest about what the system IS, not what the layer numbers claim.

07Action Roadmap (Pareto-Sorted)

1

Extract error taxonomy from event/ — 80% benefit, 20% effort

Replace event.NewConflict(...) → errorfamily.NewConflict(...) across ~50 files. Delete event/errors.go. Zero API change. Unblocks independent use of command/query without event baggage. This was identified in ARCHITECTURE_LAYERS_RECONSIDERED.md as Phase 1 and is the single highest-impact change.

2

Extract shared types (AggregateRef, CustomData) — Breaks command→event dep

Move AggregateRef, AggregateType, CustomData[K], Tracing into a shared/ module (Layer 0). Both event/ and command/ depend on it; neither depends on the other. Commands become truly independent of events.

3

Add context.Context to kv/ interface — Critical for production

Add context.Context as first parameter of every kv.Store, Reader, Writer, Iterator, Batch method. Breaking change — v4. Without this, hung I/O in Pebble blocks goroutines forever with no cancellation.

4

Split storage/ by concern — v4, high effort

Split storage/ into storage/event/, storage/command/, storage/kv/, storage/view/. Each shares storage/sql/ helpers but has its own package boundary. 100+ files become 4 focused packages of ~25 files each.

5

Implement outbox pattern — Reliability

Add an optional outbox table to Repository.Execute: Save events + outbox row in the same transaction. A background process reads the outbox and publishes. Eliminates the "saved but not published" gap.

6

Document the four-tier model — Replace fake layers

Update AGENTS.md, flake.nix, cmd/api-stability to use the four-tier model instead of the seven fake layers. Aligns documentation with reality.
