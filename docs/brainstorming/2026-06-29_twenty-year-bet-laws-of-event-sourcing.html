The 20-Year Bet

One question: what is something hard worth doing in this repo that will still be paying dividends in 2046? This is the reasoning — the candidates considered and rejected, the answer, and what it looks like in real Go against this codebase's actual API.

Scope: architectural Time horizon: 20 years Status: proposal

00The verdict, up front

Machine-check the algebraic laws of event sourcing. A dedicated laws/ module that imports the entire stack and proves the cross-cutting invariants that are true today, true in 2046, and true regardless of language or backend — the math that event sourcing is.

Everything else in this repo — every transport adapter, every storage backend, every stack preset — will be rewritten three to five times over two decades. Backends come and go. Projections get rebuilt. That is healthy, expected churn. What does not change is the structure: a fold over an ordered log of immutable facts. That structure has laws, and those laws are where the business-killing bugs hide.

The artifact itself is timeless. You only ever add laws, never remove them.

02The answer: machine-check the algebra

Event sourcing is, at its core, a fold over an ordered log of immutable facts. That structure has laws — algebraic identities that are true today, true in 2046, true regardless of language or backend. A dedicated laws/ module asserts these laws against the real code, with property-based testing, so that every future refactor of the store, snapshot, decider, or codec is automatically validated against them.

The key insight: this is additive and permanent. You only ever add laws, never remove them. Once SnapshotDeltaEqualsReplay is a green test, it guards that invariant for the life of the project. The compound interest over twenty years is enormous — it converts “trust me, I didn't break it” into “the test runner proved it.”

Why a separate module

The existing property tests live inside modules. But the real laws span modules: snapshot correctness requires snapshot + event + decider + storage together. The roundtrip law requires event + storage. This is precisely why it is missing — it does not fit the per-module test structure, so it fell through the cracks. A laws/ module is the one place that imports the whole stack to prove composition.

03Why it is genuinely hard

Not hard in typing. Hard in identifying the complete and minimal set of laws — which requires deciding what is mathematically true versus what is merely this implementation's choice. Miss a law and you have left a hole. Add a law that is not actually universal and you have frozen an implementation detail into a constraint.

That distinction is the 20-year design work, and the difficulty breaks into five real problems:

1. Which laws are universal?

Is “fold is a monoid” a law of the library, or an implementation choice? Getting this wrong in either direction is costly.

2. Cross-module composition

The killer laws do not live in one module. Snapshot+delta==replay spans four modules. No per-module test can catch it.

3. Codec roundtrips

A snapshot is only correct if encode(decode(s)) == s. The law must exercise the real codec, not an in-memory shortcut.

4. Concurrency invariants

Optimistic concurrency (“save at v succeeds only if at v”) is a correctness law, not a performance feature. It must be proven, not assumed.

04Current state: behavior tests, not laws

The repo already has property tests across 10+ modules using pgregory.net/rapid. On reading the two algebraic hearts — decider/property_test.go and event/property_test.go — they verify good but local properties:

+
Deterministic apply Folding the same event sequence twice yields the same state. Solid.
+
Event immutability & isolation Clone independence, payload/metadata mutation isolation. Thorough.
+
Version monotonicity NewEvents produces strictly increasing versions. Good.
The gap · High impact

The laws that matter most are not checked anywhere

decider/property_test.go uses a local foldAll helper, not the real Repository.Execute path

The decider tests use a local foldAll helper, not the real decider.Execute path. The law that matters most — “a snapshot-accelerated load produces the same state as a full replay” — is not checked anywhere. That is the single bug class that destroys trust in an event-sourcing system, and it is exactly the kind of subtle invariant that survives every refactor by being machine-checked, not by someone remembering to test it.

05The law inventory

This is the design work — the complete and minimal set of laws, each with its precise statement, the module boundary it spans, and whether it is checked today. Drafted below; this is the artifact that, if wrong, makes everything built on it wrong.

Law Statement Spans Checked?
Fold identity fold(s₀, []) == s₀ decider No
Fold associativity fold(fold(s₀, A), B) == fold(s₀, A+B) decider No
Snapshot==replay load via snapshot@n == load via full replay snapshot + event + decider + storage No
Store roundtrip Save(e); Load() == e (order, content, version) event + storage No
Monotonic append Save@v succeeds ⇒ next Load sees exactly v event + storage No
Codec roundtrip encode(decode(s)) == s (all codecs) codec + snapshot No
Decider invariant fold(Decide(cmd, s)) preserves invariants Decide guarded on decider No
Zero of seven. Every law that spans more than one module is unchecked. This is not a failure of diligence — it is the structural consequence of per-module testing. The laws live in the gaps between modules.

06The killer law, as real Go

This compiles against the repo's actual API — snapshot.Snapshot with State []byte, decider.Decider[State]{Initial, Apply}, the real type signatures. It is the law that is not checked anywhere today, and the one that catches the bug class that destroys trust silently. 

// laws/snapshot_laws_test.go
package laws_test

import (
    "testing"
    "pgregory.net/rapid"

    "github.com/larsartmann/go-cqrs-lite/decider/v3"
    "github.com/larsartmann/go-cqrs-lite/event/v3"
    "github.com/larsartmann/go-cqrs-lite/id/v3"
    "github.com/larsartmann/go-cqrs-lite/snapshot/v3"
)

// Law: a snapshot-accelerated load MUST equal a full replay.
//
//     load(via snapshot@k) == load(full replay from v0)
//
// If this ever fails, every projection rebuilt from snapshots is silently
// wrong, and no amount of per-module testing will have caught it —
// because the bug only emerges when snapshot + decider + store act together.
func TestSnapshotDeltaEqualsReplay(t *testing.T) {
    t.Parallel()

    rapid.Check(t, func(t *rapid.T) {
        events := rapid.SliceOfN(genCounterEvent(t), 5, 100).Draw(t, "events")
        splitAt := rapid.IntRange(1, len(events)-1).Draw(t, "splitAt")

        d := decider.Decider[counterState]{
            Initial: counterState{},
            Apply:   foldCounter,
        }

        // Ground truth: fold the ENTIRE sequence from scratch.
        want, err := foldAll(d.Initial, d.Apply, events)
        if err != nil {
            t.Fatalf("ground-truth fold: %v", err)
        }

        // Snapshot path: fold [0..k), snapshot, fold [k..N) from snapshot.
        got, err := foldFromSnapshot(d, events, splitAt)
        if err != nil {
            t.Fatalf("snapshot path: %v", err)
        }

        // THE assertion. One line. Twenty years of protection.
        if got != want {
            t.Fatalf("snapshot path diverged:\n  full   = %+v\n  snap@%d = %+v",
                want, splitAt, got)
        }
    })
}

// foldFromSnapshot simulates exactly what decider.Repository.Load does
// when a snapshotStrategy is configured: load snapshot, fold the delta.
func foldFromSnapshot(
    d decider.Decider[counterState],
    events []event.Event,
    splitAt int,
) (counterState, error) {
    state := d.Initial

    // Fold the prefix, then persist it as a snapshot (State is []byte).
    state, err := foldAll(state, d.Apply, events[:splitAt])
    if err != nil {
        return state, err
    }
    snap := snapshot.Snapshot{
        AggregateID: events[0].AggregateID(),
        Version:     events[splitAt-1].Version(),
        State:       encode(state), // codec roundtrip (a second law covers this)
    }

    // Reload: start FROM the snapshot, fold only the delta.
    state = decode(snap.State)
    return foldAll(state, d.Apply, events[splitAt:])
}

The bug this catches — concretely

Picture a refactor in 2031. Someone “optimizes” the snapshot path to skip folding the event at the snapshot version (off-by-one: folding [k..N) instead of (k..N]). Every per-module test passes:

snapshot/ tests pass — Save/Load roundtrip fine.
decider/ tests pass — Apply is deterministic.
event/ tests pass — Load returns the right events.

But projections rebuilt from snapshots now drift by exactly one event's effect. Silently. For months. Until a user reports “the total is off by one increment on accounts created before the migration.”

This law makes that bug a red test in 30 seconds. Nothing else in the repo does, because nothing else exercises the composition.

07What it means in practice

Question Answer
Where does it live? A new laws/ module — the only module that imports the full stack to prove composition.
How big? ~5–8 laws. Each is ~40 lines. Total under 400 lines.
How is it run? go test ./laws/... -count=1 — joins the existing suite, runs in CI.
When does it pay off? Every refactor of store / snapshot / decider / codec for the life of the project.

08The concrete next step

Not code. The law inventory design doc: list every law, its precise mathematical statement, the module boundary it spans, and whether it is checked today. If the set of laws is wrong, every test built on it is theatrical. Writing the Go is mechanical once the laws are pinned down; identifying the complete and minimal set is the irreducible design work.

1

Draft the law inventory

The seven laws above are a first draft. Each needs a formal statement, the exact modules it spans, and a yes/no on whether it is checked today. Challenge every entry: is this universal, or is it this implementation's choice?

2

Create the laws/ module skeleton

go.mod importing the full stack, wired into go.work, doc.go explaining its singular purpose. No test logic yet.

3

Implement the killer law first

TestSnapshotDeltaEqualsReplay. If it passes, the current implementation is sound. If it fails, we have found a latent bug — and proven the value of the suite before writing the second law.

4

Add laws incrementally, forever

Fold identity, fold associativity, store roundtrip, monotonic append, codec roundtrip, decider invariant. Each is ~40 lines. Each guards an invariant for the life of the project.

The bottom line. Every other artifact in this repo will be rewritten. The laws will not. They are the constitution — the one thing worth getting exactly right, because everything else is built on the assumption that they hold.
