00Executive Summary

go-cqrs-lite is already one of the most thoughtfully architected CQRS libraries in any language. Its ISP-split store interfaces, branded ULID identifiers, five-family error taxonomy, pure-function Decider, and tombstone soft-delete model are genuinely excellent. The hard architectural problems — immutability, optimistic concurrency, replay-safe projections, schema evolution — are solved.

But the type algebra has accumulated organic rot in three systemic places that block the path to "best in the world". Each is backed by verbatim evidence below:

  1. The Event interface is a leaky abstraction — 4 internal hot-path helpers type-assert to *ImmutableEvent, and 12 first-class domain concepts live as strings in Metadata.Custom.
  2. The materialization story is incomplete — no projection lifecycle choice (Marten's Inline/Live/Async), a fire-and-forget DLQ, no shipped projection→readmodel integration.
  3. Massive duplication — ~600 LOC copy-pasted between command/query, typed/untyped parallel hierarchies, inconsistent context handling.

02State of the Art — What "Best" Means

Deep research into the leading CQRS/ES libraries reveals four capabilities that distinguish the best from the mediocre. No current Go library has achieved all four. go-cqrs-lite is positioned to be the first.

Capability Pioneered by What it means go-cqrs-lite
Decide/Apply separation Eventuous (.NET) Three pure functions: Decide(cmd, state) → events, Apply(state, event) → state, Project(event). No aggregate base class. Fully testable without mocks. 70% — has Fold (=Apply) but Decide is per-call, not a field
Projection lifecycle Marten (.NET) Every read model declares when it updates: Inline (same-tx, strong consistency), Live (recompute on read), Async (background tail). 30% — has Async only; ad-hoc Live in listing
Dual-store architecture LiveStore (TS) Event log (immutable, source of truth) + materialized state DB (disposable, rebuildable). Schema migration triggers automatic rebuild. 40% — pieces exist but never wired into one contract
Type-safe event application Eventuous, thefabric-io Apply(state, event) → state is statically typed — no any casts, no runtime type assertions in the hot path. 20% — DecodePayload[T] exists but Event payload is []byte
Dynamic consistency boundaries Sekiban DCB (C#) Tag-based consistency instead of stream-per-aggregate. Cross-aggregate invariants without sagas. (Cutting-edge; may be overkill for Go.) —
Context-aware replay Axon (Java) isLive() flag so handlers skip side-effects (emails, notifications) during replay. 100% — WithProcessingMode(ctx, ModeReplay) is cleaner than Axon's static
The four-color opportunity: Achieving (1) Decide/Apply as typed pure functions, (2) projection lifecycle as a first-class choice, (3) a wired dual-store architecture, and (4) type-safe event application makes go-cqrs-lite the reference Go implementation — the library other Go CQRS projects are measured against.

03What's Already World-Class (Preserve These)

These patterns are the quality benchmark. Every redesign decision must preserve them.

+
ISP-split store interfaces (ADR-0006) EventSink | EventSource | Journal | SeekableJournal | BackwardsSource. A projection depends only on EventSource; a writer depends only on EventSink. Delete is impossible at the type level. This is textbook ISP applied correctly.
+
Branded ULID identifiers (ADR-0024) id.Of[T] = cbid.ID[T, ulid.ULID] — phantom-typed, compile-time-safe. EventID can never be confused with AggregateID. 8 markers exported for downstream tooling. Zero runtime cost.
+
Five-family error taxonomy Rejection | Conflict | Transient | Infrastructure | Corruption — classified via go-error-family. Retry middleware does IsRetryable(err) structurally, not by string matching. Genuinely ahead of most Go libraries.
+
Pure-function Decider (ADR-0001) Decider[State]{Initial, Fold} — functional core, imperative shell. No base class, no reflection, no embedded infrastructure. Matches the Eventuous / functional-ES frontier.
+
Replay-safe processing mode WithProcessingMode(ctx, ModeReplay) lets handlers distinguish live from replay — don't send emails during catch-up. Cleaner than Axon's isLive() because it's context-scoped.
+
Codec abstraction with BufferEncoder codec.Codec + BufferEncoder extension for zero-alloc encoding. JSON, CBOR (canonical), CBOR-compact, Raw. Clean separation of payload encoding from event structure.
+
Defensive cloning on all public accessors Payload() returns slices.Clone, Metadata() returns .Clone(). The immutability contract is enforced at the boundary.
+
Stack presets as composition root stack/memory, stack/sqlite, stack/pebble, stack/postgres — one call wires the full stack. The deployer picks the preset; the app developer never imports a backend.

04Problem Catalog — Brutal Honesty with Evidence

Twenty-three problems across seven themes. Every claim is backed by verbatim source with file:line. Not opinions — observations from reading every production .go file in 16 core modules.

Theme A — The Leaky Event Abstraction

The Event interface documents an immutability contract that only *ImmutableEvent actually enforces. The library's own helpers silently depend on the concrete type.

Critical · P0

A1 · "Generic" helpers type-assert to the concrete impl

event/codec.go:44-50 · event/codec.go:62-64 · event/codec.go:69-75 · event/tombstone.go:93-100

Here is the verbatim source of payloadForDecode — an exported-path function that claims to work on any Event but silently breaks on any non-ImmutableEvent implementation: 

// event/codec.go:44 — verbatim
func payloadForDecode(evt Event) []byte {
    if ie, ok := evt.(*ImmutableEvent); ok {
        return ie.payload  // bypasses defensive clone — reaches into PRIVATE field
    }
    return evt.Payload()  // pays clone cost — the "slow path"
}

Four helpers do this: payloadForDecode, PayloadReadOnly (exported!), encodingForCopy, tombstone.copyWithMetadata. A custom Event implementation (test fake, proxy, future variant) silently pays the clone cost or breaks. The interface is a lie; the concrete struct is the real contract.

Fix: Make Event a concrete struct. There is exactly one production impl. The "interface for testability" benefit is already provided by store interfaces operating on []Event values. The type-assertions become direct field access — honest, fast, no leak.
High · P1

A2 · eventOptions pointer leaks config into event lifetime

event/event.go:86 · event/event.go:89-93

Verbatim — the struct that every event carries for its entire lifetime:

// event/event.go:75-93 — verbatim
type ImmutableEvent struct {
    id            id.EventID
    eventType     Type
    aggregateID   id.AggregateID
    aggregateType AggregateType
    version       Version
    schemaVersion SchemaVersion
    encoding      codec.Encoding
    payload       []byte
    metadata      Metadata
    occurredAt    time.Time
    opts          *eventOptions  // ← construction-time config persists for life
}

type eventOptions struct {
    clock    Clock       // only needed at construction
    newCodec codec.Codec  // only needed at construction
    deadline time.Time
}
Fix: Construction-time config stays in the constructor's local scope. Apply options to a local builder, materialize an Event with only data fields + deadline.
High · P1

A3 · Encoding() normalizes "" to JSON, hiding unset state

event/event.go:119-125
// event/event.go:119 — verbatim
func (e *ImmutableEvent) Encoding() codec.Encoding {
    if e.encoding == "" {
        return codec.EncodingJSON  // "never set" looks identical to "genuinely JSON"
    }
    return e.encoding
}
Fix: Make encoding required at construction (default to JSON explicitly, never zero-value). Or add EncodingUnknown sentinel and reject it at decode boundaries.
Critical · P0

A4 · Immutability is contractual, not compiler-enforced

event/event.go:49-60 (doc only) · decider/enricher.go:9-29 (mutates in place)

The Event interface documents the contract in a doc comment (line 51: "Implementations must ensure..."). But decider.applyEnricher type-asserts to *ImmutableEvent and applies event.Options — mutating events in place between decide and Save. The "Immutable" name is a documentation claim, not a type-system guarantee.

Fix: Enrichment should produce a new event via Clone+options (which already exists), not mutate in place. The decider maps the decide result through the enricher, producing a new slice.

Theme B — The Soft Metadata Escape Hatch

Metadata has 7 typed fields and Custom map[MetadataKey]string. The escape hatch has become the real domain model — tombstone, causation, signing, encryption all live there as strings.

Critical · P0

B1 · Tombstone state is a magic string in a string map

event/tombstone.go:48 · event/tombstone.go:70 · event/tombstone.go:74 · event/tombstone.go:83-84

Verbatim — the actual detection logic:

// event/tombstone.go:48 — verbatim
const MetadataKeyTombstone MetadataKey = "tombstone"

// event/tombstone.go:57-79 — verbatim detection
func DetectTombstone(events []Event) TombstoneStatus {
    last := events[len(events)-1]
    md := last.Metadata()
    if md.Custom == nil { return TombstoneUndetermined }

    if md.Custom[MetadataKeyRebirth] == "true" { return TombstoneActive }
    if md.Custom[MetadataKeyTombstone] == "true" { return TombstoneTombstoned }
    return TombstoneUndetermined
}

// event/tombstone.go:83 — verbatim marking
func MarkTombstone(evt Event) (*ImmutableEvent, error) {
    return copyWithMetadata(evt, MetadataKeyTombstone, "mark tombstone")
}

The soft-delete state of an aggregate — a critical domain concept — is Custom["tombstone"] == "true". Only the literal string "true" is honored. "True", "1", "yes" are all silently "not tombstoned". This is the textbook example of a domain concept that should be a first-class type.

Critical · P0

B2 · The "real" event schema lives in Custom

event/metadata.go:10-19 · event/tombstone.go · event/causality.go · signing/event.go · encryption/envelope.go

Verbatim — the current Metadata struct, with annotations showing what actually lives where: 

// event/metadata.go:10 — verbatim, annotated
type Metadata struct {
    CorrelationID id.CorrelationID  `json:"correlationId"`      // ← typed ✓
    CausationID   id.CausationID    `json:"causationId"`        // ← typed ✓ (but no omitempty!)
    UserID        id.UserID         `json:"userId"`             // ← typed ✓ (no omitempty!)
    RequestID     id.RequestID      `json:"requestId"`          // ← typed ✓ (no omitempty!)
    Source        Source            `json:"source,omitempty"`
    IPAddress     IPAddress         `json:"ipAddress,omitempty"`
    UserAgent     UserAgent         `json:"userAgent,omitempty"`
    Custom        map[MetadataKey]string `json:"custom,omitempty"`
    //                        ↑ Where domain concepts ACTUALLY live:
    //                          Custom["tombstone"] = "true"     ← soft-delete
    //                          Custom["rebirth"]   = "true"     ← un-delete
    //                          Custom["command.type"] = "user.create" ← causation
    //                          Custom["command.id"]   = "01J..."   ← causation
    //                          Custom["client.id"]          = "..." ← offline-first
    //                          Custom["client.occurred_at"] = "..." ← offline-first
    //                          + signing alg/key-id/sig + encryption alg/key-id/iv
    //                          = 12 first-class concepts as STRINGS
}
The damage: 12 domain concepts that 5+ modules depend on are encoded as strings in a map documented as the "custom" escape hatch. The 7 typed fields are the minority; the string map is the real model. Typos are silent. Type errors are impossible to catch at compile time.
High · P1

B3 · omitempty inconsistency leaks zero-value ULIDs

event/metadata.go:11-14

Four ID fields (CorrelationID, CausationID, UserID, RequestID) have no omitempty. Events with no correlation produce JSON with four 26-character zero-ULID strings ("00000000000000000000000000"). The three string fields correctly use omitempty.

Fix: Give branded ID types an IsZero()-aware MarshalJSON that omits when zero — one change in id/, fixes it everywhere.

Theme D — The Decider Identity Crisis

Critical · P0

D1 · Decider has no Decide field — the name lies

decider/decider.go:24-27 · decider/decider.go:94

Verbatim — the struct that is named "Decider" but contains only fold logic: 

// decider/decider.go:24 — verbatim
type Decider[State any] struct {
    Initial State
    Fold    func(state State, evt event.Event) (State, error)
    // ↑ NO Decide field! The decision logic is passed per-call:
}

// decider/decider.go:94 — verbatim
type DecideFunc[State any] func(state State, currentVersion event.Version) ([]event.Event, error)

The struct is named Decider[State] but contains only Initial and Fold. It's a Fold-spec, not a Decider. Every caller closes over their command inside the per-call DecideFunc, so the command type CreateUser is invisible to the type system. There's no compile-time link between Decider[UserState] and CreateUser.

Fix — Eventuous-inspired: Add a two-type-param variant with Decide as a field and rename Fold→Apply (standard ES terminology). See §05 Redesign → Decider.
High · P1

D2 · LoadAtVersion/LoadAtTime bypass snapshots entirely

decider/load.go:100-163

Repository.Load uses snapshots when configured. But the time-travel APIs (LoadAtVersion, LoadAtTime) always replay from version 0, ignoring snapshots. A snapshot at version 10 + LoadAtVersion(15) replays all 15 events when it could load the v10 snapshot and replay 5.

High · P1

D3 · Snapshot save errors silently swallowed

decider/decider.go:169-227

saveSnapshotAfterEvents writes after Publish; any error is slog.WarnContext'd and discarded. No way for callers to observe snapshot failure — not via return, not via metric, not via span event. A silently-failing snapshot means the optimization silently stops.

Theme E — Materialization Gaps (The Biggest Opportunity)

Where the library is furthest from "best in the world" — and where the biggest wins live.

Critical · P0

E1 · No projection lifecycle choice (Marten's killer feature)

projection/runner.go:34 (Async only) · listing/in_memory.go:16 (ad-hoc Live) · no Inline anywhere

Marten's three lifecycles — Inline (same-tx), Live (recompute on read), Async (background tail) — let the consumer declare per-view how they want consistency vs performance. go-cqrs-lite ships only Async and an ad-hoc Live. No Inline. No type-level way to say "this view must be strongly consistent."

Event Append → Async Runner → (eventual) Read Model | Inline (missing) → (same tx) Read Model
Critical · P0

E2 · DLQ is a fire-and-forget callback, not a durable queue

projection/options.go:22 · projection/runner_live.go:112

DeadLetterHandler = func(ctx, projectionName, evt, err) — invoked inline after retries exhaust. If the callback only logs (the common case), the event is silently lost. No persistent store, no replay API. The weakest link in the reliability model.

Fix: DeadLetterStore interface (Sink + Source). In-memory + SQL + Pebble impls. runner.ReplayDeadLetters(ctx, projectionName) re-drives after a fix. Turns "lost" into "recoverable".
High · P1

E3 · replayIDs is unbounded + racy

projection/runner.go:41 · projection/options.go:78

Default dedup capacity is 0 (unbounded) — memory grows forever for 24/7 runners. The map is written during replay (single-threaded) and read concurrently by the live dedup filter. WithDedupCapacity bounds it, but the default is a leak.

High · P1

E4 · No shipped projection→readmodel integration

projection/ (no import of readmodel) · readmodel/ (no import of projection)

The library has a clean separation: projection (event→handler), readmodel (typed KV store). But the consumer must hand-wire the projection handler closure to call readmodel.Store.Set. No shipped TypedProjection[V,K] that materializes events into a readmodel automatically. The clean separation is never demonstrated.

Theme F — Storage & Composition Leaks

High · P1

F1 · IsDuplicateKeyError matches driver error strings

storage/sql/duplicate.go:8

String-matches "UNIQUE constraint failed" (SQLite) and "duplicate key value violates unique constraint" (Postgres). Any driver version change that tweaks the message breaks this silently — optimistic concurrency detection fails, conflicts get misclassified.

Fix: pgconn.PgError code 23505 for Postgres, SQLite extended error codes. String matching only as fallback, logged when it fires.
High · P1

F2 · kv.Store and readmodel.Store ignore context

kv/kv.go:6-83 (no ctx) · readmodel/store.go:20-23 (_ context.Context) · storage/kv_sql.go:28 (uses context.Background())

kv.Store methods take no context.Context. readmodel.Store accepts _ context.Context (underscore-named, explicitly ignored). SQLKVStore uses context.Background(). Cancellation and deadlines cannot propagate. For a library that threads context everywhere else, this is a consistency gap and a production hazard.

High · P1

F3 · stack errors use plain errors.New, not the classified family

stack/errors.go:6-40

ErrMissingEventStore, ErrMissingPublisher, etc. use errors.New — invisible to IsRetryable and errors.As family checks. Every other module uses event.NewInfrastructure.

Retry, exponential backoff+jitter, circuit breaker are pure algorithms on func() error. Today they're packaged as Middleware func(Handler) Handler — locked to CQRS handler types. The algorithms are 90% of the value; the packaging is the blocker.

Production event/*.go imports only id, codec, go-error-family, samber/ro. But event/go.mod lists command, query, memory, schema, snapshot as direct requires (test-only). A consumer running go mod tidy sees the inflated graph and concludes "hub". The architecture is right; the manifest lies.

05The Redesigned Data Model

From first principles — Go's full type power: branded types, generics, composition, constructor functions, interface-based unions. Every decision has rationale (§08); rejected alternatives documented.

Event + Metadata — Honest and Immutable

Event becomes a concrete struct (one production impl — the "interface for testing" benefit is provided by store interfaces on []Event). Leaky assertions disappear. Metadata promotes 12 soft concepts to typed fields. 

// event/event.go — redesigned

// Event is an immutable domain event. All fields set at construction;
// no setters. Payload cloned on construction and on every Payload() call.
type Event struct {
    id            id.EventID
    eventType     Type
    ref           AggregateRef     // typed pair, not split fields
    version       Version          // uint64 — negatives unrepresentable
    schemaVersion SchemaVersion    // uint32
    encoding      codec.Encoding   // required at construction, never zero
    payload       []byte
    metadata      Metadata
    occurredAt    time.Time
    deadline      time.Time        // zero = no deadline
    // NO opts pointer — config stays in constructor scope
}

// Metadata — tracing + first-class domain concepts.
// Extensions is the TRUE escape hatch (consumer-defined only).
type Metadata struct {
    CorrelationID id.CorrelationID  `json:"correlationId,omitempty"`
    CausationID   id.CausationID    `json:"causationId,omitempty"`
    UserID        id.UserID         `json:"userId,omitempty"`
    RequestID     id.RequestID      `json:"requestId,omitempty"`
    Source        Source            `json:"source,omitempty"`

    // Promoted from Custom strings → typed fields:
    Causation  *Causation          `json:"causation,omitempty"`   // was Custom["command.*"]
    Tombstone  TombstoneMark      `json:"tombstone,omitempty"`   // was Custom["tombstone"]
    Security   *SecurityEnvelope  `json:"security,omitempty"`   // signing+encryption unified
    ClientTime *ClientTime         `json:"clientTime,omitempty"`  // offline-first

    Extensions map[string]string     `json:"extensions,omitempty"`  // TRUE escape hatch
}

// TombstoneMark — closed three-state. Zero value = None (not a tombstone event).
type TombstoneMark uint8
const (
    TombstoneNone    TombstoneMark = iota
    TombstoneSet                    // soft-delete
    TombstoneRebirth                // un-delete
)

type Causation struct {
    CommandType command.Type   // typed, not bare string
    CommandID   id.CommandID
}
What this fixes: 12 first-class concepts move from string map to typed fields. Tombstone is a typed TombstoneMark — discoverable, validated, impossible to typo. Command causation carries typed command.Type. Security collapses into one envelope. Extensions is honestly named and scoped. The opts pointer disappears. Encoding is never zero.

Store Interfaces — Keep the ISP Split

The ISP split (ADR-0006) is one of the best decisions in the library. The redesign preserves it entirely — no change needed. The only addition is an optional InlineHook for Inline projection mode. 

// event/store.go — preserved from ADR-0006, ONE addition

type EventSink interface {
    io.Closer
    Save(ctx, ref AggregateRef, events []Event, expected Version) error
    AppendBatch(ctx, ref, events) error

// NEW: opt-in inline projection hook — for ModeInline (Marten-style)
type InlineSink interface {
    EventSink
    SaveWithHooks(ctx, ref, events, expected, hooks []InlineHook) error
}

type InlineHook func(ctx, tx Tx, events []Event) error  // runs in same tx as Save

Decider Evolution — Decide/Apply Separation (Eventuous-inspired)

// decider/decider.go — redesigned with two type params

type Decider[State any, Cmd any] struct {
    Initial State

// Now the command type is bound at compile time:
userDecider := Decider[UserState, CreateUser]{...}

// Backward-compat: old single-param form preserved as alias

06Validation Layer — Making Invalid States Unrepresentable

The core question of data-model design: can a consumer construct an invalid value that still compiles? If yes, the type system isn't doing its job. Here's how the redesigned model pushes validation from runtime to compile-time.

Invalid state Today (runtime check) Redesigned (compile-time)
Negative event version Version int — validateEventParams checks at runtime Version uint64 — negatives are unrepresentable
Zero schema version SchemaVersion int — ParseSchemaVersion rejects <1 at runtime SchemaVersion uint32 — min 1 enforced by constructor; zero is the "not set" sentinel
Tombstone typo Custom["tombston"] = "true" — silently ignored, no error TombstoneMark is a typed enum — typos are compile errors
Wrong ID type passed Already fixed — branded IDs (id.Of[T]) prevent this at compile time ✓ Preserved — the branded ID system is excellent
Command dispatched to wrong handler Runtime type assertion cmd.(T) in RegisterTyped adapter Decider[State, Cmd] binds command type at construction — mismatch is a compile error
Encoding never set encoding == "" silently normalized to JSON — hides corruption Encoding is required at construction — zero value rejected
Delete on event store Already impossible — no Delete method on Store ✓ Preserved — hard-delete stays impossible at the type level
Nil store/publisher NewRepository checks at runtime → returns ErrNilStore Stay runtime (Go can't enforce non-nil at compile time) — but error is classified + retryable
Net result: Five classes of invalid state move from runtime-check to compile-time-unrepresentable. Three are already correct (branded IDs, no Delete, classified errors). The biggest win is Decider[State, Cmd] — the command-to-handler binding becomes a compile-time fact, eliminating the runtime type assertion in RegisterTyped.

09Anti-Patterns to Avoid

Don't add Delete to Store

History is immutable. ADR-0006 was right. Soft-delete via tombstone is the only path.

Don't make Event generic Event[T]

Storage stores bytes. Generic Event forces every store to be generic, breaks the journal. Keep Event as envelope; decode to T at boundary.

Don't reimplement the outbox

Removed for good reason. Crash recovery via SeekableJournal + CheckpointStore + durable DLQ. Relay uses event store's own journal.

Don't force a transport/broker

"Library, not framework." Every transport adapter is optional. Never bake one into core.

Don't conflate Decide and Apply

Different functions, different signatures, different test profiles. Mixing them (Axon-style) creates indirection.

Don't string-match driver errors

IsDuplicateKeyError breaks on driver updates. Use typed error codes.

Don't make DLQ fire-and-forget

Callback that logs = silent data loss. DLQ must be durable with replay API.

Don't ignore ctx anywhere

Every I/O op must honor context. kv.Store ignoring ctx is a production hazard.

11Conclusion

go-cqrs-lite is already one of the most thoughtfully architected CQRS libraries in any language. Its ISP-split interfaces, branded identifiers, error taxonomy, pure-function Decider, and tombstone model are genuinely excellent — the hard problems are solved. The path from "excellent" to unequivocally best is not a rewrite; it is three targeted extractions, three state-of-the-art additions, and a consistency pass.

No Go library today offers projection lifecycle choice, type-safe event application, clean Decide/Apply separation, or a wired dual-store architecture. Achieving all four — and the library is 70% of the way there — makes go-cqrs-lite the reference implementation.
