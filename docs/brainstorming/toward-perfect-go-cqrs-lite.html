1. What We Have — The Excellent

v2.1.0 is a genuinely strong release. The following areas are already at or near production-grade trustworthiness. These should be preserved and used as the quality benchmark for everything else.

AreaWhy It Is ExcellentStatus
event/ Immutable events, 19 functional options, strong error taxonomy, lazy allocation, clock injection, defensive copies. Done
id/ Branded ULIDs with compile-time safety, full serialization support, 97.8% coverage. Done
command/ & query/ Typed handlers, middleware chains, lifecycle, metadata, catalog introspection. 100% / 94% coverage. Done
decider/ Pure-function aggregates, snapshot/time-travel support, fully deterministic. 100% coverage. Done
middleware/ 8 concerns × 3 message types = 24 middleware factories. Circuit breaker, retry, tracing, metrics, logging, validation, recovery. Done
signing/ HMAC + Ed25519 + multisig, canonical encoding, zero external crypto deps. Done
catalog/ Auto-docs: AsyncAPI, OpenAPI, EventCatalog MDX, D2 diagrams, docserver with Scalar + AsyncAPI React. Done
projection/ Replay + live runner, checkpointing, DLQ, replay context markers, graceful close. 95%+ coverage. Done
listing/ Aggregate listing with tombstone detection, cursor pagination, SQL + in-memory readers, cache invalidation. Done
storage/ PostgreSQL + SQLite + Turso, optimistic concurrency, time-travel, snapshots, checkpoints, dialect abstraction. Done
memory/ Reference in-memory implementations for testing. 99.6% coverage. Done
otel/ Shared OpenTelemetry helpers across modules. Clean abstraction over raw OTel SDK. Done

Core insight: The hard parts are solved. Event model, identity, dispatch, projections, storage backends, docs generation, and middleware are all credible, tested, and composable. The remaining work is mostly connective tissue and production hardening.

2. Where We Are Not Yet Perfect

GapSeverityWhat It Means for Consumers
No generic read-model store High Every projection writes its own SQL. No typed CRUD abstraction between projection/ and query/.
SQL storage lacks Journal Medium Cross-aggregate replay from SQL requires table-scan workarounds instead of native ReadAll/ReadFrom.
Pebble gaps Medium No BackwardsSource or StreamLoader; limits parity with SQL/memory.
Turso coverage 29% Medium Remote sync (Push/Pull/Checkpoint) is effectively untested. Consumers cannot trust it in production.
Outbox exists but is fragmented Medium Outbox types are split across storage/ and event/. No first-class poller or retry policy API.
No schema registry middleware Medium Consumers can upcast on load, but cannot enforce schema compatibility at publish time.
Test utilities are thin Medium No fluent AggregateTester, ProjectionTester, or BusTester. Every consumer hand-rolls setup.
BuildFlow pre-commit hook broken Low Requires --no-verify. Annoying, not blocking, but erodes contributor trust.
Catalog lint issues (7) Low Pre-existing; not correctness issues, but they stain an otherwise zero-lint codebase.

3. Vision of the Perfect State

A perfect go-cqrs-lite would mean any team can build a production CQRS system by composing modules without writing infrastructure glue. The library would handle the boring, risky parts: persistence, schema evolution, observability, caching, and resilience.

✓ Type-safe everything

No any in public APIs. Branded IDs, generic stores, generic projections, generic queries. The compiler prevents mixing IDs and payloads.

✓ Observable by default

Every store, bus, dispatcher, projection, and query handler emits OTel traces and metrics. Zero config means zero telemetry.

✓ Resilient by default

Outbox guarantees at-least-once delivery. Retries, circuit breakers, and DLQ are opt-out, not opt-in.

✓ Schema-aware

Publish-time validation against a registry. Versioned read models. Upcasters migrate both event and projection schemas.

✓ Testable without mocks

High-level test utilities let consumers write Given-When-Then specs against real in-memory infrastructure.

✓ Modular acyclic graph

No module depends on more than it needs. Consumers import only what they use. No replace-directive tangles.

4. Roadmap to Perfect

1

Add a typed data/ read-model module

This is the highest-impact missing piece. It sits between projection/ (writes read models) and query/ (reads them). A generic Store[K,V] with SQL + in-memory implementations, cursor pagination, optimistic concurrency, cache decorator, and OTel.

2

Complete SQL Journal and Pebble parity

SQL storage should implement event.Journal and event.SeekableJournal natively. Pebble should implement BackwardsSource and StreamLoader. All three backends should pass a shared contract test suite.

3

Promote outbox to a first-class module

Consolidate outbox types and poller into outbox/ with a stable API: Outbox, Poller, RetryPolicy, OutboxEntry, and transactional sink integration. Remove the fragmentation between storage/ and event/.

4

Production-harden Turso

Add integration tests for Push/Pull/Checkpoint against a local libSQL replica or testcontainer. Document sync semantics, conflict resolution, and offline-first guarantees. Target 80%+ coverage.

5

Add schema registry middleware

A publish-side middleware that validates event payloads against the catalog JSON schema. Prevents incompatible events from ever reaching the bus. Complements the existing load-time upcaster.

6

Build testing/ fluent utilities

AggregateTester, ProjectionTester, BusTester, and StoreContractSuite so consumers write BDD-style tests without boilerplate. This is the missing DX layer.

7

Polish developer experience

Fix BuildFlow pre-commit, eliminate catalog lint issues, add a dedicated "getting started" example that uses command dispatch → decider → event store → projection → query end-to-end. Make onboarding 15 minutes, not 2 hours.

5. New Module Proposals

data/ — Typed Read-Model Store

// data/store.go
type Reader[K comparable, V any] interface {
    Get(ctx context.Context, key K) (Record[K, V], error)
    List(ctx context.Context, opts ListOptions[K]) (Page[Record[K, V]], error)
}

type Writer[K comparable, V any] interface {
    Put(ctx context.Context, rec Record[K, V]) error
    Delete(ctx context.Context, key K) error
}

type Store[K comparable, V any] interface {
    Reader[K, V]
    Writer[K, V]
    io.Closer
}

type Record[K comparable, V any] struct {
    Key       K
    Value     V
    Version   uint64
    UpdatedAt time.Time
    Status    event.TombstoneStatus
}
  • Implementations: NewSQLStore[K,V], NewInMemoryStore[K,V], NewCachedReader[K,V] (otter), NewVersionedStore[K,V] (projection schema migration).
  • Integration: data.Projection[V] implements event.Projection with a typed fold function.
  • Dependencies: event, id, codec, otel only. No coupling to projection or query.
  • Quality gate: ≥90% coverage, BDD suite, benchmarks comparing SQL vs in-memory vs cached.

outbox/ — Transactional Outbox

// outbox/outbox.go
type Outbox interface {
    Append(ctx context.Context, entries []Entry) error
    PollPending(ctx context.Context, limit int) ([]Entry, error)
    Ack(ctx context.Context, ids []id.EventID) error
}

type Poller interface {
    Run(ctx context.Context) error
}

type RetryPolicy struct {
    MaxAttempts  int
    InitialDelay time.Duration
    MaxDelay     time.Duration
}
  • Consolidate SQL outbox, memory outbox, and poller into one module with a single mental model.
  • Integrate cleanly with storage.NewTransactionalSink(store, outbox).
  • Add at-least-once delivery semantics, poison-message handling, and observability spans.

schema/registry/ — Publish-Time Schema Validation

// registry/registry.go
type Registry struct { /* JSON schemas by (eventType, version) */ }

func (r *Registry) Validate(evt event.Event) error
func ValidationMiddleware(r *Registry) event.PublishMiddleware
  • Reuses catalog.SchemaFromType[T]() to build schemas.
  • Prevents producer/consumer drift. Complements schema.Upcaster (load-time migration).

testing/ — Fluent Test Utilities

// testing/aggregate.go
tester := cqtesting.NewAggregateTester(t, store, bus).
    Given(decider.InitialState).
    When(CreateUser{Name: "Alice"}).
    Then(func(t *testing.T, state UserState) {
        assert.Equal(t, "Alice", state.Name)
    })

// testing/projection.go
checker := cqtesting.NewProjectionTester(t, runner).
    ExpectProjection("user-summary").
    After(UserCreated{Name: "Alice"}).
    To(func(t *testing.T, rec UserSummary) {
        assert.Equal(t, "Alice", rec.Name)
    })
  • High-level BDD helpers for the three things every consumer tests: aggregates, projections, and commands/events.
  • Works with real memory implementations — no mocks required.

6. Module Graph Target

Layer 0: id/, dispatcher/, codec/
Layer 1: event/ (id, codec), command/ (id, dispatcher), query/ (dispatcher)
Layer 2: schema/ (event), snapshot/ (event)
Layer 3: decider/ (event, snapshot)
Layer 4: memory/, signing/, otel/, data/
Layer 5: middleware/, storage/, projection/ (+data), listing/ (+data), watermill/, pebble/, turso/, outbox/
Layer 6: integration/, catalog/, examples/, cmd/cqrs-gen, cmd/api-stability, testing/, registry/

The key addition is data/ at Layer 4 alongside memory/, signing/, and otel/. It becomes the standard read-model persistence contract, allowing projection/, listing/, and consumers to write typed read models without touching SQL.

7. Decision Principles for New Work

PrincipleApplication
Library, not framework Never impose a transport, message broker, or SQL driver. Provide interfaces and reference implementations.
Zero any in public APIs The only exception is database driver interop. Everything else is generic or strongly typed.
Composition over inheritance Store decorators (cached, versioned, retrying) wrap inner stores. No base structs.
Observability built-in Every new module uses otel/ for traces and metrics from day one.
Tombstone over delete Read models use event.TombstoneStatus; deletes are soft and reversible.
Test like we mean it ≥90% coverage, BDD suite, benchmarks, contract tests shared across implementations.
Acyclic module graph No lower-layer module may depend on a higher layer. Replace directives only for CI isolation.

8. Summary — What to Do Next

If I had one quarter to move this project from "excellent" to "perfect," the order would be:

  1. Build data/ — this is the biggest missing capability and unlocks everything else.
  2. Promote outbox/ — consolidate fragmented outbox code into a first-class, observable module.
  3. Complete storage parity — SQL Journal, Pebble BackwardsSource/StreamLoader, shared contract tests.
  4. Harden Turso — integration tests for sync semantics; target 80% coverage.
  5. Add registry middleware — publish-time schema validation to complement upcasters.
  6. Ship testing/ — fluent BDD utilities. This is the DX multiplier.
  7. Polish — fix BuildFlow, zero catalog lint, better onboarding example.

Bottom line: go-cqrs-lite is already one of the most thoughtfully architected Go CQRS libraries available. The remaining work is not about fixing fundamental mistakes — it is about closing the last gaps so consumers can assemble a complete, production-grade CQRS stack using only library modules, with zero hand-rolled infrastructure glue.
