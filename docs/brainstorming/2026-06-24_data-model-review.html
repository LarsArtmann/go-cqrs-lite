02AggregateID backing inconsistency

Primitive obsession / inconsistency

AggregateID is string-backed; every other ID is ULID-backed

id/aggregate_id.go:27 vs id/event_id.go:8 (and 6 others)
type AggregateID = cbid.ID[AggregateMarker, string]   // string-backed
type EventID      = id.Of[EventMarker]                 // ULID-backed ([]byte, sortable)

Seven of the eight branded IDs wrap a ulid.ULID (sortable, time-ordered, validated). AggregateID alone wraps a raw string, so it can hold any string with no format guarantee — the one place the "branded ID prevents garbage" promise breaks. This also means aggregate IDs are not uniformly time-sortable, which can surprise store implementations that optimise for ULID ordering.

Options (a) Make AggregateID = Of[AggregateMarker] for ULID consistency (breaking — changes the public value type); (b) document the split as intentional (user-supplied natural keys) and add a constructor that validates length/charset. Recommended: (b) now, (a) at the next major if consumers agree.

03Pointer-as-optionality

Design polish

Nil pointers encode "absent" for Tombstone & Causation

event/metadata.go:12-15
Tombstone *TombstoneMark  // nil == "no tombstone"
Causation  *Causation      // nil == "no causation"

Nil-means-absent is idiomatic Go, but it pushes a "present/absent" distinction to runtime (nil-checks) instead of the type system. The fields are well-named and the surrounding code handles nil correctly, so this is a nit — but a sealed-interface option type (type Presence interface { presence() } with None/Some) would make absence unrepresentable-by-accident. Low priority given the clean current handling.

04Snapshot leaks serialization detail

Leaky abstraction

Snapshot.State is []byte in the domain type

snapshot/store.go:16
type Snapshot struct {
    ...
    State []byte      // already-serialised bytes
}

The base Snapshot carries pre-serialised bytes, leaking the codec into the domain type. The library already ships the correct alternative — TypedSnapshot[State any] (snapshot/typed.go:24) with a generic State. Recommendation: present TypedSnapshot as the primary type in docs and treat Snapshot as the storage-layer envelope.

05The Vision (what perfection looks like)

Impossible states stay unrepresentable

Every identifier is a branded type that cannot be confused with another. Every count is a phantom Version/SchemaVersion that cannot be added to a plain int. Every error carries a typed Family the compiler can switch on exhaustively. Every mutable surface is hidden behind a clone-returning accessor. The three refinements above close the last gaps.

Strengths to Preserve

+
Phantom Version with full arithmetic + JSONCompile-time separation from int; Decrement returns ErrVersionUnderflow rather than underflowing.
+
SchemaVersion is a distinct type from VersionTwo semantically-different counts can't be mixed — a common bug class eliminated.
+
ImmutableEvent is fully encapsulatedAll fields unexported; Payload()/Metadata() return defensive clones. Mutating shared internals is impossible.
+
Typed 5-family error taxonomyFamily is an int enum switchable exhaustively; Error is a struct with code/family/context; 16 typed sentinels. Real errors-as-values, not string matching.
+
Per-module Metadata types (ADR-0031)event/command/query each own a Metadata embedding shared Tracing — a change to event's shape can't silently reshape commands.
+
TombstoneStatus is int+iota with IsKnown()The tri-state (Active/Tombstoned/Undetermined) is explicit, not a bool.
