Binary Wire Codec

A domain-aware binary serialization layer for the event envelope, designed to eliminate reflection, base64 inflation, and triple-encode round-trips in go-cqrs-lite.

The Problem

Every event payload today traverses three serialization passes for a single round-trip through the Pebble store. The SQL store avoids the worst of it, but still pays reflection tax on every json.Marshal / json.Unmarshal.

struct → json.Marshal → []byte in ImmutableEvent → json.Marshal (envelope) → base64(payload) → disk
Base64 Tax

Go's encoding/json automatically base64-encodes []byte fields. A 256-byte payload becomes 344 bytes on wire — a 33% size inflation with zero informational gain. This affects every event stored via the Pebble backend.

Current State

The codec/ module is a leaf — zero external dependencies, clean interface: 

type Codec interface {
    Encoding() Encoding
    Encode(v any) ([]byte, error)
    Decode(data []byte, v any) error
}

Two implementations exist: JSONCodec (wraps encoding/json) and RawCodec (passthrough for []byte). The payload lifecycle across the event module is already optimized with zero-copy internal reads via PayloadReadOnly() and payloadForDecode() — but the wire format remains pure JSON.

What's already good

The internal zero-copy paths (PayloadReadOnly, payloadForDecode, encodingForCopy) are solid. The win is on the wire format, not the in-process access patterns.

The Wire Format

Not a generic binary marshaller. A domain-aware format where the event envelope has fixed structure and the payload is opaque bytes. The codec knows the shape of an event; it doesn't care what's inside the payload.

Event Wire Layout
 ┌──────────────────────────────────────────────────────┐
 │  Header  (32 bytes, fixed)                           │
 │                                                       │
 │  [2]  magic          0xC5 0x51                    │
 │  [1]  version        format = 1                   │
 │  [1]  flags          bitfield                      │
 │  [4]  payload_len    uint32 LE                     │
 │  [2]  type_len       uint16 LE                     │
 │  [2]  agg_type_len   uint16 LE                     │
 │  [8]  occurred_at    int64 (unix nano)             │
 │  [4]  version        uint32                        │
 │  [4]  schema_version uint32                        │
 │  [4]  reserved       zeros                        │
 ├──────────────────────────────────────────────────────┤
 │  Fixed Fields  (variable length, zero-copy parse) │
 │                                                       │
 │  [type_len]     event_type     UTF-8 bytes          │
 │  [agg_type_len] aggregate_type UTF-8 bytes          │
 │  [16]           aggregate_id   raw ULID, no string  │
 │  [16]           event_id       raw ULID, no string  │
 ├──────────────────────────────────────────────────────┤
 │  Payload  (opaque, no encoding)                  │
 │                                                       │
 │  [payload_len]  bytes          raw, no base64       │
 ├──────────────────────────────────────────────────────┤
 │  Metadata  (optional, keyed by flags)             │
 │                                                       │
 │  [2]            metadata_len   uint16 LE              │
 │  [metadata_len] kv pairs       length-prefixed       │
 └──────────────────────────────────────────────────────┘

Flag bitfield

Bit Meaning
0x01 Has metadata block
0x02 Has non-zero schema version
0x04 Payload encoding = raw (vs json default)
0x08–0x80 Reserved for future use

Why this shape

  • Fixed 32-byte header — parse envelope without branching. One bounds check, then direct offset reads.
  • ULIDs as raw 16 bytes — no string encoding. id.EventID already implements BinaryMarshaler. Saves 10 bytes per ID (26-char string → 16 raw bytes).
  • Payload is opaque — the envelope codec doesn't inspect it. Payload encoding (JSON, msgpack, flatbuffers) is orthogonal and pluggable.
  • No base64 — binary payloads stored directly. This alone saves 33% on Pebble storage.
  • Metadata optional — most events have sparse metadata. The flag bit gates the entire metadata section.
  • Length-prefixed KV for metadata — no JSON object overhead. Simple [key_len][key][val_len][val] pairs.

Three-Layer Architecture

The design separates concerns into three composable layers. Each layer can be used independently. Consumers pick their stack.

Layer 1 · Binary Envelope
Serializes the event envelope: header + fixed fields. Zero-copy read path via unsafe.Slice / unsafe.String. No reflection. No allocs on envelope decode.

Existing API preserved

BinaryCodec and ComposedCodec both implement the existing codec.Codec interface. No API changes to event, command, query, or storage modules. They just get a new Encoding value: "binary".

The Real Win

The biggest gain isn't the binary envelope — it's eliminating the triple-encode for Pebble. Today json.Marshal(serializableEvent) base64-encodes the payload. A binary envelope stores payload bytes raw. That one change saves 33% storage and one entire encode/decode cycle.

The second biggest win: zero-copy envelope parsing. When replaying 100K events, you parse the 32-byte header once, then hand the payload slice directly to the inner codec — no json.Unmarshal of the envelope at all.

Integration Points

Pebble store

Today pebble/serialization.go uses json.Marshal(serializableEvent{}). Replace with BinaryCodec.Encode(evt). The payload bytes go raw into the value — no base64, no JSON envelope overhead. On load, BinaryCodec.Decode() parses the header in a single pass.

SQL store

Already stores payload as raw []byte in a BLOB column. The binary codec doesn't change SQL's column layout. It only changes how the payload is encoded before insertion — msgpack instead of JSON, for events that opt in.

Event creation

event.New() already accepts a codec.Codec parameter. Pass a ComposedCodec{Envelope: BinaryCodec{}, Payload: MsgpackCodec{}} and events are created with binary encoding. The encoding field on ImmutableEvent records "binary" — the same validation flow in DecodePayload works unchanged.

Signing

signing.SignMiddleware hashes PayloadReadOnly(evt) — the raw bytes. Binary encoding is transparent to signing. No changes needed.

Catalog / AsyncAPI / OpenAPI exporters

The catalog reads event metadata, not wire format. The Encoding field already records the codec used. Catalog exporters continue to describe the logical schema (JSON Schema), not the physical encoding.

Everything lives inside the existing codec/ module. No new modules.

Key Decisions

Custom binary, not protobuf or msgpack for the envelope

The event envelope has a fixed, known structure. Protobuf adds varint overhead, field tags, and schema dependency for no gain. Msgpack for the envelope would still require reflection. A hand-rolled binary format with fixed offsets gives O(1) field access and zero reflection.

Payload encoding is orthogonal

The binary envelope treats the payload as opaque bytes. Whether the consumer uses JSON, msgpack, protobuf, or raw bytes for their domain data is their choice. The envelope just carries the bytes and records the encoding via the flags bitfield. This preserves the library's "no opinionated transport" principle.

unsafe for zero-copy string conversion

unsafe.String(&buf[offset], len) and unsafe.Slice(&str[0], len) for converting between []byte and string without allocation. This is the same pattern used by strings.Builder, strconv, and the standard library's own fast paths. The alternative (allocating a string copy per field) defeats the purpose of the binary format.

Backward compatibility via format version

The header's version byte enables future format changes without breaking existing stored data. A decoder that sees version 2 can branch to a different layout while still supporting version 1.

No streaming / incremental decode

Events fit in memory. This is a CQRS library, not a streaming framework. The entire wire blob is available before decode starts. This simplifies the implementation enormously and avoids the complexity of partial reads, buffering, and framing.

Alternatives Considered

Approach Verdict Why
Protobuf envelope Rejected Requires .proto schema, code generation, and adds google.golang.org/protobuf dep. Overkill for a fixed 10-field envelope.
Msgpack for everything Partial Good for payload encoding (Phase 3), but the envelope still pays reflection cost. Binary header is faster for fixed-structure data.
Flatbuffers for everything Future option Zero-copy is compelling, but requires per-event-type schema generation. Too opinionated for the library's design. Available as Phase 4 opt-in.
Gob encoding Rejected Go-specific, not cross-language. Type registration complexity. No random field access.
CBOR (RFC 8949) Deferred Attractive standard, but no compelling advantage over msgpack for this use case. Could be added as another payload codec later.
Compress payload (zstd/snappy) Orthogonal Compression is a transport concern, not a codec concern. Can be layered on top via middleware. Not part of this proposal.
Just optimize JSONCodec Insufficient Can't fix base64 tax. Can't fix reflection overhead. Can't achieve zero-copy decode. The ceiling is too low.

Consumer choice preserved

This proposal adds options without removing anything. The existing JSONCodec remains the default. Binary codecs are opt-in. Consumers who value debuggability over throughput keep JSON. Consumers who need maximum performance opt into binary. The library stays unopinionated.
