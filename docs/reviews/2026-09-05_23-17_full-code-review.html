01The v5 Gap, Quantified

The repo marks the entire v5 removal surface with // Deprecated: doc comments: ~150 markers across 30+ files — every stack/* preset, stack.Materialize/RunProjections/Bundle, the storage/relational and storage/view tiers, graph.GraphProjection, the ADR-0126 shells (schema.VersionedStore, signing.Rejecting*, metadata.CustomData), and the ADR-0114 tombstone helpers. Before this review, the linter detected exactly two of them (event.NewEvent, dispatcher.Register via A014) plus transport module imports (F030).

NEW — V007 v5-removed-api-usage

Data-driven detection of the v5 removal surface at use-site granularity, each finding carrying the ADR reference and the sanctioned replacement:

  • Whole-module flag — any import-qualified reference into the 10 wholly-removed modules (8 stack presets, storage/relational, storage/view) fires, covering calls, type references, and composite literals alike.
  • Symbol table — 30 deprecated symbols inside surviving modules (stack root, graph, schema, signing, encryption, metadata, event), sourced mechanically from the repo's own Deprecated: markers.
  • Alias-safe resolution — qualifiers resolve through import declarations with version-suffix handling and dot-import immunity; foreign packages named stack or event cannot false-positive.
  • Verified end-to-end — a synthetic compiling consumer with 81 local replace directives produces all three finding classes with correct positions, ADRs, and suggestions. Silent in library self-lint mode.

02Fixed On the Spot

Bug 1 — Malformed block suppressions failed OPEN critical

//cqrs-lint:ignore-start(A001 (typo, unclosed paren) and even ignore-start() suppressed every rule inside the block — a typo could silently disable the entire ruleset for a file region. parseBlockStart now returns (ids, valid); malformed directives fail closed and suppress nothing. The old fail-open behavior was pinned by a test — the test asserted the bug. pkg/suppression/parser.go:344, block_test.go

Bug 2 — Working suppressions reported stale high

Stale detection matched a finding's line ±1, but the suppression filter honors a comment above the finding skipping blank lines. A suppression separated from its finding by a blank line worked — and was simultaneously reported stale under --fail-on-stale-suppressions, failing CI on correct code. Stale detection now rebuilds the matched-location set per file, mirroring the filter's blank-skip walk exactly. pkg/suppression/stale.go:35

Bug 3 — Auto-fix could rewrite the wrong occurrence high

When position-based matching missed, the fix provider fell back to the first occurrence anywhere in the file — with repeated patterns (the norm: multiple event.NewEvent calls), --fix could edit a different site than the one reported. The fallback is now scoped to the finding's line and refuses to edit otherwise. Two pre-existing test fixtures carried bogus positions that the loose fallback had masked — corrected, and the stricter semantic is pinned by new tests. pkg/fix/provider.go:51

Bug 4 — A014 alias blindness and foreign-package false positives medium

The deprecated-API detector matched the textual qualifier only: an aliased import ev "…/event/v4" + ev.NewEvent(…) was invisible, while a consumer's own package named event with a NewEvent function false-positived. It now resolves qualifiers through the file's imports (QualifierResolvesTo) — the exact helper whose doc comment says rules "should use this helper". Tests cover alias, foreign-package, and upcaster-closure paths. pkg/rules/api/a011_a014_a017.go

Bug 5 — Suppression filter index panic on out-of-range findings defensive

The block-suppression check bounds the finding line against the file length; the inline check's backward loop did not. A file truncated between AST load and suppression check (the concurrent-session hazard this repo documents) could panic the filter. The loop is now clamped, with a beyond-EOF regression test. pkg/suppression/parser.go:266

Bonus — the repo's own lint gate was red: 366 files failing gci high

Running the full nix run .#verify exposed that a .golangci.yml reformat had silently re-added gci to formatters.enable — the exact config-reformat-mutates-linters class as the 2026-08-30 depguard incident, and the class AGENTS gotcha 18 documents. Import grouping is owned by treefmt; gci made the linter fight the formatter, failing 366 treefmt-clean files repo-wide. Fixed at root cause (gci removed per the documented decision) and pinned mechanically: scripts/check-formatters.sh now runs inside nix run .#check-lint-config and fails loudly on recurrence. The four modules still red once the noise cleared (pre-existing: ST1019 duplicate encoding/json/v2 imports in metadata + record tests, a varnamelen rename in catalog, a drifted //nolint:contextcheck in pgengine) were fixed in the same pass.

03Open Findings (harvested to TODO_LIST)

Nine findings were real but beyond this pass's blast radius; each is a bounded TODO under TODO_LIST.md § cqrs-lint. The three with v5 relevance:

V007 table drift risk

The symbol tables are hand-curated; a future Deprecated: removed in v5 marker could ship without lint coverage. Proposed: a meta-test that greps the repo's markers and asserts V007-table membership (Effort: S — the single highest-leverage follow-up).

Examples are immune to consumer rules

IsLibrarySelfLint prefix-matches the module path, so example/* suppresses all coaching rules including V007 — an example demonstrating a v5-removed pattern would silently teach it (Effort: S).

lintutil dot-import footgun

QualifierToImportPath resolves ANY qualifier to the import path when a dot-import exists — V007 shipped its own resolver to avoid it; A014's helper path still carries the edge case (Effort: M, needs call-site review).

The remaining six: severity-vs-catalog meta-test, fix-provider dual edit-spec source of truth, dead lintutil exports, the gci-vs-treefmt fight resurfacing in performance/ (10 committed findings), dead RULES.md DocURLs, and 16 files over the 350-line limit.

04Strengths Worth Preserving

Registration integrity is machine-checked

TestCatalogCountMatchesRegister asserts bidirectional catalog ↔ detector agreement; README and AGENTS rule counts are meta-test-pinned (this review's +1 rule was forced through all four count sites by the gate itself — the safety net works).

The meta-rule pipeline treats its own output as adversarial input

Raw-string-aware suppression parsing, per-module feature profiles with longest-prefix resolution, config-key typo validation, and adoption-excluded health scoring — the linter consistently models "what if the analyzed code lies".

F030 is the right template for migration coaching

ADR reference + concrete replacement + import-granularity precision; V007 extends the pattern to symbols and the two rules now partition the deprecated surface cleanly.
