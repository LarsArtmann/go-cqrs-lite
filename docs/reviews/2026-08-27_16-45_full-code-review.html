Verdict

The library is in strong shape. Tier 0–3 code shows consistent discipline: defensive cloning at every boundary, errorfamily classification everywhere, validated constructors, and honest doc comments. The residual risk the review targeted — behavioral and semantic drift that gates cannot see — produced three real bugs (a silently-poisoned lifecycle counter, a zero-backoff hot crash loop, a recurring TTL-test flake misdiagnosed twice) and four footguns, all fixed on the spot with regression tests. No split brains, no type-safety violations beyond documented any exception zones.

01Coverage & Method

Pareto-tiered per the plan artifact (docs/planning/2026-08-27_15-10_DEEP-FULL-CODE-REVIEW-PARETO.html): deep manual read of everything a consumer imports by default (Tier 0–3 cores), spot review of Tier 4–6 hotspots, and repo-wide smell sweeps. The repo was already heavily gated (CI verify, api-stability golden, dep budgets, coverage drift, duplication baseline) and recently reviewed (system 2026-08-16/17, data models 2026-08-22) — this review deliberately hunted what gates cannot see: cancellation semantics, cache-poisoning paths, counter recovery after failed writes, doc lies, and load-order contracts.

Honest coverage statement

Every production file was read in: record, id, dedup, dispatcher, metadata, event, command, query, scheduling, schema, snapshot, decider, kv, listing, projection, deriver, scenario, commandlifecycle (+projections), projectionhost, graph (core), storage/memory (LogStore core), and middleware/retry. Tier 4–6 engines, stacks, transports, catalog and cmd/* were spot-checked (1–3 files each) and covered by the sweep greps; the engine modules are dep-isolated intentional clones by design (ADR-0126 / art-dupl baselines) and rely on their own conformance harnesses (enginetest/adttest). Not every one of the 2,375 files was opened — the tiers above were chosen because every consumer imports them.

02Fixed on the Spot

Bug

Recorder version cache poisoned forever after one failed append

commandlifecycle/recorder.go:172-180

On any Save failure the in-memory version counter stayed incremented past the unwritten position, so every subsequent lifecycle emit conflicted with the real stream — in default best-effort mode the conflict is logged and swallowed, meaning all further lifecycle events for that command were silently dropped after a single transient store error or concurrent writer.

Fix Drop the cached version on Save error so the next emit re-seeds from the store. Pinned by TestRecorder_RecoversAfterFailedAppend (fail-first store wrapper; fails on the old code).
Bug

Backoff shift overflow collapses crash restarts to a hot loop

projectionhost/worker.go:201, 274-277

1<<uint(restartCount-1) wraps to zero once the exponent passes 63: under unlimited-restart configs (maxRestarts = -1) a permanently failing projection degrades from exponential backoff to a zero-delay crash loop after 64 crashes. The same latent overflow sat in the per-event retry path for large dlqThreshold.

Fix Cap the exponent at 30 (maxBackoffShift); 2^30 × initial delay is far beyond any sane backoffMax cap, so behavior is unchanged for realistic configs.
Flake

TTL property test flake, third recurrence — structurally cured

idempotency/sqlstore/property_test.go:147-198

The "seen immediately after Record" assertion shared one key and a 50ms TTL with the expiry assertion: under full-gate load the goroutine can be descheduled past the TTL between Record and Seen. Margin bumps (10→50→100ms) never killed the class. Bonus find while fixing: the assertions swallowed Seen's error (seen, _ :=), so error paths asserted as false negatives.

Fix Visibility assertion moved to a derived key with a 1-hour TTL (timing-proof by construction), errors propagated, expiry assertion keeps its wide margin. 3× -count runs green.
Footgun

WaitForVersion panics on non-positive poll options

decider/wait_for_version.go:35-52, 90

WithPollInterval(0) reached time.NewTicker, which panics on non-positive intervals. Repo precedent (decider.NewStateCache, listing.ListBuilder.PageSize) is to clamp.

Fix Both wait options clamp non-positive values to defaults; documented on the option funcs; two regression tests.
Bug

Flight-recorder snapshot dies with the request context

decider/flightrecorder.go:44-53

The post-Execute snapshot goroutine inherited the request ctx, which is typically cancelled exactly when error captures matter (client gave up). go-flightrecorder's snapshot() checks ctx.Done() first — the capture was silently discarded.

Fix context.WithoutCancel for the async snapshot (matching projectionhost's existing deferred-flush pattern). Pinned by TestRepository_FlightRecorder_CaptureSurvivesCancelledContext.
Footgun

NewTypedRepository accepted nil Decide — panic time bomb

decider/typed_decider.go:42-51

NewRepository validates Apply but nothing validated the typed Decide function; nil surfaced as a typed-nil-call panic at the first dispatch, far from the construction site.

Fix Constructor rejects nil Decide with new sentinel decider.ErrNilDecide (family Rejection); golden regenerated (4274 exports); regression test added.
Bug

kv.Cache.Set left a stale entry when the isolation copy failed

kv/cache.go:149-167

Store-write-then-copy order: if the deep copy for cache isolation failed after a successful store write, the cache kept the pre-Set value — the next Get served stale data while the error suggested nothing was cached.

Fix Invalidate the cached key on copy failure; the error still propagates.

03Open Findings (harvested to TODO_LIST.md)

P3

Unbounded maps in long-running paths

commandlifecycle/recorder.go · commandlifecycle/middleware.go · snapshot/read_pressure.go

The Recorder's version cache, the standalone AttemptMiddleware tracker, and ReadPressure's reads map all grow with distinct keys and are never evicted. Individually small; together a slow leak in exactly the long-running dispatch loops this library targets.

P3

projectionhost retries non-retryable error families

projectionhost/worker.go:233-291

applyWithRetry retries handler errors dlqThreshold times regardless of family — a Rejection or Corruption (permanent by definition in the 6-family taxonomy) still burns the full retry budget before DLQ. middleware/retry.go already does this right via IsRetryable.

Observations (deliberate choices, no action)

Publish-failure paths (decider, listing, commandlifecycle) force Infrastructure classification on downstream errors — defensible ("the publish operation is infrastructure") but it can mask Transient retryability; consistent across modules, so left alone. listing's DetectTombstone(lastEvent) heuristic assumes no post-tombstone events — true under decider discipline, and the ADR-0114 type-based bridge replaces it at v5.

05Strengths

  • Decider's state cache is a fold checkpoint, not a blind cache — every hit reconciles via LoadFromVersion, so stale entries self-heal and publish-failure paths cannot corrupt subsequent loads.
  • LogStore[T, ID] (ADR-0126): one generic WAL core, divergent policies injected via config — the unification held up under review with zero copy-paste found.
  • Defensive cloning is universal at boundaries (kv Get/Set/iterator, event accessors, batch ops) — no aliasing escape hatches found in any tier read.
  • errorfamily discipline: zero bare fmt.Errorf without wrapping in production code; sentinel codes are dot-namespaced and honest.
  • Must* panic pattern is consistently documented ("use only for hardcoded constants"); no stray panics in library paths.
  • Sweeps came back clean: slices.Backward value-copy trap correctly avoided everywhere (indexed forms), no duplicate type declarations across modules, api golden + doc-check + changelog-symbols all honest.
