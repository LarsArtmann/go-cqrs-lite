How go-cqrs-lite can better use itself

A library whose own code does not always consume the primitives it ships for consumers. Two sibling transports prove it; here is the proof, the two fixes that are already verified, and the ranked plan for the rest.

Correctness gap found

The one-sentence diagnosis: go-cqrs-lite hand-rolls local copies of its own primitives whenever the shared helper is one import tier away, and sibling modules then drift apart. The library is excellent at giving consumers a primitive (dedup.Ring, metaengine.DeferClose, SortPaginate) and inconsistent about using it internally.

01What we got wrong

The tell: two siblings, one primitive

metaengine/irohengine/quic deduplicates op IDs with dedup.Ring (graceful eviction, its own comment says "no reset gap"). metaengine/irohengine/loopback, the sibling transport in the same module family, hand-rolled a map[string]struct{} that resets wholesale at 10k entries. Same repo, same contract, two different correctness levels. That is the pattern in miniature.

The fix direction

Dogfood the primitive at every call site. Where a call site cannot reach it without a dependency-budget hit, the primitive is mis-tiered - fix the tier, not the call site.

02Findings + fixes

Fixed

Loopback transport ignored dedup.Ring - and had a dedup reset gap

metaengine/irohengine/loopback/transport.go:68-70, conn.go:87-95, dedup_internal_test.go

markSeen stored IDs in an unbounded map and, past 10k entries, dropped the whole set - so an op ID seen before the reset was forgotten and would be re-applied on redelivery. The library's own dedup.Ring bounds memory and evicts only the oldest ID, with no reset gap. The sibling QUIC transport already used it.

Fix Switched loopback to dedup.NewRing(DefaultDedupCapacity), promoted dedup to a direct dependency (budget 4, now 3), and rewrote the internal test to pin graceful eviction of the oldest ID plus bounded growth. Green in both GOWORK=off and workspace modes.
Fixed

Engine modules bypassed metaengine.DeferClose

metaengine/{enginetest,claimkit,pebbleengine,sqliteengine}

The helper exists specifically to replace defer func() { _ = x.Close() }(), and AGENTS.md records the 2026-09-10 conversion - but 9 engine-module sites never got the memo, in packages that already import metaengine.

Fix Converted 9 sites across 7 files. Build + -short tests green in all four modules.
Open - needs a decision

The close helper is mis-tiered

metaengine/engine.go:564-573 vs storage/* and queue/*

54 production sites still hand-roll the close idiom, concentrated where the helper is expensive to import: storage (16), queue (7), example (5), scheduling (3), plus scattered. They cannot reach metaengine.DeferClose (Tier 3) without a budget hit, and storage/sql.CloseRows is a Tier-4 sibling. The primitive is fine; its address is wrong.

Recommendation Expose a Tier-0 Closer/DeferClose (or re-export it from an existing primitive) and let metaengine keep its alias. Owner/ADR call - growing public API is a v5-window decision.
Open

Duplicated scan/paginate helpers across engines

metaengine/{sqlite,mysql,duckdb}engine, pebbleengine, bboltengine

scanScoredVector, scanJSONValues, and per-engine sortAndPaginate* variants repeat near-identical bodies. Every engine already depends on metaengine, so the shared home exists. Gated by the .art-dupl baseline dirty-tree rule, so it needs a clean-tree window.

Strengths worth preserving

+
The primitives are genuinely good dedup.Ring is nil-safe, O(1), and documents its eviction contract; DeferClose has 151 call sites.
+
The policy is already encoded in gates The duplication gate and cqrs-lint rules (C015, F015-F017) turn "use the primitive" into CI, not folklore.
+
The North Star has a dogfooding demo in flight example/goal-shaped-app (built concurrently this session) exercises the declare-once / operator-picks story end to end.

Rejected on purpose (do not relitigate)

queue/task ID minter vs the id/ module

Superficially a ULID clone. It is not. Its per-millisecond re-rolled seed plus monotonic sequence is load-bearing for the id ASC claim tie-break (a documented conformance flake fix). Unifying would change sort semantics and add deps to a near-zero-dep module. Leave it.

system.CachedEventStore as a hand-written wrapper

Contract #16 warns that hand-written wrappers drop optional capabilities. This one does not: it forwards ReadAll/ReadFrom, and the sanctioned event.DecorateStore also implements optional interfaces unconditionally (returning ErrInnerStoreNot* when unsupported). Consistent, not a bug.

03Improvement plan

1

Loopback transport adopts dedup.Ring (done)

Removes the reset gap, bounds memory, pins graceful eviction with tests.

2

Engine modules adopt DeferClose (done)

9 sites across enginetest, claimkit, pebbleengine, sqliteengine.

3

Decide the Tier-0 close helper

An ADR/owner call: a primitive-tier Closer/DeferClose unlocks the remaining 54 sites without per-module dep churn.

4

Finish the sweep where the helper is already importable

queue/{sqlite,mysql,postgres} already require metaengine; convert the 7 sites and add the import.

5

Extract the duplicated scan/paginate helpers into metaengine

Do it in a clean-tree window so the .art-dupl baseline can shrink honestly.

6

Keep the goal-shaped app as the compile-gated North Star demo

The best proof that consumers declare only commands, events, and queries is the library's own example doing exactly that.
