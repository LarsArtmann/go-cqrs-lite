40 KLOC of Go pretending to be a library, morphing into a framework, a docs empire, a benchmark suite, a static-site generator, and a WASM demo — while shipping 3 dead build tags, a broken CI gate, 88 unclassified errors, and 740 commits in 20 days. 00The Verdict

You can absolutely program. You can't absolutely stop.

The Go on display here is genuinely good: interface segregation done right, typed handlers, branded IDs, real OpenTelemetry, a 5-family error taxonomy, property-based tests, golden tests, integration tests against a real Postgres container. The unit of code quality is high. This is not the work of someone who can't program.

The problem is everything around the code. The repo is a case study in compulsive scope expansion driven by commit velocity: 740 commits in 20 days (37/day, 1 author), 53,726 net Go lines added in one month, 60,884 markdown lines added, 67,886 HTML lines added. Every interesting thought becomes a module, every proposal becomes 5 versions of a markdown file, every CI gate is added with an escape hatch so it can never fail, every architectural rule is documented and then quietly broken. You're not building a library any more — you're building a monument to the idea of a library, and the monument is now 3.5× heavier than the library it commemorates.

The real bug is not in any .go file. It's the absence of a discipline that says "no". Every shiny object gets added. Nothing gets removed. The API surface has grown 1,266 → 1,351 → 1,784 → 1,852 exports across four releases without a single Deprecated or Removed entry in the changelog. The docs grow 3× faster than the code. This is how libraries die — not from bugs, but from becoming unmaintainable through their own unchecked ambition.

07CI Theater: Gates That Look Like Gates But Aren't

Theater #1 · The Big One

file-size-gate is structurally incapable of failing — reproduced locally

.github/workflows/ci.yml · file-size-gate job
failed=false
find . -name "*.go" ... | while read -r f; do   # ← PIPE = subshell!
  if [ "$lines" -gt 350 ]; then
    failed=true   # ← dies in subshell, never propagates
  fi
done
# ↑ $failed is ALWAYS false here. Gate exits 0. EVERY. TIME.

Reproduced locally: ran the exact script pattern with sh -c '…'. Result: 7 violations found inside the loop, $failed=false after the loop, exit 0. This gate has never fired in the history of the project.

Fix (1 character) Replace the pipe with process substitution: while read -r f; do …; done < <(find …). Now the loop runs in the parent shell and $failed propagates.
Theater #2

gosec runs with -no-fail — can never break CI

.github/workflows/ci.yml · gosec job
gosec -fmt sarif -out gosec.sarif -no-fail ./event/... ./command/...

-no-fail means gosec returns exit 0 even if it finds critical vulnerabilities. The SARIF uploads to GitHub for a nice badge, but the job itself can never fail the build.

Theater #3

vulncheck and secrets-scan have || true

flake.nix · apps.vulncheck, apps.secrets-scan

Both end with || true and are not wired into CI. They print a green checkmark regardless of findings. Performative security.

Theater #4

Benchmark regression check emits ::warning:: not ::error::

.github/workflows/ci.yml · benchmark job

A >2× regression produces an annotation, not a failure. And benchmark-baseline.txt is committed and updated by hand — easy to gaslight.

11Type Model: Where It Hurts

Type Hole #1

query.Handler returns any — by design

query/dispatcher.go:27
// The return type is `any` because a single dispatcher handles heterogeneous query types
type Handler = func(context.Context, Query) (any, error)

func (d *Dispatcher) Dispatch(ctx context.Context, query Query) (any, error)

// The typed escape hatch:
func DispatchTyped[R any](ctx context.Context, d *Dispatcher, q Query) (R, error) {
    // internally does a runtime type assertion on the any — not compile-time safe
}

Every consumer either uses DispatchTyped (runtime type assertion + potential alloc) or re-implements the assertion. The untyped Handler and the typed TypedHandler[Q, R] are both first-class in the docs. Pick one as primary.

Type Hole #2

schema.Validator type-erases payloads to any

schema/validator.go:35–36

validators map[event.Type]func(any) error — callers can't recover the original T after validation. They must re-decode. RegisterType[T]() papers over this at registration time but the stored map still erases.

Type Win

The branded ID design is genuinely excellent

id/

type Of[T any] = cbid.ID[T, ulid.ULID] with phantom markers (UserMarker, CorrelationMarker) is the correct pattern. Impossible states made unrepresentable — exactly what the principle asks for.
