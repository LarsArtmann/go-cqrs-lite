04Real bugs shipped (not caught by tests)

Bug 1 · Critical · silent data corruption

Materialize treats any Store.Get error as "not found" → OnCreate

stack/materialize.go:131-144
existing, err := m.Store.Get(ctx, key)
if err != nil {
    // Not found → create.    <-- LIE. Any error lands here.
    if m.OnCreate != nil {
        val, createErr := m.OnCreate(ctx, evt)
        ...
    }
    return nil
}

A DB connection failure, a CBOR decode corruption, a Pebble IO error — all silently classified as "record doesn't exist" and trigger OnCreate. The new record overwrites the real one on the next Set. Silent data loss dressed up as a successful create. Tests don't catch it because the fake store only returns "not found" errors.

Fix if errors.Is(err, kv.ErrNotFound) { ... create path ... }; return err. Add a test that injects a non-ErrNotFound error and asserts it propagates.
Bug 2 · Important · latent footgun from uint64 change

Version.Add(n int) has no negative-input guard → silent wrap to MaxUint64

event/types.go · storage/pg_bus_listen.go (np.Version - 1 underflow)

Version is now uint64. Sub() guards against underflow (if Version(n) > v). Add(n int) does NOT — a negative n silently wraps to a huge value. Also: storage/pg_bus_listen.go computes np.Version - 1; if a NOTIFY payload ever carries Version == 0 (shouldn't happen, but the wire format allows it), it underflows to MaxUint64.

Fix Either make Add(n uint64) (typed, can't be negative) OR add if n < 0 { return v, ErrNegativeVersion }. Add a property-based test (pgregory.net/rapid, already a dep) that verifies Add/Sub invariants over the uint64 domain.
Bug 3 · Important · data race

PgxListener.conn read/written without mutex across reconnect/Close

stack/postgres/pg_listener_reconnect.go · pg_listener.go Close()

l.conn is nulled in reconnect() and Close(), read in receiveOnce(), with no synchronization. Currently serialized only by ctx-cancellation timing. go test -race against a real Postgres with concurrent Close would catch this; the integration tests don't exercise it.

Fix Add a sync.Mutex (or atomic.Pointer[pgxpool.Conn]) guarding l.conn. Add a race test that calls Close() while receiveLoop is mid-iteration.
Pre-existing · not ours, but unfixed

CBOR fuzz test failure (duplicate map key -17)

codec/codec_fuzz_test.go FuzzCBORCodec_CanonicalFidelity

Real bug in the CBOR codec's canonical-encoding handling of fuzzed integer keys. Pre-dates all of yesterday's work. 37/38 test suites green. Listed as Top-25 #1 in the status report; still unfixed.

05Stupid patterns we keep doing

Question 2: "What is something that's stupid that we do anyway?"

  • Bulk-delete by directory pattern. The docs wipe deleted 564 files because they matched docs/status/archive/** — not because anyone verified each was stale. They weren't. Status reports are session history, not stale TODOs. Verify before deleting. Always.
  • Mark TODOs DONE before wiring. TransactionID is the canonical case. Build the type, tick the box, move on. The type does nothing. "DONE" means "wired and tested," not "the file exists."
  • Status reports with metrics that go stale on the next commit. "62 files" was true for 3 hours. Status reports are snapshots — fine — but the next one must explicitly correct the previous one's reverted claims. History is a sequence, not a stack of independent truths.
  • 100+ "execution plan" documents. docs/planning/ has 100+ planning docs, most describing work that was either done, abandoned, or superseded by the next plan. Each new "comprehensive plan" claims to supersede the last. None deletes the last. Stop writing plans; do work. If you must plan, delete the prior plan first.
  • "v3 boundary" framing for work that already shipped. ADR-0029 is labeled "v3 breaking change" but the move is done. V3_MIGRATION lists memory/ as "to be deleted in v3" but it's already deleted. If the work is done, mark the ADR Implemented and remove it from the migration doc.
  • Moving complexity into test helpers. FakeBus went from a 30-line stub to a 130-line synchronous bus with real middleware chains. Test helpers should be simple stubs, not parallel implementations of production logic. If your fake needs its own tests, it's not a fake.
  • Calling things "ghost code" without grep. pg_bus and reactive were labeled ghost. Both are live. One grep would have caught both. The grep is cheaper than the restore.

06Scope creep severe

Question 8: "Are we focusing on the scope creep trap?"

In 24 hours we shipped: 5 new ADRs, a 102-task Pareto plan, a V3 migration doc, a deployer-first architecture, 6 new public types, 4 deleted modules, 1 restored set of 564 docs, and 70+ commits. The library is a CQRS/Event-Sourcing SDK, not a startup. The scope of "what could be improved" is infinite; the scope of "what should ship next" is small and focused.

  • The 102-task Pareto plan is itself scope creep. It exists because we wanted to "MAKE A PLAN" instead of "fix the 3 real bugs." The plan has 102 tasks; 24 hours later, 17 are done, 6 introduced ghost islands, 3 introduced bugs, and the rest are pending or rejected. The Pareto principle says 80% of value comes from 20% of work — the plan should have been 5 tasks, not 102.
  • Plans for transport/grpc/, transport/nats/, transport/redis/ when no consumer has asked for them. Tier 3A-C (T076-T085). YAGNI. A library shouldn't ship adapters for transports nobody is using it with. Wait for a consumer.
  • v3 migration planning while v2.7.0 just shipped. The deployer-first architecture is good, but v2.7.0 shipped yesterday. Stabilize before breaking.
  • 6 new public types in 24 hours, 0 wired. Building ahead of demand is how APIs get designed in a vacuum. TypedDecider, DistributedRunner, Materialize, CatchUpSubscriber, EventPublisher, TransactionID. Each is a maintenance liability with no consumer feedback shaping it.
The reframe Stop planning v3. Fix v2. The library has 3 real bugs (Materialize error misclassification, Version underflow, PgxListener race), 1 stale ADR status, 1 broken migration doc, 1 ghost type marked DONE, and 1 duplicated module (readmodel ↔ kv). That's a 1-day scope. Do that day. Then reassess.

09Architectural reflection

Good decisions made in the last 24h

  • Watermill as delivery layer (ADR-0028). Replaces 4 ad-hoc bus implementations with one battle-tested library. GoChannel default, Kafka/NATS backends via WithBackend. Correct use of an established library instead of reinventing.
  • Storage consolidation (ADR-0029). storage/{memory,pebble,turso} under one parent. Stores belong with stores. Module boundaries now match domain boundaries.
  • Version: uint64. Strong types over runtime checks. Domain invariant (no negative versions) enforced at compile time. The right kind of breaking change.
  • MessageToEvent export (DRY). Killed the decode duplication between watermill and stack. Small, correct, irreversible win.

Decisions causing problems now

  • ADR-0032 (readmodel → kv) half-applied. Created the destination, didn't delete the source. Now have two near-identical types. Either finish the merge or revert the destination. Half-applied ADRs are worse than no ADR.
  • ADR-0030 (dissolve projection) half-applied. Built CatchUpSubscriber + Materialize, didn't delete projection/. Now have two catch-up implementations. Same problem.
  • ADR-0031 (metadata split) half-applied. Typed structs added, aliases not broken. The aliases are the part consumers actually feel. Half-applied = invisible to consumers = no value.
  • "v3 boundary" framing. Lets us ship additive prep work without committing to the break. Result: 3 half-applied ADRs, 6 island types, 1 duplicated module. Either commit to v3 (break, release) or stop building v3 prep.

Libraries we should be using more

  • pgregory.net/rapid — already a dep, barely used. Perfect for Version arithmetic, Metadata round-trips, ULID ordering, CBOR canonical encoding. Should be the default for any pure-function property.
  • onsi/ginkgo + gomega — used in event/decider/query BDD suites. Should extend to projection, stack, storage for the catch-up/replay flows that keep having subtle ordering bugs.
  • samber/ro — reactive operators. Already used for event streams. The dedup logic in event/reactive_dedup.go is good; the issue is that it's slated for removal in favor of Watermill's built-in dedup. Don't remove until the replacement is wired.

11How can we be less stupid?

Question 6. Rules to internalize, not checkbox.

  1. Never delete without grep. One grep -rn "Name" --include="*.go" before any deletion. The grep is cheaper than the restore.
  2. "DONE" means wired and tested. Not "the file exists." If the type has no consumer outside its own test, it's not done — it's an island.
  3. Status reports are write-once. Don't trust their numbers after reverts. The next report must explicitly correct the previous one's reversed claims.
  4. Stop writing comprehensive plans. We have 100+ in docs/planning/. Each claims to supersede the last; none deletes the last. Do the work; if you must plan, delete the prior plan first.
  5. Half-applied ADRs are worse than no ADR. If you build the destination but don't delete the source, you get a split brain. Either finish the merge in the same commit, or don't start.
  6. "v3 boundary" is not a license to ship half-work. Either commit to v3 (break, release) or stop building v3 prep. The current state — 3 half-applied ADRs, 6 islands — is the worst of both worlds.
  7. If the fake needs its own tests, it's not a fake. FakeBus at 130 LOC is a parallel implementation. Either extract to a real module or shrink to a stub.
  8. Verify examples compile. Codify V3_MIGRATION.md examples as Example_* functions. go test catches the breakage automatically.
  9. Run the review skill when you schedule it. Top-25 #10 was "run brutal-self-review." We didn't, until the user asked. Schedule = do, not defer.
  10. Test the error paths, not just the happy path. Materialize's bug exists because the fake store only returns ErrNotFound. Inject real errors; assert they propagate.
