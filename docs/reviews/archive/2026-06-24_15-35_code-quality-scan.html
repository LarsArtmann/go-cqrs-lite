02The Real Defects (7)

After filtering out style, these are the findings worth acting on.

Security

Integer-overflow conversions flagged by gosec G115

middleware/tracing.go:76 · watermill/protocol.go:151

Two uint64→int / int→uint64 conversions can overflow on 32-bit targets. Per the project's own lint conventions, these should be isolated in a single-line helper function with a scoped //nolint:gosec.

Fix Extract a safeIntFromUint helper and gate with //nolint:gosec // bounded by schema.
Correctness

Non-exhaustive switches — silent fallthrough

stack/materialize.go:126 · storage/view_store_auto.go:159

materialize.go switches on event.TombstoneStatus without a TombstoneUndetermined case; view_store_auto.go switches on reflect.Kind missing many cases. Both mean a new enum value or unhandled type is silently ignored rather than caught at compile time.

Fix Add explicit cases or a guarded default that returns an error. The exhaustive linter is correctly flagging real gaps here.
Dead code

Unused function in SSE broker

transport/http/sse.go:266 · func drainReplayDups

drainReplayDups is declared but never called — leftover from an earlier dedup strategy. The unused linter caught it; go vet does not.

API hygiene

Deprecated API still in use

middleware/generic.go:85 · staticcheck SA1019

References query.Handler, which is deprecated in favour of TypedHandler[Q, R]. Internal code should not depend on its own deprecated surface.

Design smell

context.Context stored in a struct

watermill/event_bus.go:40 · containedctx

A struct embeds a context.Context. Contexts should flow through method parameters, not be stored, to preserve cancellation/lifetime semantics.

Complexity

High cognitive complexity & nested blocks

kv/viewstoretest/contract.go:49 (gocognit 37) · stack/materialize.go:116 (nestif)

Two functions exceed complexity thresholds. Test-contract code and the tombstone branch in Materialize are candidates for extraction.

04Architecture Signals Surfaced by the Scan

Test-dependency leak: 4 core modules depend on storage/memory

event, command, decider and watermill declare storage/memory as a direct production require, yet it is imported only from _test.go files. This creates a circular require graph (e.g. event → storage/memory → command → event) that resolves only because the real import graph is acyclic. It also means the leaf event module drags a Layer-4 test implementation into its module graph.

Fix direction Hand-rolled in-package fakes, or consolidate the test doubles already in event/eventtest. See the architecture-review & go-modularize reports.

transport/grpc excluded from go.work by a genproto conflict

transport/grpc compiles cleanly in isolation (GOWORK=off) but is kept out of go.work: adding it triggers an ambiguous-import error between the monolithic google.golang.org/genproto and the split genproto/googleapis/rpc (grpc v1.81.1). Root go test ./.../lint never cover it. Fix = align the workspace on the split genproto modules, then wire it in.

File-size gate would fail on generated protobuf

transport/grpc/proto/cqrs.pb.go (530 lines, // Code generated … DO NOT EDIT) trips the 350-line gate. The gate has no generated-code exclusion. Either the gate is not actually run in CI, or it is silently red.

Fix Exclude *.pb.go / Code generated files in check-file-size.

Dead goexperiment tags linger in lint config

AGENTS.md states goroutineleakprofile, runtimesecret, simd were removed (they gate zero files), yet all three remain in .golangci.yml → run.build-tags. Dead config that misleads.

storage/turso carries 4 unused dependencies

LSP/gopls reports samber/lo, samber/ro, golang.org/x/exp, golang.org/x/text as unused in storage/turso/go.mod, and kv/v3 mis-marked indirect. A go mod tidy is overdue here.
