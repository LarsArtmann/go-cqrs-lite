What We Actually Write to Disk

WAL logs × projections × auxiliary stores — the empirical schema audit of go-cqrs-lite’s Commands → Events → Queries pipeline. Every claim below cites file:line in the repo. The headline: the strategic path has the weaker data model. The system composition root (ADR-0123, the v5 future) journals events as an untyped JSON string in meta_stream_log.value — no unique event ID, no (stream, version) constraint, payloads base64’d inside JSON — while the legacy storage/sql table it replaces has typed columns, a primary key, and a stream-version uniqueness constraint. The projection layer is better modeled than the WAL layer; the declaration pipeline (Go → columns) carries one critical footgun (name-based typing) and no on-disk schema registry.

Layer B — Projections / read models (metaengine)

  • Generic collections (every engine): meta_map(collection,key,value), meta_set, meta_counter, meta_multimap(..,seq,value), meta_log, meta_graph_edges(from_node,to_node), meta_snapshot, meta_vector. Value = whole-entity JSON (PG: JSONB; MySQL: JSON; DuckDB: VARCHAR; Dgraph: string predicates emulating the relational shape).
  • Planned tables (typed projections): meta_planned_<collection>(key PK, value, <typed cols>) — both the JSON and extracted columns written on every upsert; one index per column; PG remaps to BIGINT/DOUBLE PRECISION, MySQL to BIGINT/DOUBLE with FNV-hashed identifiers ≤64 chars.
  • Type mapping (sqlTypeOf, metaengine/layout.go:306): ints→INTEGER, float32→REAL, float64→DOUBLE, bool→INTEGER, everything else (incl. time.Time, slices, maps)→TEXT. Field → column keeps the declared name; JSON matching falls back to snake_case.
  • Mat views (turso/libSQL only): cqrs_mv_* over json_extract(value,'$.col'), name truncated 48 chars + FNV suffix.
  • Vectors: 4 physical formats (LE-f32 BLOB sqlite/mysql, JSONB array PG — no pgvector, FLOAT[] DuckDB, 'b'|dim|f32 KV) — deliberate ADR-0140 tradeoff, first-insert-wins dimension lock via probe.

Layer C — Auxiliary persisted stores

  • Blind-store envelope (ADR-0044): {"$":"gcdc","enc":"json|cbor","dat":<bytes>} — shared by kv/snapshot/command/query typed stores (one impl in go-codec).
  • Snapshots: SQL snapshots(stream_type,stream_id,version,state) PK(stream) latest-wins, no encoding column (envelope carries it); pebble CBOR twin with UnixNano.
  • Timers: timers(id PK, fire_at, payload, created_at) + claimkit meta_due_claims/meta_claim_facts; payload wrapped in a hand-rolled {"v":1,"actor":...,"payload":...} envelope.
  • Dedup/claims: meta_dedup(collection,key,expires_at), CAS upsert w/ RETURNING.
  • DLQ: projection_dead_letters — 15 typed columns, aggregate_* naming, UNIQUE(projection, event_id).
  • Checkpoints: checkpoints(projection_name PK, event_id, processed_at); zero-checkpoint = row delete.
  • Command lifecycle: domain events on CommandLifecycle/<cmd-id> streams + metaengine collections (command_dlq Map, command_retry_count Counter, Logs, Multimap).

02Problem Catalog

Critical PC-1 · The strategic WAL is schema-less

system journals serializedEvent as one JSON TEXT blob. Consequences: (a) event IDs are not unique at the storage layer — replay/duplicate appends are invisible unless the opt-in DedupStore catches them; (b) no (stream, version) constraint — optimistic-concurrency correctness lives entirely in code; (c) payload []byte and metadata []byte are base64’d inside JSON (~33% bloat, binary CBOR payloads worst-hit); (d) the only structure is a SQLite-only partial json_extract index. The legacy events table proves the better model already exists in-repo. 

meta_stream_log(seq, collection, stream_id, value TEXT)   -- everything else is inside value
Critical PC-2 · Name-based column typing

When a projected field’s Go type is unknown (any), inferColumnType (metaengine/layout.go:169) types the column from the field name: contains price|amount|rate|cost → REAL, priority|count|age|level|score|num → INTEGER. A field named contentType becomes INTEGER. Sort/filter on it then misbehaves silently. Schema by naming horoscope.

High PC-3 · Separator injection in KV keys

Stream IDs are caller-chosen arbitrary strings (string-backed branded IDs). KV keys join them with unescaped separators: {type}:{id}:{version} (pebble/bbolt storage) and \x00 (keycodec). An ID containing : (or NUL) aliases into other streams’ key ranges — range scans return wrong streams.

High PC-4 · aggregate_* vs stream_* column split brain

The July rename (ADR-0058) renamed Go types; the disk kept both vocabularies: events.aggregate_type/aggregate_id (legacy WAL, DLQ table) vs stream_type/stream_id (snapshots, system envelopes, meta tables). Cross-store joins and operator queries speak two dialects of the same concept.

High PC-5 · No on-disk schema registry

Every engine creates tables with CREATE TABLE IF NOT EXISTS; layout plans live in an in-memory map (sqliteengine/planned.go:84). Change a plan (rename a field, add a column) and existing databases silently keep the old shape — no fingerprint comparison, no migration, no failure. The repo even has schema/fingerprint.go for events; projections have nothing.

Medium PC-6 · Three time encodings, one breaks ordering

SQLite WAL/DLQ: TEXT 2006-01-02T15:04:05.000000000Z07:00 — fixed-width fractions but a variable-length offset suffix (Z vs +02:00), so lexicographic ORDER BY occurred_at misorders mixed-offset rows. KV journals: int64 UnixNano (orders correctly). system envelope: RFC3339 JSON (Go default). Same concept, three wire forms, one subtly wrong.

Medium PC-7 · Three envelope systems

ADR-0044 gcdc envelope (kv/snapshot/command/query), serializedEvent JSON (system WAL), and a hand-rolled {"v":1,"actor":...} (timers). Three versioning stories, three magic formats, one of them undocumented as an envelope at all.

Medium PC-8 · Planned tables: JSON + columns double-write, names can drift

Every upsert writes the full entity JSON and extracted columns; the column name comes from the declared filter name, JSON matching falls back to snake_case of the Go field (ParentID→parent_id). Two naming schemes feeding one row means a plan edited across sessions can write columns the JSON no longer matches.

Medium PC-9 · VARCHAR(255) on unbounded caller keys (MySQL)

meta_map.key, meta_stream_log.stream_id, events.aggregate_id are caller-chosen strings, but MySQL variants cap them at 255 chars (engine-specific failure), and MySQL planned identifiers are FNV-hashed to 64 chars — two engines, two different limits, neither enforced at the API boundary.

Medium PC-10 · Metadata unreachable inside the WAL blob

serializedEvent.Metadata is base64 JSON-in-JSON: no engine can index or push down correlation/actor without decoding the whole envelope. PG’s meta_map shows the right pattern (JSONB + (value->'$.field') expression index) — the WAL lacks it everywhere.

Low PC-11 · Two integer encodings in one keycodec

Sequences are 20-digit zero-padded decimal; counters are 8-byte big-endian. Both order correctly; the inconsistency is maintenance tax.

Low PC-12 · Untagged JSON wire fields lock in Go names

Causation{CommandType, CommandID} and TombstoneMark{Status,Reason} have no JSON tags — the persisted shape is Go-field-name-camelCase by accident (event/causality.go:13, tombstone.go:69). Renaming a field rewrites the wire.

Cleared PC-13 · Lifecycle timestamp key drift — verified non-issue

Settled after writing: ReceivedAt time.Time carries the tag json:"receivedAt" (commandlifecycle/events.go:95) — the receivingAt sighting was an audit artifact, not wire drift. Kept as a card because the check itself is the pattern: wire keys are forever, so audit discrepancies get pinned, not assumed.

Accepted PC-14 · Vectors in four physical formats

LE-f32 BLOB / JSONB array / FLOAT[] / length-prefixed binary. This is the ADR-0140 engine-native tradeoff, compensated by the first-insert-wins dimension lock and path reporting. Recorded, not fixed — the lock is the invariant that matters.

03The Vision

  • The journal of record is constraint-backed wherever SQL lives. Event identity and (stream, version) uniqueness enforced by the engine, not by hope.
  • One declared schema per concept, fingerprinted on disk. A layout plan change against an existing database is a loud, versioned event — never a silent no-op.
  • Column types come from Go types, never from names. Unknown → TEXT + warning; heuristics deleted.
  • Keys are injective. Any caller string round-trips through the key codec unambiguously — separator injection is structurally impossible.
  • One envelope, one time discipline. ADR-0044 for all blind stores (timers included); UTC fixed-width (or integer nanos) for every stored instant.
  • Operators can read the WAL with plain SQL. Typed columns + real JSON metadata beat json_extract archaeology on a base64 blob.

04Go Data Model

The typed WAL row (SQL engines)

// StreamLogRecord is the single source of truth for the system WAL's
// physical shape on SQL engines. Engines render it through their dialect;
// the invariant set is engine-independent.
type StreamLogRecord struct {
    Seq           int64  // engine-assigned, monotonic
    Collection    string
    EventID       string // UNIQUE — duplicate append is a storage error
    EventType     string
    StreamType    string // stream_*, not aggregate_* — one vocabulary (PC-4)
    StreamID      string // bare wire value — Get(), never String()
    Version       int64  // UNIQUE (Collection, StreamID, Version)
    SchemaVersion int
    Payload       []byte // raw codec bytes — no base64 (PC-1c)
    Encoding      string // "json" | "cbor"
    Metadata      string // JSON text / JSONB — indexable (PC-10)
    OccurredAt    int64  // UnixNano UTC — orders everywhere (PC-6)
}

Injective key codec (KV engines)

// Escaped key component: separator and escape byte are always paired,
// so no caller string can forge a component boundary (PC-3).
const (
    keySep  = byte(0x00)
    keyEsc  = byte(0x01)
)

func escapeComponent(s string) []byte {
    out := make([]byte, 0, len(s)+4)
    for i := 0; i < len(s); i++ {
        b := s[i]
        if b == keySep || b == keyEsc {
            out = append(out, keyEsc)
        }
        out = append(out, b)
    }
    return out
}

// Fingerprinted plan: the disk remembers what it was built from (PC-5).
type LayoutFingerprintRow struct {
    Collection  string // PK
    Fingerprint string // schema.PlanFingerprint(plan) — hex
    AppliedAt   int64
}

Typing without horoscopes (PC-2)

func sqlTypeOf(t reflect.Type) (string, error) {
    switch t.Kind() {
    case reflect.Int, reflect.Int64, reflect.Uint64:
        return "INTEGER", nil
    case reflect.Float64:
        return "DOUBLE", nil
    default:
        // unknown types are TEXT + an explicit warning — never guessed
        // from the field name (deletes inferColumnType entirely)
        return "TEXT", errUntypedColumn{Field: t.String()}
    }
}

06Validation Layer

  • Storage constraints as tests: conformance suite appends the same event twice → expects a conflict error from every SQL engine (today only legacy storage/sql would pass).
  • Key round-trip law: decode(encode(type, id, v)) == (type, id, v) for ids including ":", "\x00", "a:b:c", empty-ish and 255+ char strings — property-tested (rapid) for all KV engines.
  • Fingerprint gate at boot: LayoutPlanApplier compares the stored LayoutFingerprintRow against the declared plan; mismatch = loud error naming the collection and both fingerprints (precedent: schema/fingerprint.go already does this for event schemas).
  • Raw-bytes pins: persisted WAL bytes asserted to contain bare stream IDs, no base64 payload, UTC-suffix times — the lesson from the StreamMarker leak applied to every new invariant.
  • Dimension-lock precedent: vectors already prove the pattern — first-insert-wins invariant + adttest.AssertVectorDimensionGuard per engine. Copy it for key length limits (PC-9): enforce a validated MaxKeyBytes at the API, not a MySQL runtime error.

07Decision Log

DecisionChosenRejected & why
WAL physical shape (SQL engines) Typed columns (StreamLogRecord) CBOR envelope blob — portable and compact, but forfeits engine constraints, typed indexes and operator SQL; constraints are the reason SQL engines exist in the matrix. The generic-JSON path survives only for memory/dgraph.
Keep value JSON column in planned tables? Keep (belt for unplanned fields) Columns-only — loses fields outside the plan; JSON-only — loses pushdown. Double-write stays, but under one naming rule: column name = JSON key, always.
Key escaping vs length-prefix Byte escaping (sep/esc pairing) Length-prefix — also injective, but variable-length ints complicate range scans and debuggability; escaping keeps keys grep-able.
Time on disk UnixNano int64 (SQL INTEGER / KV) TEXT UTC fixed-width — human-readable in sqlite CLI, but int wins: orders everywhere, fixed width, no offset footgun. Render to text at query time.
Timers envelope ADR-0044 gcdc Keep {"v":1,...} — a third envelope with no detection magic and no codec stamp; pure duplication.
Column vocabulary stream_* everywhere new; legacy tables get read-aliases Keep aggregate_* — the domain language renamed two quarters ago; disk should stop disagreeing with it.

08Anti-Patterns

  • json_extract as a schema. If the engine must parse JSON to find an event’s identity, the table is wrong.
  • Typing by name. inferColumnType’s word lists are schema-by-horoscope; delete, don’t extend.
  • CREATE TABLE IF NOT EXISTS as migration. It is an idempotent no-op, not a schema manager; without fingerprints it guarantees drift.
  • VARCHAR(255) on caller strings. Engine-specific limits on unbounded inputs produce portability bombs; validate at the boundary or store TEXT.
  • Untagged wire structs. Go field names are not a wire contract; every persisted struct gets JSON tags (PC-12).
  • Base64 inside JSON for binary that has a codec stamp. The stamp exists precisely so bytes can ride raw.

09Migration Roadmap

1. Delete inferColumnType; unknown → TEXT + warning (PC-2). Zero migration — heuristics only ever produced wrong types.
2. Additive WAL columns: extend meta_stream_log with typed columns, backfill via json_extract from existing value, then add UNIQUE constraints and keep value as read-legacy (PC-1, PC-10). Per-engine, additive, replayable — journal rows are facts (ADR-0143), so backfill must copy, never rewrite.
3. keycodec: escape components; storage/pebble + storage/bbolt switch to escaped keys with a versioned family prefix; dual-read old ranges during one release (PC-3).
4. LayoutFingerprintRow table + boot comparison in LayoutPlanApplier (PC-5); warn-first v4.x, hard error at v5 (mirrors the reset-capability rollout).
5. Timers payload → ADR-0044 envelope (PC-7); one migration decode-old-wrap-new.
6. Time columns: new writes UnixNano; SQLite TEXT column gets a generated UTC-normalized shadow during transition (PC-6).
7. Conformance additions: duplicate-append conflict, key round-trip law, fingerprint-mismatch boot failure, raw-bytes pins — all engines, adttest pattern.
8. v5 cut: aggregate_* → stream_* aliases dropped where safe; PC-13 grep-and-pin; base64 payload paths deleted.

10Conclusion

“The projection layer grew constraints and the journal of record grew a string. Disk is the contract your future self debugs at 3am — give it types, keys, and fingerprints.”
