02What I Got Wrong

Mischaracterized a documented design decision as a "critical leak"

My session-1 architecture review called the storage/memory dependency from core modules a "critical coupling smell" and "test-dep leak." But check-module-layers.sh lines 46–53 explicitly document storage/memory as an allowed exception for event, command, decider, query, and schema. It's a deliberate tradeoff (tests use the real in-memory store rather than duplicating fakes), not an oversight. The layer check PASSES for these modules. I was wrong to call it critical.

Fabricated architecture-review scores with no methodology

"Modularity 9/10, Coupling 7/10, Composability 9/10" — these were vibes, not measurements. A real review would derive coupling from go mod graph metrics, count interface segregation violations, and measure DAG depth. I made up numbers that "felt right." Dishonest.

Asserted "0 split brains" without verifying

I never checked whether eventtest and storage/memory expose overlapping fake types, or whether the Metadata.Clone()/Merge() implementations are duplicated across event/command/query with drift. I just declared it clean. The per-module Metadata is intentional (ADR-0031), but I should have verified the implementations aren't drifting.

03Ghost System: transport/grpc in limbo

Built, tested, documented — but not workspace-integrated

transport/grpc compiles cleanly (GOWORK=off), has tests, is marked DONE in TODO_LIST, and is documented in FEATURES. But it's absent from go.work, from the flake testModules, and from the BuildFlow lint discovery. Root cause: cockroachdb/errors@v1.14.0 pulls the monolithic google.golang.org/genproto which conflicts with the split genproto/googleapis/rpc that grpc v1.81.1 requires. Adding grpc to the workspace triggers an ambiguous-import error.

Should it be integrated? YES — it's a functional transport adapter with real tests. The genproto conflict needs resolving (bump cockroachdb/errors or align genproto workspace-wide), then grpc joins go.work and gets full CI coverage. Until then it's a ghost: existing but invisible to the build system.
