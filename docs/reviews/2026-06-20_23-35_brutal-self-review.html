1. What Did You Forget?

SSE multi-line payload bug (spec violation)

The original SSE handler used fmt.Fprintf(w, "data: %s\n\n", payload) which corrupts the SSE stream when payloads contain newlines. JSON pretty-printed payloads or multi-line event data would silently break the browser's event parsing. This was the most serious bug — a real correctness issue, not just a missing feature.

Status: FIXED — Rewrote with WriteSSEEvent + SSEEvent struct, spec-correct multi-line handling.

SSE missing heartbeat

Without heartbeat, SSE connections are killed by ALB/Nginx/Cloudflare after ~30-60s idle. The handler loop blocked on <-ch with no keepalive — production connections would silently die.

Status: FIXED — Added 15s heartbeat ticker writing : heartbeat\n\n comment frames.

2. What Is Something Stupid?

fmt.Fprintf for SSE wire format

Using fmt.Fprintf on every SSE event is stupid because: (a) it uses reflection (slow on hot paths), (b) it can't handle multi-line data correctly, (c) the wire format is untestable when inlined in the handler.

Status: FIXED — Replaced with bytes.Buffer construction in WriteSSEEvent.

SSEBroker is a non-generic reimplementation of fanOut[T]

cqrs-htmx has a battle-tested fanOut[T] generic pattern (keyed by channel pointer for O(1) unsubscribe, shared by SSE + WebSocket). Our SSEBroker is a non-generic copy of that pattern. Adopting the generic would fix the client ID race (two tabs with same ?client= param silently overwrite each other) and enable future WebSocket support.

Status: Not yet done — deferred. Requires careful API design. Worth doing when a second transport (WebSocket) is needed.

Architectural Reflection

Type Model Improvements Made

The SSE type model was improved from inline fmt.Fprintf to:

type SSEEventID string  // Branded, validates no \n/\r
type SSEEvent struct {
    Type  string
    ID    SSEEventID
    Data  string     // Multi-line handled per spec
    Retry int        // Reconnection hint in ms
}
func WriteSSEEvent(w io.Writer, evt SSEEvent) error
func WriteSSEHeartbeat(w io.Writer) error

This separates the data model (SSEEvent) from the serialization (WriteSSEEvent) from the transport (SSEHandler). Each is independently testable. The pattern mirrors cqrs-htmx's SSEEvent + WriteSSEEvent design.

Library Awareness: cqrs-htmx fanOut[T]

The fanOut[T] generic in cqrs-htmx (fanout.go) is a transport-agnostic subscriber hub: map[uintptr]chan T keyed by channel pointer. It's shared by SSE and WebSocket broadcasters. Adopting it in go-cqrs-lite would eliminate the SSEClientID string-keyed map race and make transport/ws/ trivial to add. This is the single highest-value architectural improvement for the transport layer.
