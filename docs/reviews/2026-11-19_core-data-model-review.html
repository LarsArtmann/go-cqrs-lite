00Summary

The core data model is in better shape than most organically grown systems — a prior review already paid down the worst rot (the Stamp, Cause, and Actor types carry its fingerprints). But the model now lives in two places at once: the v4 train and the core/v5 copy-forward. The copy-forward was supposed to be the clean cut; instead it carried every deprecated dual-field across, including the six CommonMetadata pairs whose comments say “removed in v5” — inside the v5 module itself.

Twelve findings reduce to three systemic root causes. First, zero-dependency was read as zero-types: the record/ module cannot import id/, so Record.ID, Record.Type, and Record.StreamType collapsed to raw strings — even though the module defines record.Type and record.StreamRef and could use them. Second, the dual-train transition optimizes for compile-compat today and bills model clarity forever: every metadata fact exists twice until a cut that has not been executed where it matters. Third, boundary-conversion discipline is uneven: actors and encodings cross layers through named, single-purpose functions, while versions and identities cross through scattered int64()/uint64() casts guarded by #nosec comments.

The bottom line The v5 target is ~70% designed and the designed part is the best code in the review. What remains: execute the deprecation cut inside core/v5 while it still has zero fleet consumers, and make the five decisions no deprecation trail currently covers — the unbranded Record fields, the version sign split, the encoding tri-conflation, the duplicate stream-identity fields, and the fabricated query stream.

◆What's already excellent

Honesty first: the hard problems were mostly solved once already. The v5-direction types are textbook, and this review's job is to finish their adoption, not to redesign them.

+
record.Stamp — presence-explicit timestamps A zero time.Time can no longer masquerade as “recorded at epoch”. Unexported fields make inconsistent states unconstructible; the JSON round-trip preserves known-ness losslessly (record/v4/stamp.go:17).
+
record.Cause and record.Actor — discriminated unions done right Zero value = none; CauseUnknown and ActorUnknown are honest states, not errors; the kind is structural, no “kind:raw” parse tax (record/v4/cause.go:58, actor.go:60).
+
id/ phantom branding with a documented backing decision ULID-backing for system-minted IDs, string-backing for caller-chosen semantic keys (StreamID) — the rationale lives in the type doc, and it is correct (id/v4/stream_id.go:21).
+
metadata.Metadata[K] — one generic, module-local key brands command.MetadataKey can never collide with query.MetadataKey, and neither gains event-only fields. Clone, Merge, WithCustom inherited from one implementation (metadata/v4/metadata.go:72).
+
Capability interfaces instead of interface growth MetadataCarrier / PayloadCarrier let middleware opt in via type assertion instead of breaking every hand-rolled Command (command/v4/capability.go:12) — the right way to defer breaking growth to a major cut.
+
Defensive clones at every public accessor Payload() clones, Metadata() deep-copies, EventTypes() clones — with zero-copy internal paths (PayloadReadOnly) so honesty does not cost throughput.

01Problem catalog

Twelve findings, ordered by impact. Each names the exact shape in the source, why it matters, and the fix. Two are critical not because the code is wrong today, but because the window to fix them cheaply is open now and closing.

Critical · Systemic

R1 — The v5 train inherited its own death sentence

core/v5/record/record.go:30-108 · diff vs record/v4/record.go is lint directives only

The ADR-0152 copy-forward duplicated the v4 modules into core/v5 verbatim. That includes every field whose comment says “Deprecated: removed in v5” — CausationID, ActorID, ClientCreatedAt, ServerReceivedAt, ServerStoredAt, plus the tombstone channel and the per-module ParseType re-exports. Sixty deprecation markers live inside the module that was created to end them. Every day the cut is deferred, new v5 code binds to the deprecated shapes. 

// core/v5/record/record.go — inside the v5 module, today:
type CommonMetadata struct {
    // Deprecated: removed in v5. Use Cause ...
    CausationID string   // ... still here, in v5
    Cause       Cause
    // Deprecated: removed in v5. Use Actor ...
    ActorID     string   // ... still here, in v5
    Actor       Actor
    // + four more deprecated/new pairs
}
Fix (as written): execute the cut inside core/v5, now The fleet census shows zero production consumers of core/v5 modules — deleting the deprecated halves there breaks no one and gets cheaper never again. Start with record/ (the root of the type tree), then event/metadata/command/query. The v4 train stays frozen as-is until fleet migration.
Amended 2026-11-19 (errata #1 — see the follow-up plan) The cut is T26-gated: the v007 v5-twin table (v007_tables_symbols_v5.go) records these deprecated twins as “removed together with the v4 train in T26”, so the cqrs-upgrade --to-v5 import rewrite stays mechanical — deleting the twins now would strand migrating consumers. The finding’s urgency transfers to the new surface: the free window (zero consumers, pre-first-tag) is spent finalizing the NEW core/v5 types. Plan of record: docs/planning/2026-11-19_20-52_SUPERB-v5-core-type-finalization-pareto-plan.md.
Critical · Type safety

R2 — The meeting point de-brands everything

Cross-ref: the 2026-10-17 on-disk schema review’s PC-1 (typed WAL) rides exactly this work — the typed Record IS the WAL cell the storage layer wants. (Fixed 2026-11-20: M03 brands + M05 Payload.)

record/v4/record.go:125-148 · Record.ID, Record.Type, Record.StreamType

Record is where events, commands, and queries become one shape for the metaengine — the exact layer where cross-family confusion is most dangerous. And it is precisely there that the type system gives up: ID string, Type string, StreamType string. The module's zero-dependency constraint (ADR-0111) forbids importing id/ — but zero-dep was misread as zero-types. The module already defines record.Type, record.StreamRef, and record.Encoding; Record.Type simply fails to use the type sitting in the same file. 

type Record struct {
    ID         string     // was id.EventID / CommandID / RequestID
    Type       string     // record.Type exists 20 lines up. Unused.
    StreamType string     // id.StreamType exists. Unusable here.
    // ...
}
Fix: in-module brands Type Type is a one-line fix. Add type InstanceID string and type StreamType string brands inside record/ — zero-dep intact, compile-time distinction restored. ULID-ness stays a minting concern in id/; Record only promises “an identifier”, which a brand expresses honestly.
High · Systemic

R3 — The version sign split

event/v4/types.go:100 vs record/v4/record.go:152 · every AsRecord bridge

Stream position is 1-indexed and cannot be negative — the domain says uint64 (event.Version). Record says int64. Every bridge pays the toll: int64(evt.Version()) guarded by #nosec G115, and CheckVersionConflict(existingLen int, ...) accepts a third numeric vocabulary. Actors already cross the SQL boundary through named functions (PrefixedString/ParseActorID); versions deserve the same discipline. 

Version: int64(evt.Version()), // #nosec G115 -- hope
Fix: record.Version uint64 + one SQL boundary Define the brand in record/ (zero = unversioned, the honest state for queries and commands). event.Version becomes an alias. SQL engines convert through one named function per driver — the ActorID precedent, applied to numbers.
High · Representability

R4 — One encoding zero value means three different things

record/v4/encoding.go:14-27 · event/v4/asrecord.go:118-125

EncodingUnknown conflates absent payload, opaque payload, and envelope-wrapped payload (ADR-0044). A consumer cannot distinguish “nothing to decode” from “bytes present, look inside the envelope”. Layered on top: two enums for one concept — codec.Encoding (string-backed, at the event layer) and record.Encoding (uint8) — bridged by parsing the name string on every event conversion.

Fix: make the three states three values Add EncodingEnvelope, and pair the bytes with their stamp: Payload struct { Data []byte; Enc Encoding }. Absent ⇔ zero Payload; opaque ⇔ Data + Unknown; wrapped ⇔ Data + Envelope. The dual enum survives (different layers, different budgets), but the bridge gets one home and a direction.
High · Dual truth

R5 — Stream identity lives in two fields that can disagree

Cross-ref: the 2026-10-17 on-disk schema review’s PC-3 (key law) governs the SAME identity at the storage layer — one canonical key form per stream; ADR-0166’s StreamKey() collapse is the in-memory half of that law. (Fixed 2026-11-20: M04.)

record/v4/record.go:143-148 · StreamID + StreamType

StreamID StreamRef already embeds the stream type (“User/01J...”); StreamType string restates it. Nothing enforces agreement — a Record with StreamID “User/1” and StreamType “Order” compiles, validates, and persists. The pair is redundant for events, single-sourced for commands (empty ref-type), and fabricated for queries — one shape carrying three different meanings. The field name lies too: StreamID holds a Ref.

Fix: one home Rename to Stream StreamRef, delete the StreamType field, derive the type through an accessor backed by Split(). The validating v5 constructor (NewStreamRef returning an error, already planned at record/v4/record.go:167) closes the malformed ref gap. Commands keep the legal empty-type ref.
High · Split brain

R6 — Causation has three homes and four fields

metadata/v4/ids.go Tracing.CausationID · event/v4/causality.go:18 · record/v4 CommonMetadata.{Cause, CausationID}

What caused a record is stored as: an untyped ULID (Tracing.CausationID), a pointer with a stringly type (Metadata.Causation *Causation, where CommandType is a raw string), and the structural union plus its deprecated twin at the record layer. Precedence rules (“typed beats tracing beats none”) live in prose comments and are re-implemented per bridge. WithCommandCausality already carries typed data through context — it just never becomes a first-class field.

Fix: one home, typed at birth Promote cause record.Cause to a first-class ImmutableEvent field stamped at construction. Causation.CommandType becomes record.Type (same module, no layering violation). Tracing.CausationID and the metadata pointer ride the R1 deletion.
Medium · Parse tax

R7 — Actors pay the parse tax at the minting layer

id/v4/actor_id.go · metadata/v4/ids.go:21-27

id.ActorID serializes as “kind:raw” (“user:01ARZ...”); recovering the kind means prefix parsing. record.Actor fixed this structurally — but Tracing, where actors are born from HTTP contexts, still carries the stringly form, and every Record consumer re-derives the union (metadata.RecordActor) or pays the tax. The UserID→ActorID fallback precedence is implicit domain knowledge encoded in one helper.

Fix: structural at birth, stringly at the wire Tracing carries the structural Actor; “kind:raw” survives only at serialization edges (SQL columns, headers) through the existing PrefixedString/ParseActorID pair. The fallback precedence stays in the one helper, documented as the rule.
Medium · Semantics

R8 — A server clock is relabeled a client clock

event/v4/asrecord.go:105-106 · types.go:22

ImmutableEvent.occurredAt defaults to a server clock (defaultClock, UTC). AsRecord maps it into ClientCreatedAt and Created — fields documented as “the client's clock, which may lie” — while Received, the honest home for a server intake time, stays zero. Downstream audit tooling reading “clientCreatedAt” for a server-minted event is being told a lie about which clock ran.

Fix: stamp what actually happened Created is populated only when a client clock exists (offline first). Server-minted events stamp Received at intake; the store keeps stamping Stored. One clock, one field, no relabeling.
Medium · Honesty

R9 — The query bridge fabricates a stream

query/v4/asrecord.go:88 · NewStreamRefOrZero("", id)

Queries are not members of any stream, but Record's shape assumes stream membership — so the bridge mints a pseudo-ref “/01JX...” from the RequestID. It looks real downstream: a metaengine fold cannot tell a query's fake stream from a command's real one. Fabricated identity is worse than absent identity because it is indistinguishable from truth.

Fix: zero means not-a-member Queries leave Stream zero. Consumers branch on IsZero() — which reads as exactly what is true: this record belongs to no stream.
Medium · Two empties

R10 — Event has two empty states

event/v4/event.go:52 · Event = *ImmutableEvent

A nil Event and a zero &ImmutableEvent{} are both representable, and they behave differently: AsRecord(nil) returns a zero Record, AsRecord(zero-struct) returns one full of empty strings that look populated. The concrete-alias decision (perf, no interface assertions) is right and stays — but the two-empties asymmetry is a trap for reconstruct paths.

Fix: uniform rejection at the boundary Reconstruct/AsRecord treat a zero struct exactly like nil (validate ID/type before mapping). Document the invariant: “events exist only via constructors”.
Low · API surface

R11 — Version's method sprawl feeds the cast noise

event/v4/types.go:98-182

Int() int, UInt64() uint64, Mod(n int) int, Add(uint), Sub(int) — five arithmetic helpers speaking three numeric vocabularies. Every convenience method that returns a different numeric type licenses another scattered conversion, which is exactly the R3 noise.

Fix: shrink at v5 Keep Cmp, String, Increment, Decrement, IsZero, UInt64. Delete the numeric-converters; callers go through the record.Version brand or the SQL boundary.
Low · Deprecated residue

R12 — Pointer-as-state remnants in event.Metadata

event/v4/metadata.go:15-16 · Tombstone, Causation

Nil-pointer presence encoding — the pattern Stamp was invented to replace — survives in two metadata fields, both already sentenced (ADR-0114 tombstones → domain events; Causation → R6). Every Metadata.Clone still copies both pointers.

Fix: ride the R1 cut No new work — just do not let either survive it, and never add a pointer-presence field again (see anti-patterns).

02The vision

What does perfection look like for this model? Not more types — fewer truths per fact.

+
One fact, one field No dual-train pairs, no StreamRef+StreamType, no three causation homes. Every fact has exactly one home; everything else derives.
+
Zero-dep with zero-types rejected record/ brands its own vocabulary (Type, InstanceID, StreamType, Version, Encoding) — dependency-free is not stringly.
+
Presence is explicit everywhere Stamp for times, Cause/Actor zero-kinds for unions, zero Payload for absence, zero Stream for non-membership. No pointer-as-state, no epoch-as-absence.
+
Boundaries convert through named doors ULID↔string, uint64↔int64, kind↔prefix: every layer crossing has one function pair, the ActorID precedent everywhere.
+
Constructors are the only doors in Validating constructors (NewStreamRef, ParseType, ParseVersion) make malformed values a compile-or-construct-time event, never a persisted fact.
+
Deprecated means deleted on schedule A field marked “removed in v5” does not exist in the v5 module. New majors inherit the payoff, not the debt.

03The target model

The post-cut record package. Every change extends the already recorded v5 direction (ADR-0111, ADR-0123, ADR-0152) — nothing here reverses a decision, it finishes them and names the five that had no trail. 

package record

// --- The in-module brand vocabulary (zero-dep, zero-stringly) ---

type InstanceID string    // the record's own identity (event/command/request ID)
type Type string         // exists today — finally used by Record
type StreamType string    // in-module twin; ULID-ness stays id/'s concern
type Version uint64       // 1-indexed position; zero = unversioned (queries, commands)
type CorrelationID string // chain identity; minted as ULID in id/, carried as a brand here

// --- Payload: three states, three representations ---

type Encoding uint8 // Unknown | JSON | CBOR | Envelope

type Payload struct {
    Data []byte
    Enc  Encoding   // absent ⇔ zero struct; opaque ⇔ Unknown; wrapped ⇔ Envelope
}

// --- Stream: one home for identity ---

type StreamRef string        // "Type/EntityID"; zero = not a stream member

func NewStreamRef(t StreamType, id InstanceID) (StreamRef, error) // validating (already planned)

// --- The Record: 6 fields, each a single truth ---

type Record struct {
    ID       InstanceID
    Type     Type
    Payload  Payload
    Stream   StreamRef      // renamed from StreamID (it is a Ref); StreamType field deleted
    Version  Version        // zero = unversioned
    MetaData CommonMetadata
}

func (r Record) StreamType() StreamType // derived: Stream.Split()

// --- CommonMetadata post-cut: 7 fields, one truth each ---

type CommonMetadata struct {
    CorrelationID CorrelationID
    Cause         Cause          // {none | command | timer | event | unknown, ID}
    Actor         Actor          // {unknown | user | bot | system | service, Raw}
    Created       Stamp          // client clock; zero = not recorded
    Received      Stamp          // server intake; zero = not yet
    Stored        Stamp          // DB ack; zero = not yet
    SchemaVersion int
}

On the event side, causation is promoted to a first-class field — typed where it is born instead of boxed in metadata: 

type ImmutableEvent struct {
    id        id.EventID
    eventType record.Type
    stream    id.StreamRef      // type + ID travel together, always
    version   record.Version
    cause     record.Cause       // stamped by WithCommandCausality at construction
    // ... payload, encoding, stamps, metadata (Custom only)
}
This is the target Six Record fields instead of eight, seven metadata fields instead of thirteen, one causation home instead of three, and every field either branded, presence-explicit, or honestly zero.

05Validation layer

Invalid states become unrepresentable at three gates — construct, cross, consume — each already proven somewhere in this codebase; the target applies them uniformly.

Construct: validating constructors

NewStreamRef(type, id) errors on empty ID (planned at v5). ParseType rejects empty. ParseVersion/ParseSchemaVersion enforce ≥ 1. Malformed values never become values.

Represent: zero-value honesty

Version 0 = unversioned. Zero StreamRef = not a member. Zero Payload = absent. EncodingEnvelope = wrapped. Cause/Actor/Stamp zero = not recorded. Every absence is a value, never a sentinel lie.

Cross: named boundary doors

ULID→InstanceID at the bridges; record.Version→int64 in one sqlVersion() per driver; Actor↔“kind:raw” through PrefixedString/ParseActorID. A scattered cast is a code smell the linter can see (the #nosec G115 pattern is its signature).

Consume: fold-time assertions

metaengine folds branch on IsZero() — a query with no Stream reads as non-member, not as a fake stream. Type-switch defaults on Cause/Actor kinds are build-breaker bugs, not fallbacks.

06Decision log

Every design choice with its rejected alternative and the reason it lost.

Decision Chosen Rejected — why it lost
D1 — Record.Type Type Type (in-module brand) Raw string status quo — the brand exists in the same file; not using it is inertia, not design.
D2 — record identity type InstanceID string Struct wrapper with validation — ULID-ness is a minting concern (id/); Record promises only “an identifier”, which a brand states honestly. Alias keeps wire/SQL compat.
D3 — Version record.Version uint64; event aliases it int64 for SQL convenience — domain owns the truth, boundaries convert (ActorID precedent). Bare uint64 without brand — three numeric vocabularies already caused R3.
D4 — payload presence Payload{Data, Enc} + EncodingEnvelope Keep Encoding field with tri-conflated zero — three meanings in one value is exactly the ambiguity being removed.
D5 — stream identity Stream StreamRef; StreamType() derived Keep both + Validate() — a runtime check licenses the drift it detects; one home makes drift unrepresentable.
D6 — causation home Cause field on ImmutableEvent Metadata.Causation pointer — pointer presence + stringly CommandType + per-bridge precedence ladders.
D7 — query streams zero StreamRef = not a member Fabricated “/RequestID” ref — fake identity is indistinguishable from real identity downstream.
D8 — correlation record.CorrelationID brand Raw string — same reasoning as D2; chains deserve compile-time identity too.
D9 — Event alias Keep Event = *ImmutableEvent Interface — the recorded perf decision stands; two-empties handled at boundaries (R10) instead.
D10 — Tracing.UserID Keep alongside Actor Remove — UserID is the human principal, Actor the attribution; different questions, both legitimate.

07Anti-patterns

Traps to avoid while adopting the target model.

Pointer-as-presence

*TombstoneMark and *Causation are the museum pieces. Presence is a value: Stamp, zero-kind unions, zero Payload. Never again a nil-pointer state machine.

Copy-forwarding debt into a new major

The core/v5 copy made every “removed in v5” field immortal. New majors inherit the payoff of prior deprecations, or the deprecation was a lie.

Scattered numeric casts

int64(x) + #nosec G115 is the signature of a missing boundary door. One named conversion per crossing, per layer.

Zero-dep as zero-types

“Cannot import id/” constrains dependencies, not type safety. A package with 12 types can define brands; record/ already had three.

One fact, two fields

StreamRef + StreamType; CausationID + Cause. Every duplicate becomes a consistency check someone forgets to write.

Fabricated identity

Stuffing a RequestID into a StreamRef makes absence look like presence. Zero values are honest; fake ones are corrosive.

08Migration roadmap

Ordered for the free window: core/v5 has zero fleet consumers today (fleet census, ADR-0152), so steps 1-5 break no one. The v4 train is frozen throughout.

1

Execute the deprecation cut inside core/v5

Delete the six deprecated CommonMetadata pairs, tombstone marks, EnsureCustom, and per-module ParseType re-exports from core/v5/*, starting with record/. Verify with the api-stability golden regenerated per module. This is R1; everything else lands on top of it.

2

Brand the Record fields

In core/v5/record: Type Type, plus InstanceID, StreamType, Version, CorrelationID brands (R2, R3). event.Version becomes an alias. Compile errors are the migration map — follow them.

3

Payload struct + EncodingEnvelope

Pair bytes with their stamp; make absent/opaque/wrapped three values (R4). The codec.Encoding bridge gets one home and a direction (event→record only).

4

Single-home stream identity

Rename StreamID→Stream, delete the StreamType field, add the derived accessor, switch on the validating constructor (R5). Update metaengine folds and listing to read Split() instead of the field.

5

Promote Cause; fix the stamps

First-class cause field on ImmutableEvent; Causation.CommandType becomes record.Type (R6). AsRecord stamps Received instead of relabeling occurredAt as a client clock (R8). Query bridges leave Stream zero (R9); Reconstruct validates zero structs like nil (R10).

6

SQL boundary doors

One named Version conversion per driver replaces the scattered casts and their #nosec guards (R3). Grep the guards to prove the sweep is complete — the annotation is the checklist.

7

Fleet migration at the cut

cqrs-upgrade codemod targets cqrs-htmx + go-appkit first (73%+18% of indirect edges, ADR-0152), then direct-import residue. The v4 train tags fixes until the fleet drains; then the twin modules merge into one.
