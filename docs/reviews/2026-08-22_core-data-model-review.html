Core Data Model Review — go-cqrs-lite

A first-principles review of the shared type system that every consumer builds on: identity, records, events, commands, queries, metadata, snapshots, and timers. Twelve modules read line by line, every claim verified against source. The verdict: excellent primitive-level craft undermined by two generational split brains that v5 must close.

02Strengths

Honest reviews start with what already works — and this model has genuinely excellent primitives. Several types are textbook.

+
id.ActorID — a model branded type Unexported fields, kind-discriminated constructors (NewUserActor, NewSystemActor…), parse round-trip, self-describing wire format. Exactly the struct-wrapper pattern the rest of the model should follow.
+
event.Version — underflow-aware arithmetic uint64 base, Add(uint) cannot go negative, Sub(int) returns ErrVersionUnderflow. Strong type doing real work.
+
metadata.Metadata[K] — phantom key generics Command keys and query keys cannot collide at compile time; each module keeps its own key vocabulary while sharing one implementation.
+
ImmutableEvent — enforced immutability Unexported fields, defensive clones on every public accessor (Payload(), Metadata()), zero-copy internal reads for hot paths. Discipline, not luck.
+
query.Pagination & listing.Page[T] uint fields make negative pages unrepresentable; cursor-based Page[T] with HasMore honestly avoids stale TotalCount on append-only logs.
+
Capability-segregated stores Sink/Source/Journal/SeekableJournal/StreamingJournal split means stores implement only what they can honestly provide — the middleware discovers capabilities via type assertion (ADR-0126), never via dropped interfaces.

Critical · P1

Three stream-identity representations coexist

id/stream_type.go:36-58 · record/record.go:16-138 · event/event.go:63-64 · command/aggregate_ref.go:16

The same concept — which stream does this belong to — has three shapes: id.StreamRef (struct {Type, ID}, ":" separator), record.StreamRef (string "Type/EntityID", "/" separator), and unbundled (streamID, streamType) parameter pairs (event.New, Decider.Execute, BasicCommand carries only the ID). Same name, two types, two separators. Every AsRecord adapter re-marshals between them; every consumer must learn which convention each API speaks.

Fix One shape wins: id.StreamRef at runtime, record.Stream (two struct fields, not a composite string) in the zero-dep base. Kill the stringly ref and the unbundled pairs at v5.
Critical · P2

Three parallel metadata hierarchies

metadata/metadata.go:72-76 · event/metadata.go:10-18 · record/record.go:26-59

ADR-0111 introduced CommonMetadata to "replace the parallel metadata hierarchies" — instead a third one was added. metadata.Metadata[K] (generic, branded IDs), event.Metadata (own struct: Tracing + Source + IPAddress + UserAgent + *TombstoneMark + *Causation + Custom), and record.CommonMetadata (plain strings). Conversion helpers (BrandedString, ActorString) with documented precedence rules compensate at runtime for what the types cannot express. Runtime precedence rules are the smell: two fields claiming one concept.

Fix One canonical shape per layer, mapped mechanically: branded at the runtime layer, structural mirrors in record/. No precedence rules — one home per concept.
High · P3

record.CommonMetadata is stringly-typed

record/record.go:26-59 · scheduling/store.go:46

CorrelationID string, CausationID string, ActorID string — while metadata.Tracing brands the same concepts. The zero-dependency constraint on record/ forced the downgrade, and ActorString then smuggles the discriminated actor union through a "kind:raw" string. Every consumer pays a parse tax to recover type information the sender already had. scheduling.Timer.Actor repeats the same escape.

Fix Zero-dep does not mean stringly: structural branded mirrors (record.Actor{Kind, Raw}) keep the dep count at zero while making the union explicit at the type level.
High · P4

Optional state as pointers & zero values; two causation homes

event/metadata.go:15-16 · event/causality.go:13 · metadata/metadata.go:17-18

Tombstone *TombstoneMark and Causation *Causation encode "maybe present" as nil. Worse, causation lives in two places: Tracing.CausationID and Metadata.Causation.CommandID — event.AsRecord arbitrates between them with a documented 3-step precedence rule. Presence-as-nil plus duplicate homes means every reader must know the arbitration.

Fix One Cause{Kind, ID} value (zero kind = no cause); deletion semantics become domain events (ADR-0114), retiring the tombstone pointers entirely at v5.
High · P5

Record drops identity & encoding; Version sign mismatch

record/record.go:65-89 · event/asrecord.go:46-75

record.Record has no ID field — AsRecord silently discards EventID/CommandID. It has no encoding field either, so the library's flagship self-describing-payload property (evt.Encoding()) is lost crossing the bridge. Record.Version int64 vs event.Version uint64 makes negative positions representable in the base type. And the stream type is stored twice: embedded inside the StreamRef string and in the StreamType field.

Fix Record gains ID and Encoding, uses uint64 for version, and holds one Stream{Type, EntityID} struct.
High · P6

Under-powered interfaces force duck-typed workarounds

command/command.go:34-38 · query/query.go:30-32 · query/audit.go:86,114

command.Command exposes Type/StreamID/ID — but both implementations also have Metadata(), which the interface omits. Code holding a Command cannot read metadata without a type assertion; query/audit.go already declares two inline type metadatable interface{...} duck types to compensate. Decider.Execute(ctx, streamID, streamType, decide) takes the identity pair while Store.Save takes a ref — two conventions for one concept, in the same call chain.

Fix Grow Command/Query with the Metadata() accessor both implementations already carry; Execute takes id.StreamRef.
Medium · P7

Timestamps encode "unknown" as zero time.Time

record/record.go:44-53

ClientCreatedAt, ServerReceivedAt, ServerStoredAt — three mostly-zero timestamps where zero means "unknown/not yet". Zero-value discipline is documented but unenforced: a reader cannot distinguish "no server stamp" from "stamped at epoch", and AsRecord leaves two of the three zero by design.

Fix Stamp{at, known} value type with NewStamp(t) — presence is explicit, nil-safe, and JSON-friendly.
Medium · P8

Aggregate-era vocabulary survives in aliases & wire formats

36 deprecated aliases across id/, command/, event/, query/, listing/, snapshot/ · snapshot/store.go:12-13

The Aggregate→Stream rename left 36 deprecated aliases (AggregateID, AggregateRef, AggregateListing…), JSON wire tags that still say "aggregateId"/"aggregateType" on snapshot.Snapshot, and error codes like "command.nil_aggregate_id". The rename is half-done: names migrated, wire and codes did not.

Watch out Wire tags and error codes are consumer-visible contracts — they need a migration plan, not a search-and-replace.
Medium · P9

TombstoneMark reuses a 3-state enum where 2 are legal

event/tombstone.go:15-25, 69-75

TombstoneMark.Status is a TombstoneStatus — which can also be Undetermined. Inside a mark, only Tombstoned and Active (rebirth) are meaningful: an illegal state is representable. The whole path is deprecated (ADR-0114), which makes this a fix-by-deletion.

Fix Domain events (user.deleted) at v5; if the mark survives one more minor, give it its own 2-value enum.
Medium · P10

snapshot.Snapshot: bare public struct, lying JSON tags

snapshot/store.go:11-17

Public mutable fields, no constructor, no invariant enforcement (State may be nil, Version may be 0) — inconsistent with ImmutableEvent's discipline one tier up. JSON tags name fields the struct no longer has ("aggregateId" for StreamID). Snapshot payloads are also not self-describing: no codec stamp, unlike events.

Fix Constructor + id.StreamRef + encoding stamp + honest tags at v5 (with an on-disk migration for the rename).
Low · P11

TimerID unbranded; Timer.Actor is a wire-format string

scheduling/store.go:10, 46

type TimerID = string in a module whose sibling IDs are all branded; Timer.Actor string carries the "kind:raw" wire format as its in-memory type, documented as a zero-dep choice. But scheduling/ is Tier 1 — depending on Tier 0 id/ is legal by the project's own layering rules.

Fix id.Of[TimerMarker] and id.ActorID; pay the one dependency the layer rules already permit.
Low · P12

Type / ParseType / IsZero triplicated across three modules

event/event.go:14-29 · command/command.go:10-25 · query/query.go:11-26

Three byte-for-byte-parallel Type string definitions. Module isolation is deliberate — but all three modules already depend on record/, so a shared record.Type (aliased per module) costs zero new dependencies and removes the triplication.

Fix Define once in record/, alias in each module: type Type = record.Type.

04Reflection — Root Causes

Twelve findings, but they are not twelve independent problems. Everything above reduces to four systemic causes.

1 · A migration caught mid-stride

ADR-0111 (Record) and ADR-0114/0123 (v5) began a generational shift, but v4 must keep the old world compiling. Result: two generations of every core concept coexist, with adapters — not types — holding them together. Causes P1, P2, P8.

2 · Zero-dep interpreted as stringly

record/ and scheduling/ refuse to import id/, so branded types downgrade to strings and parallel identity shapes get invented. Zero deps is a fine goal; throwing away type structure to reach it is not. Causes P3, P11, half of P1.

3 · Presence encoded implicitly

Nil pointers (*TombstoneMark), zero time.Time, zero CausationID — "not yet" and "absent" and "unknown" all collapse into zero values, then runtime precedence rules decide what the zero meant. Causes P4, P7, P9.

4 · Contracts under-specified

Interfaces and base structs that omit what every implementation actually has (Metadata()), drop what every sender provided (ID, Encoding), or accept what no caller should send (negative int64 versions). Causes P5, P6, P10, P12.

Core entities

Strip the noise and five concepts remain — everything else is machinery around them:

Record → Stream identity → Metadata context → Decider fold → Store capabilities

Invariants the model must always enforce

  • I1 — Stream integrity: every record belongs to exactly one stream; a stream is (Type, EntityID), both non-empty for events.
  • I2 — Version monotonicity: versions are 1..N contiguous per stream; never negative, never zero for persisted records.
  • I3 — Immutability: events are frozen at construction; every accessor defensively copies.
  • I4 — Correlation propagation: the correlation ID rides every causal hop: action → command → events → derived commands.
  • I5 — Actor attribution: every record knows who or what produced it, kind-discriminated.
  • I6 — Self-describing payloads: the codec stamp survives every hop, including persistence and Record conversion.

05The Vision

What perfection looks like for this model — the bar the v5 cut should be measured against:

  1. One stream shape. Asking for a stream's type is a field access, never a parse; there is exactly one StreamRef in the runtime and one Stream in the base layer.
  2. One metadata hierarchy. Causation has one home. Actor has one home. No precedence rules anywhere.
  3. Identity never drops. Every Record knows its ID, its encoding, and its stream — from creation through persistence to projection.
  4. Invalid states unrepresentable. Negative versions, empty entity IDs, unknown-encoding blobs, "maybe tombstoned" pointers — none of these compile.
  5. Deletion is a domain event. The tombstone metadata machinery is gone; user.deleted is just another event.
  6. Honest vocabulary. Aggregate-era names exist nowhere — not in types, not in wire formats, not in error codes.

06The Go Data Model

The redesigned base layer. record/ stays zero-dep — structure replaces stringliness. Everything is additive until the v5 cut. 

// record/ — Tier 0, zero dependencies. One home per concept.

// Stream replaces both the "Type/EntityID" string AND the duplicated
// StreamType field. Two struct fields: no separator, no parsing, no drift.
type Stream struct {
    Type     string // aggregate/category name; non-empty for events
    EntityID string // ULID, derived hash, or domain ID; non-empty
}

// Actor is the structural mirror of id.ActorID — the discriminated
// union made explicit instead of smuggled through "kind:raw" strings.
type Actor struct {
    Kind string // "user" | "bot" | "system" | "service"
    Raw  string
}

// Cause unifies what is today Tracing.CausationID + Metadata.Causation.
type CauseKind uint8

const (
    CauseNone CauseKind = iota // zero value = no cause; presence is explicit
    CauseCommand
    CauseTimer
    CauseEvent
)

type Cause struct {
    Kind CauseKind
    ID   string
}

// Stamp makes timestamp presence explicit. Zero time.Time can no
// longer masquerade as "recorded at epoch".
type Stamp struct {
    at    time.Time
    known bool
}

func NewStamp(t time.Time) Stamp { return Stamp{at: t.UTC(), known: true} }
func (s Stamp) Get() (time.Time, bool) { return s.at, s.known }

type CommonMetadata struct {
    CorrelationID string
    Cause         Cause       // one home — no precedence rules
    Actor         Actor
    Created       Stamp      // client clock
    Received      Stamp      // server intake clock
    Stored        Stamp      // DB acknowledgment clock
    SchemaVersion uint       // 1-indexed; 0 = unset
}

type Record struct {
    ID       string  // EventID / CommandID / RequestID — never dropped again
    Type     string
    Stream   Stream  // one home for type + entity ID
    Version  uint64  // negative positions unrepresentable
    Payload  []byte
    Encoding uint8   // codec stamp survives the bridge (I6)
    MetaData CommonMetadata
}

The runtime layer — slimmed, one shape per concept, interfaces that carry what implementations actually provide: 

// event/metadata.go — v5: tombstone & causation pointers deleted (ADR-0114).
// Tracing.CausationID moves into Cause; the struct keeps only what is real.
type Metadata struct {
    metadata.Tracing
    Source    Source
    IPAddress IPAddress
    UserAgent UserAgent
    Custom    map[MetadataKey]string
}

// command/command.go — the interface grows the accessor both
// implementations already have. Duck-typed workarounds die.
type Command interface {
    Type() Type
    StreamID() id.StreamID
    ID() id.CommandID
    Metadata() Metadata // NEW — no more type assertions in middleware
}

// decider — one identity argument, matching Store.Save's convention.
func (r *Repository[State]) Execute(
    ctx context.Context,
    ref id.StreamRef, // was: streamID id.StreamID, streamType id.StreamType
    decide DecideFunc[State],
) error

// scheduling — Tier 1 may depend on Tier 0 id/ by the layer rules.
type TimerID = id.Of[TimerMarker]

type Timer[P any] struct {
    ID      TimerID
    FireAt  time.Time
    Payload P
    Actor   id.ActorID // was: Actor string in "kind:raw" wire format
}

// snapshot — constructor, ref, codec stamp, honest tags.
func NewSnapshot(ref id.StreamRef, v event.Version, state []byte, enc codec.Encoding) Snapshot

// Type triplication — one definition, three aliases, zero new deps.
type Type = record.Type // in event/, command/, query/

Stream identity: parse-vs-access

Before — 3 shapes, 2 separators
After — 1 shape, 0 parses
// id.StreamRef — struct, ":" separator

// record.StreamRef — string, "/" separator

// event fields — unbundled pair

// Runtime: the one ref — field access, no parse

08Validation Layer

How invalid states become unrepresentable — or, where a constructor must remain the gatekeeper, how the type makes forgetting it impossible:

Compile-time elimination

  • Version uint64 — negative versions do not compile. The int64 in today's Record accepts them silently.
  • Stream struct — a stream without a type or entity cannot hide inside a malformed string; empty fields are visible at a glance and checkable by one Validate() with no parsing.
  • Cause value — "command-caused" and "no cause" are distinct values, not two nil-checks in a precedence chain.
  • Command.Metadata() in the interface — metadata access cannot fail; there is no assertion to forget.

Constructor-enforced invariants

  • Stamp: only NewStamp(t) produces a known stamp — the zero value reads as known=false, never as epoch.
  • NewSnapshot(ref, version, state, encoding) rejects nil state and zero version at creation, mirroring event.New's validation.
  • id.StreamRef.Validate() stays as the runtime gate (already correct today).

What deliberately stays runtime-checked

record/ is structural by design — its fields are plain strings so any layer can hold Record data without importing the domain. The validation lives one layer up: Validate() on Record checks I1/I2 before persistence. The type system narrows the invalid space; constructors close the rest.

10Anti-Patterns

Traps to avoid while adopting the new model — each one bit this codebase:

Never hand-roll a second identity shape

Every "convenience" local StreamRef fork eventually grows its own separator, its own parser, its own bugs. This repo's three shapes are the cautionary tale.

Never encode presence in zero values across a boundary

Inside one process, zero-means-unset is survivable. Across persistence or module boundaries it becomes ambiguity — and ambiguity becomes precedence rules.

Never let adapters invent precedence

If a converter must arbitrate between two fields, the model is wrong upstream. Two homes for one concept always leak.

Never keep deprecated shells past the major

36 Aggregate-era aliases still live because each minor kept them "one more release." The v5 cut must be ruthless or the vocabulary debt compounds forever.

Never confuse zero-dep with stringly

"This module can't import that one" constrains dependencies, not type structure. Structs, enums, and value objects are free.

Never drop fields in bridge types

A bridge that loses ID, encoding, or timestamps doesn't simplify — it silently narrows what the far side can do. AsRecord dropping both is this review's P5.

11Migration Roadmap

Ordered by Pareto impact — the first three steps close both critical findings' root causes without breaking consumers.

1

Additive v4.x — grow Record, fill the new fields (amended 2026-08-22)

Add Cause, Stamp, the structural Actor mirror, and Record.ID/Encoding; the three AsRecord bridges start populating a validated record.StreamRef by adopting the already-shipped Validate() bridge — no new identity type (Decision 09 amendment). Record.Version stays int64 and gains non-negative validation; the uint64 swap rides the v5 cut — a transitional dual Version field would be exactly the split-brain this review condemns. Zero consumer breakage; regen api-stability golden in the same change.

2

Interface completion — metadata access (reclassified 2026-08-22)

Adding Metadata() to the exported Command/Query interfaces is breaking for every consumer with a hand-rolled implementation; only embedders of *BasicCommand inherit it safely — and this is a library, where external implementors exist by design. (The original text called the impact "rare"; that was wrong.) The v4.x path is an additive capability interface (e.g. MetadataCarrier), adopted internally to replace the duck-typed paths in query/audit.go; growing the interfaces themselves is a v5-cut decision.

3

Unify signatures — Decider.Execute/Load take id.StreamRef

Add ref-based variants; deprecate the (streamID, streamType) pair forms. Internals migrate immediately; consumers at their own pace.

4

scheduling brands its IDs

TimerID = id.Of[TimerMarker], Timer.Actor id.ActorID. One new Tier-0 dependency, explicitly legal by the layer rules. Sweep consumer pins in the same wave (the MarshalBinary lesson).

5

Type consolidation

record.Type defined once; event/command/query alias it. Local ParseType/IsZero triplication collapses into record.

6

The v5 cut — delete the old generation (amended 2026-08-22)

Remove: 36 Aggregate aliases, tombstone metadata machinery (TombstoneMark, DetectTombstone, MarkTombstone/MarkRebirth, *Causation pointer), old snapshot JSON tags (with on-disk migration); swap Record.Version int64 → uint64 and make record.NewStreamRef a validating constructor — both per ADR-0123 Phase 8, owner-confirmed 2026-08-22. The string record.StreamRef type itself survives (see Amendments). One release, one coherent model, no shells.

7

Verify like the repo means it

After each step: nix run .#verify, nix run .#check-arch, consumer-pin sweep under GOWORK=off, and the full nix run .#test-all-backends matrix before the v5 tag.

12Conclusion

This codebase does not have a craftsmanship problem — id.ActorID, event.Version, and ImmutableEvent prove the team writes model types with the best of them. It has a generational problem: the v4 model is mid-flight between two architectures, and the adapters bridging them accumulate the stringly types, precedence rules, and duplicated vocabulary that this catalog documents. Close the migration, and twelve findings collapse into the four strong types this report designs.

"A data model doesn't rot because engineers write bad types. It rots because two good generations are allowed to coexist."
