01Findings — what was fucked up

1. The parser contract changed and the fuzz harnesses kept testing the old one

id.ParseStreamID/id.ParseStreamType correctly began rejecting invalid UTF-8, but four harnesses still asserted accept-any-non-empty-string. Every Fuzz Nightly since then failed as a stale-contract alarm, while “green Autoretry” runs masked it. Fixed: assertions corrected, invalid-UTF-8 seeds committed.

2. An exported named-string type interpolated raw into SQL on three engines

AggregateFn is a plain string alias; pg, sqlite, and duckdb interpolated string(fn) verbatim into aggregate SQL while mysql whitelisted. Any consumer-controlled value was a SQL-injection vector. Fixed with a whitelist, a classified rejection, and a cross-engine HostileFnRejected conformance pin.

3. The release scripts could tag poisoned go.mods and not notice

Both tag-release.sh and batch-release.sh swallowed a failed replace-strip commit (|| true) and then tagged HEAD unconditionally — the exact poisoned-tag class the batch script’s header claims to harden against (the 90-red-tags lesson said release verification must exercise behavior, not just resolution). Both now assert HEAD moved before the tag loop.

4. Gates that claim to check but only echo

The Benchmarks calibration job failed instantly on a bare-value $GITHUB_OUTPUT write — the cold run never ran and the artifact path matched nothing. The regression-gate bench legs teed empty/partial output into a green compare (no pipefail). verify-docs.sh’s “module count check” computed the actual count and never compared it. All three classes fixed; the repaired count check immediately caught a stale “58” claim in the shipped v4 wishlist.

5. Documentation lying to every agent in the fleet

The canonical skill taught deleted transport/http+transport/grpc as “deprecated until v5” for three weeks after the 2026-10-17 deletion (fixed in the earlier audit session). This session verified and fixed three more: FEATURES’ PLANNED table marked gRPC “✔” under “no production code yet”; AGENTS.md described minor-form Go directives when all 103 modules uniformly declare patch-form go 1.27.2; AGENTS.md said BuildFlow’s auto-configure is “kept skipped” when .buildflow.yml has been UNSKIPPED since 2026-10-07.

6. Two registered engines nothing in the fleet has ever booted

bigtableengine and irohengine are exported, driver-registered, and never booted by any stack adapter, example, or systemtest. With the first-party-only consumer scope (2026-10-08 decision), zero fleet consumers is the ADR-0152 delete-at-zero signal — but the census/decision is the owner’s, so they are reported, not deleted.

7. Two Tier-0 types named StreamRef that will formally disagree at v5

record.StreamRef (string Type/EntityID, empty type legal) vs id.StreamRef (struct, :-joined, empty type illegal). At the v5 cut record.NewStreamRef gains validation and the two “valid stream reference” definitions diverge on wire shape and validity rules. Needs a v5-window resolution, not a v4 patch.

02Open defects (ranked)

Blocking

decider.StateCache hands out the live cached State and folds onto it

decider/load.go:234-266 · decider/cache.go:25-26,77

loadFromCache returns the cached instance directly and foldEvents folds new events onto that shared instance. With pointer/map-bearing States (the normal aggregate shape), two concurrent LoadRef/ExecuteRef calls on one stream race — Otter is lock-free and nothing synchronizes the State value. The “consumers must treat State as immutable” contract comment is violated by the library one line later. Contrast kv/cache.go:118-123, which deep-copies on every Get.

Fix (owner decision needed) Copy-on-Get via a codec-based clone like kv.Cache, or a StateCloner option whose absence disables the hot-state cache. Both are behavior/perf tradeoffs — this is the top open defect and should be decided before the v5 cut, not rushed at the end of a session.
Important

Ghost engines: bigtableengine and irohengine have no executable composition path

metaengine/bigtableengine · metaengine/irohengine · stack/bundle.go

Verified: no stack/ adapter, no example, no systemtest boots either. Fuzz-corpus name lists and docs mention them; nothing executable does. Run the fleet census and apply the ADR-0152 delete-at-zero rule or commission a boot path — either decision is fine, drifting is not.

Important

Scheduled workflows pile up without concurrency guards

benchmarks.yml · fuzz.yml · sentinel.yml · go-finding-canary.yml · autoretry.yml

Only three workflows have a concurrency: block. Fuzz Nightly alone is four 90-minute shards weekly; overlapping dispatches are the billing-storm class the TODO already complains about.

Important

SHA-verification comments contradict their own pins

nightly-gates.yml:46-48 · go-finding-canary.yml:28,35

The “SHA verified 2026-09-18” annotation claims actions/cache v4.2.0 next to a pin labeled v6.1.0; the same checkout SHA is labeled v7.0.1 in one workflow and v7.0.0 in another. At least one label is false — the “verified” annotation process is not trustworthy and should be regenerated mechanically or deleted.

Important

Exported mutator escape hatch on nominally immutable messages

command/command.go:64-68 · query/query.go:107-111

ApplyOptions lets any middleware overwrite already-populated identity fields mid-pipeline; enriched and unenriched commands are indistinguishable. A v5-window type-model fix (enrichment epoch or unexported setters), needs a consumer-impact review.
