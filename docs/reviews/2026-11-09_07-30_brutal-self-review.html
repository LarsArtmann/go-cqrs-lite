The headline

.github/workflows/ci.yml gained cancel-in-progress: true on 2026-07-17. The auto-commit daemon pushes master every ~40 minutes; a full CI matrix needs ~2 hours. Result: every push cancelled the in-flight matrix. Of the last 30 push runs, 23 were cancelled, 5 failed, 2 were in flight — zero successes. The GitHub API confirms: the CI workflow has never had a successful run. Every “push-CI green” claim in prior reports and session summaries (including yesterday’s, citing run 42493776177 — actually cancelled) was read off a run that never finished.

Why nothing caught it for four months

Three blind spots stacked: (1) the Sentinel’s green-recency alarm reads completed runs only, and cancellations are not failures; (2) Autoretry reruns failures — nothing to rerun in a cancelled run — and its green reruns looked like health; (3) human/agent summaries conflated “jobs I watched go green” with “the run completed”. The new gates-rollup aggregator (shipped yesterday) was the first signal that names this class — it went red on both of its scheduled fires, correctly.

01Findings — what was fucked up

1. Master CI starvation: designed-in, never observed end-to-end

First fix attempt (PR-only cancel-in-progress expression) failed empirically: running push run 42565472010 was still cancelled by the next push. Expressions in cancel-in-progress did not protect the in-flight run. Second fix: push runs now get a unique per-run concurrency group — nothing shares it, nothing can cancel it. Tradeoff accepted and documented: stacked matrices queue behind each other (superseded intermediates cancelled by hand tonight). Proof pending: the newest run (be8e21f20) is the first with a realistic path to completion.

2. The nightly Benchmark Matrix timed out every night for 15+ nights — and the timeout was blamed on anything but the seed

bench-matrix.sh seeds DuckDB through Store.Apply per row: 100k rows at ~6 ms per INSERT-through-CGo on CI runners = ~10 minutes of seeding per repetition, times -count 3 times two benchmarks ≈ 66 minutes — for scans that measure 0.7 seconds. The job died at timeout-minutes: 45 every night since at least 2026-10-26 (15+ consecutive red/cancelled scheduled runs, zero successes in the last 40). Fixed: the (layout, n) fixture is now built once per process and reused across -count repetitions — measurement-honest because scans are read-only and setup was already outside the timer. CI proof: matrix runtime 45m+ → 19m19s, full cold dispatch green.

3. go-finding-canary: four consecutive weekly failures on a one-character path bug

The canary resolved the go-finding checkout as ../go-finding-master from cmd/cqrs-lint — one level short of the workspace root. It died before building anything, every Monday since 2026-10-12. Also pinned setup-go to 1.26.x while the module requires 1.27.2. Fixed + proven by manual dispatch: green. The weekly drift canary is now actually canarying.

4. The release wave left three ripple classes behind

(a) versions.json was stale against the wave’s own tags (manifest refreshed at 22:15, tags cut later) — the nightly versions gate would have flagged it. (b) The sqliteengine v4.8.0 bump reached only 3 of 11 affected go.sum files by 04:14 (nightly modsums red), and 8 more surfaced on re-check hours later. (c) Two shfmt-drift scripts from parallel sessions red the lint-scripts CI job. All three are the same lesson: tag waves need a mechanical post-wave sweep gate, not hope.

5. Gate-theater detector shipped; live tree clean

scripts/check-echo-gates.sh now flags check variables that are computed but only ever echoed — the verify-docs module-count class. Self-test with three fixtures (healthy / echo-gate / exempted), wired into verify-docs. Tree scan: zero live echo gates; seven informational displays annotated with mandatory reasons.

6. Calibration trust chain: cold → warm, both green, evidence enforced

COLD dispatch 42564460721 green (baseline established, date-fix proven); WARM dispatch 42566687686 green with zero drift warnings and a 1,094-byte drift-log artifact. The three Actions-level contract guards (freeze-on-fail, cold-establishment, evidence-class upload) are now structurally pinned by test-calibration-freeze.sh with mutation proofs, wired into CI. Failed-run provenance (42332942484, 42441847588, 42477839931) rowed into the script header.
