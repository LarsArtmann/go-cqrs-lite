Fixed On The Spot

The codebase is in genuinely strong shape. Build, vet, and all 43 test modules pass clean. The issues found were concentrated in two areas: (1) a silent data-loss bug in the scheduler, and (2) a broken contract between the CatchUpSubscriber's replay metadata and consumer-side context reconstruction. Both are fixed and tested. The remaining fixes were lint hygiene, doc/comment honesty, and removing a dead-code branch.

01Findings

Critical — Data Loss

Scheduler silently drops failed timers forever

scheduling/scheduler.go:119-123

MarkFired was called unconditionally after a failed dispatch, deleting the timer from the store. This contradicted the documented contract ("If it returns an error, the timer is re-scheduled for retry") and the DispatchFunc doc comment. Consumers relying on this contract would lose timers — e.g. a "cancel order after 30 min" timer that fails once would never fire again.

Fix Only call MarkFired on successful dispatch. On failure, log the error and continue — the timer stays in the store and will be retried on the next poll tick. Added TestScheduler_FailedTimerSurvivesForRetry that verifies the timer is re-attempted across polls.
Critical — Broken Contract

Replay processing mode never reached consumer handlers

watermill/catchup_subscriber.go:198-228

The replayCtx with ModeReplay was created but never used. The processing mode was set only in message metadata, but event.ProcessingModeFrom(ctx) reads from the context value, not metadata. So handlers branching on event.IsReplay(ctx) would always see false during replay — defeating the entire purpose of the replay/live distinction. A dead-code comment _ = replayCtx papered over the lie.

Fix Removed the dead replayCtx. Added ProcessingModeMiddleware() — the consumer-side counterpart that reconstructs the context value from message metadata, mirroring the existing TraceContextMiddleware() pattern. Documented the contract in AGENTS.md. Added 3 tests covering replay propagation, live-default behavior, and context-preservation.
Important — Doc Honesty

ProjectionHost.Start doc claimed it blocks; it returns immediately

projectionhost/host.go:95-97

The doc said "blocks until Stop is called or the context is cancelled" but Start launches goroutines and returns immediately. Worse, workers exit when caught up (no live tailing), but nothing documented this. A consumer reading the doc would build a for loop around Start expecting blocking semantics, or assume continuous tailing without pairing with CatchUpSubscriber.

Fix Rewrote the Host type doc and Start doc to accurately describe: (a) returns immediately, (b) workers are batch-drainers that exit when caught up, (c) for live tailing pair with watermill.CatchUpSubscriber.
Important — API Quality

Dynamic errors broke errors.Is classification

middleware/otel_bundle.go:103

errors.New(...) inline created a fresh error on every call, so consumers could never match it with errors.Is(err, ErrMeterRequired). This violates the project's "errors as values" principle (sentinel errors + %w).

Fix Extracted ErrMeterRequired as a package-level sentinel in errors.go, alongside the existing ErrValidationFailed, ErrRetryExhausted, etc. Consumers can now branch reliably.
Lint Hygiene

Misplaced doc comment, global variable, dead branch, magic number

decider/otel.go, middleware/metrics_otel.go, transport/http/sse*.go, decider/decider.go, stack/accessors.go

Six lint-flagged issues across non-test code: (1) a misplaced godoc describing NewOTelMetricsRecorder but attached to Histogram(); (2) two mutable globals (tracerOnce, cachedTracer) replaced with idiomatic sync.OnceValue; (3) an ineffassign in SSEBroker.handleEvent; (4) a magic 10 for strconv base; (5) a dead-code branch (if len(newEvents) > 0 after an early-return on 0); (6) four unnecessary explicit type arguments that go vet flagged; (7) a stale unused puddle/v2 dependency in stack/go.mod.

Fix All six resolved. go vet and the full lint suite now report zero non-test issues. The test-file lint warnings (forcetypeassert, nonamedreturns) are pre-existing and out of scope.

Strengths

These patterns are worth preserving. They represent the high bar this review measured against — the codebase met or exceeded it in nearly every area.

+
Phantom-typed IDs prevent cross-assignment at compile time id.Of[T] makes UserID ≠ OrderID a type error, not a runtime bug. ULID-backed, zero-cost.
+
TombstoneStatus is a typed enum, not a bool Three states (Active/Tombstoned/Undetermined) make "unknown" representable — impossible to confuse with "not deleted".
+
Version arithmetic is underflow-safe Decrement() and Sub() return ErrVersionUnderflow instead of wrapping; Add() takes uint so underflow is impossible at the type level.
+
Concurrency is disciplined everywhere CAS-based close (PostgresBus), RWMutex on fanout (SSEBroker), non-blocking sends with drop semantics, jittered backoff in workers and scheduler, proper ctx.Done() checks in every loop.
+
Singleflight load coalescing decider.Repository coalesces concurrent Load calls for the same aggregate into one store query — transparent, no API change, events are immutable so sharing is safe.
+
Defensive cloning on all public accessors Payload(), Metadata(), EventTypes() all return clones. Zero-copy internal paths (PayloadReadOnly) bypass this only where safe.
+
ISP-clean store interfaces Store = EventSink + EventSource; consumers accept the smallest interface. Event is a concrete alias, not an interface — no type assertions on hot paths.
+
5-family error taxonomy with wrapping Rejection / Conflict / Transient / Infrastructure / Corruption. All classified errors use go-error-family so errors.Is works transitively.
