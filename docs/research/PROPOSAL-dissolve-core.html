01

The Problem

core/event/ contains 28 files, ~2,500 lines, and 8 distinct concerns — from the Event type itself to snapshot strategies, outbox publishers, and projection checkpoints. It's the only package in the repo that violates the "one concept, one package" rule.

The core/ prefix is the only nested module group in a repo of 17+ flat top-level modules. It forces command/ and query/ — which share zero dependencies — to share a go.mod with 15+ dependencies they don't need.

The word "core" is meaningless. Every module thinks it's core. It's the util of package naming — a drawer for things you haven't properly named yet.

The real cost: Every import pays a core/ path tax forever. A consumer writing "go-cqrs-lite/core/event" is carrying a prefix that communicates nothing and couples unrelated packages.

02

Principles

  1. 01 Honest names. Every module named after what it is, not where it sits in a hierarchy.
  2. 02 Peer-level modules. The repo already uses flat top-level modules. core/ is the outlier.
  3. 03 Minimal go.mod. A module's dependencies should be only what it needs. command/ should not transitively depend on codec.
  4. 04 Interface–implementation separation. Core modules define interfaces. Implementations live in their own modules (memory/, storage/, pebble/).
  5. 05 Additive first, breaking last. Migration phases add new paths, update call sites, then remove old aliases.

06

schema/ — The New Module

Upcasting is currently buried in core/event/ — but it's neither an event concern nor a store concern. It's a schema evolution concern. Naming the module upcaster/ would describe the mechanism. schema/ describes the domain.

Future growth. A schema/ module naturally accommodates compatibility checks, version registration, auto-documentation hooks (via catalog/), and migration policies — none of which fit under "upcaster."

07

Dependency Graph

After the split, the dependency graph is a clean DAG — no cycles, no false coupling. Each module depends only on what it actually needs.

Layer 0 — Leaves (no internal deps) id/ · dispatcher/ · codec/ · event/

Layer 1 — Infrastructure interfaces store/ → event/
bus/ → event/
schema/ → store/, event/

Layer 2 — Domain primitives command/ → id/, dispatcher/
query/ → dispatcher/

Layer 3 — Aggregate pattern decider/ → event/, store/, schema/

Layer 4 — Implementations (outside core) memory/ → event/, store/, bus/
storage/ → store/, schema/
projection/ → event/, store/
outbox/ → bus/, store/
…

Key difference: command/ and query/ no longer share a go.mod with event/. Their only dependencies are id/ and dispatcher/ — exactly what they need.

08

Migration Plan

Each phase is independently shippable. No phase requires the next to be useful.

  1. Create new top-level directories
    Create event/, store/, bus/, schema/, command/, query/, decider/, id/, dispatcher/ with their own go.mod files.
  2. Copy files (don't move yet)
    Copy source files into their new homes. Add re-export aliases in core/event/, core/command/, etc. so existing consumers keep compiling. All tests pass at every step.
  3. Update internal consumers
    Update all imports across memory/, storage/, projection/, middleware/, signing/, catalog/, testhelpers/, etc. to use new import paths.
  4. Extract outbox + projection interfaces
    Move outbox*.go to outbox/. Move projection.go, checkpoint.go, replay.go to projection/.
  5. Remove re-export aliases
    Delete compatibility aliases in core/. Every consumer now points to flat modules.
  6. Delete core/
    Remove the core/ directory entirely. Update go.work. Full test suite passes with nix run .#test.
