01Summary

catalog/docserver is the richest consumer of github.com/larsartmann/templ-components in the workspace: five .templ pages plus their Go glue render the docs index, the EventCatalog browse UI, Scalar and AsyncAPI SPA chrome, and the D2 architecture page — all pinned at v1.19.4, which is the library's latest tagged release (2026-09-25). The version answer is unambiguous: we are current.

The utilization answer was "very good, not yet superb." The audit found the library's newest layout ergonomics unused while the same patterns were hand-rolled: the page-gutter <div> repeated at 8 sites, a three-line hand-rolled htmx kill switch, literal <script>/ <link> tags beside a CSP-safe component pair, and not-found pages that answered 200 OK. All four v1.19.4-actionable gaps were fixed during this audit, with a regression test added and every drift gate re-run green.

The bottom line We are on the latest release and use it well — after this audit. The two remaining opportunities are structural, not cosmetic: the EventCatalog tables render every row with no cap, note, or pagination (ListNote + Pagination sit unused), and the library's go-error-family-aware errorpage package exists only as unreleased upstream work — adopt it the moment a tag lands.

Feedback and icons fully typed feedback.Alert (info + warning) for degradation and deprecation notices; typed icons.Name end-to-end (spec cards carry icon fields, not strings); utils.Lookup for the kind→badge-type map (d2view.templ:55, eventcatalogview.templ:166, pages.go:47-48, eventcatalog_rows.go:57-61).
+
CSS pipeline scans the library itself Tailwind v4 @source lines cover the library's display/layout/navigation/utils sources and the theme import supplies the rest — verified: feedback classes are present in the built CSS via the theme even though feedback has no @source line (scripts/build-docserver-css.sh:45-50).
+
Codegen is gated, not trusted Committed *_templ.go with a two-gate drift guard: check-templ (freshness + a FileName cwd tripwire) and check-docserver-css (flake.nix:1189-1199, scripts/check-templ-paths.sh).

Architecturally the consumer wraps the library thinly and correctly: view-model builders (pages.go, eventcatalog_rows.go, eventcatalogview.go) translate catalog types into props; handlers apply CSP then render components; no component is re-implemented or fought with custom CSS overrides. The depguard allowlist and the full catalog dep budget (5 slots, templ + templ-components among them) keep the dependency deliberate.

03Capability Assessment — Feature by Feature

Missed Opportunity · RESOLVED this audit

Page gutter hand-rolled at 8 sites — layout.Container exists to kill exactly this

index.templ:24 · d2view.templ:35 · eventcatalogview.templ:23, 88, 137, 210, 250, 297 · spaHeader layout.templ:61 (pre-fix line numbers)

Every page opened with <div class="mx-auto w-full max-w-7xl px-4 pb-16 pt-8 sm:px-6 lg:px-8">. The library's Container doc comment names this pattern verbatim as the thing it replaces ("the single source of truth for page content width and page gutter"), with a typed ContainerWidth enum (LG = max-w-7xl) and a Pad flag for the responsive gutter.

Gotcha found while fixing The documented "Defaults: Pad=true" applies only via DefaultContainerProps(). A literal ContainerProps{...} has Go's zero Pad=false and silently drops the gutter (caught by rendering the page and diffing classes). Every adoption must pass Pad: true explicitly. This consumed the audit's debugging budget and is the single most valuable piece of knowledge in this report. 
// Before (x8)
<div class="mx-auto w-full max-w-7xl px-4 pb-16 pt-8 sm:px-6 lg:px-8">

// After
@layout.Container(layout.ContainerProps{Pad: true, Class: "pb-16 pt-8"}) { ... }
Partially Used · RESOLVED this audit

htmx disabled by hand with three redundant fields — layout.HTMXNone is the canonical switch

catalog/docserver/layout.templ:21-23 (pre-fix)

docsPageProps cleared HTMXVersion, HTMXSrc, and HTMXResponseTargets individually. Since v1.19.3 the library ships HTMXNone (backlog #282): one sentinel that emits no script, no CDN preconnect, and no response-targets extension (verified in layout/base.templ:271-291 — all three emissions are gated on HTMXSrc != HTMXNone). The two extra field clears were dead weight; rendered output is byte-identical. 

// Before
props.HTMXVersion = ""
props.HTMXSrc = ""
props.HTMXResponseTargets = false

// After
props.HTMXSrc = layout.HTMXNone
Anti-Pattern · RESOLVED this audit (status half)

Not-found pages answered 200 OK — soft-404s, while the library's errorpage direction says otherwise

eventcatalog_handlers.go:17-28, 39-51, 65-77, 86-98 · tests pinned the 200: eventcatalogview_test.go:155, eventcatalog_dataproduct_test.go:151 (pre-fix)

Unknown message/channel/service/data-product deep links rendered a styled "Unknown …" page with HTTP 200 — breaking SEO, link checkers, monitoring, and any client that branches on status. Two tests explicitly asserted the 200 with comments defending it, so this was a deliberate local choice — but it contradicts HTTP semantics and the library's own evolution: its (unreleased) errorpage package with ErrorHandler/WriteError is go-error-family-aware and status-correct, and this repo already imports go-error-family. The fix sends http.StatusNotFound through a renderComponentStatus variant; full errorpage adoption is pending the library's next release. 

// After: styled body AND honest status
ds.renderComponentStatus(w, r, http.StatusNotFound,
    eventCatalogNotFound(cfg.ServiceName, cfg.DocsPath, "message", id))
Partially Used · RESOLVED this audit

Literal <script>/<link> tags beside the CSP-safe component pair

specview.templ:44, 84 (scripts) · specview.templ:63 (stylesheet) (pre-fix)

The SPA bootstrap pages hand-wrote <script nonce={...} src={...}> and <link rel="stylesheet"> while layout.Script(nonce, src, attrs) and layout.Stylesheet(href, attrs) exist precisely to centralize CSP-safe asset tags. The two inline bootstrap scripts stay literal — the library offers no inline-script component at v1.19.4, and they correctly carry the nonce attribute. 

// After
@layout.Script(templ.GetNonce(ctx), docsPrefix+"/static/scalar.js", nil)
@layout.Stylesheet(docsPrefix+"/static/asyncapi-react.css", nil)
Missed Opportunity · High impact · OPEN

EventCatalog tables are unbounded — ListNote and Pagination/LoadMore sit unused

eventcatalogview.templ:38-76 (four tables) · eventcatalogview.go (no cap on rows)

The messages table renders every message in the catalog — a 500-message catalog means a 500-row DOM with no truncation notice and no paging. The library ships the whole answer at the pinned version: display.ListNote ("Showing N of M. Narrow your search…" / count-only variants, display/list_note.templ:9-23) and navigation.Pagination / LoadMore / EndOfList. Closing this needs a product decision first (cap size, default sort), then it is a small change. Table row-level Href (clickable rows) was assessed and is not applicable — catalog rows carry multiple distinct links per row.

Missed Opportunity · BLOCKED on upstream release

errorpage package (4 components, 6 constructors, go-error-family-aware handler) is not in any release yet

not in v1.19.4 (verified against the module cache); present in the templ-components working tree as an unreleased package

Once released, errorpage.NotFound404, WriteError, and FromError (which extracts family/title/code/why/fix/trace from a go-error-family error — the taxonomy this repo uses everywhere) replace the hand-rolled eventCatalogNotFound plumbing and give every docserver error path the same treatment. Watch the library changelog; bump + regenerate CSS in the same commit (CONTRIBUTING rule).

Partially Used · Low impact · OPEN

Minor ergonomic gaps: PageHeader.Breadcrumb slot, CollapsibleSection.StorageKey, pre-block dedup

eventcatalogview.templ (5 detail pages render Breadcrumbs above PageHeader) · d2view.templ:43-53 (StorageKey unset) · codeBlock pre styling repeated 3×

PageHeaderProps.Breadcrumb templ.Component (display/page_header.templ:12-14) renders the breadcrumb inside the header block; the current sibling-above-header layout works and keeps spacing explicit, so this is a taste-level adoption. StorageKey would persist the D2-source section's open/closed state in localStorage for free. The three near-identical <pre> source blocks (2 in d2view, 1 in eventcatalogview) are repo-local duplication — the library has no CodeBlock component at v1.19.4 (Scrollback is for logs, not code), so consolidating means a local codeBlock helper, not a library feature.

Fully Leveraged · assessed and correct

Deliberate non-adoptions that are the right call

audit-wide

StatusBadge (exists at v1.19.4, badge_templ.go:363) maps ~20 generic status strings; the docserver's event/command/query color semantics are domain-specific, so the 5-line utils.Lookup map is the better tool. 06Conclusion

Before this audit the honest answer to "are we using templ-components superbly?" was not yet: the adopted surface was clean and CSP-exemplary, but the newest layout ergonomics went unused while their patterns were hand-rolled, and one HTTP-semantics anti-pattern hid behind styled markup. The audit closed every gap actionable at v1.19.4 — 8 Container sites, HTMXNone, Script/Stylesheet, real 404 statuses, one helper dedup — with a regression test pinning the htmx-free, Container-gutter contract, and both drift gates green.

The highest-leverage next step is the table-bounds decision (opportunity #6): pick a cap, then ListNote + Pagination complete the display-story. After the library's next tag, adopt errorpage and retire the last hand-rolled error plumbing. At that point the docserver is the reference consumer the sibling library deserves.
