00Summary

CV consumes github.com/larsartmann/templ-components across 29 .templ sources and 7 Go files, touching eight packages and roughly 90 distinct exported symbols. The adoption is not casual: it is governed by a maintained adoption table with per-component rulings and re-entry triggers, integrated through a committed Tailwind safelist and an @theme tone bridge, and pinned by library-aware tests. Where the library is used, it is used superbly.

The weakness is currency, not depth. CV pins v1.16.0 (2026-09-09); the library is at v1.19.4 (2026-09-25) — 665 commits of accessibility hardening, an errorpage overhaul, form-decoding and relative-time APIs, and one production-purity fix that CV is currently without: the cv binary links the Go testing framework through utils@v1.16.0. The library's own changelog flags v1.19.3's tag tree as poisoned — the upgrade target must be v1.19.4 or newer.

The bottom line One version bump unlocks nearly every finding in this report: testing-delinked production binaries, the accessibility pack, the errorpage surface, wire.DecodeForm, and RelativeTime's injected clock — which satisfies the exact re-entry trigger CV recorded on 2026-09-05 when it rejected the component ("re-entry trigger: an upstream injected-clock prop").

Production impurity · fixed upstream in v1.18.1

The cv binary links the Go testing framework

utils@v1.16.0/test_helpers.go (non-test file importing "testing") · verified via go list -deps ./cmd/cv containing testing

The v1.16.0 utils render/assert helpers take *testing.T, so the package imports testing in production code — and any consumer binary that imports utils (CV's badges.go, fields_helpers.go) links the whole test framework. The library fixed this in v1.18.1 by moving the helpers onto a local TestReporter interface (found in dnsblockd via go tool nm). CV is carrying a defect its own dependency already fixed.

Recommendation Rides the upgrade for free. Verify after: go list -deps ./cmd/cv | grep -x testing must return nothing.
Re-entry trigger FIRED · recorded 2026-09-05

RelativeTime's injected clock exists — the T25 rejection is obsolete

CV: internal/features/admin/handlers/admin_handler.go:341 (hand-rolled relativeAge) · Library: display.RelativeTimeProps.Now + AutoRefresh (v1.17.0)

CV rejected display.RelativeTime because "the library hardcodes time.Now()" and its AutoRefresh script breaks byte-deterministic rendering, naming the upstream injected-clock prop as the re-entry trigger. v1.17.0 shipped exactly that: Now pins the reference instant and AutoRefresh: false renders fully static — both blockers are gone, and the trigger CV wrote down has fired. 

// Before: hand-rolled phrasing, tested by hand
stats.LastActivityRelative = relativeAge(snap.UpdatedAt, time.Now().UTC())

// After: library component, deterministic, i18n-formatted
@display.RelativeTime(display.RelativeTimeProps{
    Time:        snap.UpdatedAt,
    Now:         h.now.UTC(),
    AutoRefresh: false,
})
Recommendation Adopt on the admin hub's last-activity stamps. Small effort, and it retires hand-rolled bucket logic (plus its unit test) in favor of the library's 26-case boundary-tested implementation.
Partially Used · 1 of 4 error components

errorpage adoption stops at NotFound

Used: errorpage.NotFound (internal/ui/not_found.templ) · Unused: ErrorAlert, ErrorDetail, ErrorPage, FromError, ErrorHandler

Since v1.18.1 the errorpage package is a full error-rendering system: family-derived titles/status codes, oops-style Public() message safety, trace-ID footers, retry-aware way-outs, neutral ErrorDetail variants, and copyable error codes. CV hand-rolls its HTML error moments: the GraphRAG-disabled console alert parses a 503 JSON envelope into a bespoke inline alert, and typed error responses (404 VARIANT_NOT_FOUND etc.) have no HTML face.

Recommendation Render the GraphRAG enable-hint through ErrorDetail (Neutral variant fits the console), and give guarded-JSON 4xx/5xx surfaces an ErrorPage/FromError HTML face. Correlation IDs already exist in CV's command metadata — the new Trace field is a natural fit.
Missed Opportunity · rides the upgrade + one CSS import

The accessibility pack and component CSS never landed

CV ships no templates/custom.css import (only utility safelisting) · Library: v1.17.0–v1.18.0 a11y waves

Three layers of upstream accessibility work are absent from CV's output: (1) component-behavior fixes to adopted components — labeled form controls derive their DOM id from Name (WCAG 1.3.1/4.1.2), Table scroll wrappers became keyboard-focusable, StatCard trend colors hit WCAG contrast; (2) the touch-target/zoom-reflow audits that reshaped NavLink, Toast dismiss, and Table sort links; (3) the templates/custom.css rules — forced-colors focus restoration, prefers-contrast border hardening — which CV does not import at all, so no amount of version bumping delivers them.

Recommendation Import templates/custom.css into assets/css/input.css in the upgrade change and re-run the axe gates; the forced-colors and prefers-contrast rules are consumer-side imports by design.
Partially Used · typed decoding unused

wire.DecodeForm vs hand-rolled PostForm decoding

CV: internal/features/ateam/handlers/field_validation.go:28,84 (c.Request.PostForm + handleFullValidation(c, form url.Values))

v1.17.0 added utils/wire.DecodeForm[T]: typed request structs with form: tags, checkbox handling, loud failures on malformed values — the same make-impossible-states-unrepresentable discipline CV applies to its JSON wire contracts. The A-Team validation endpoint still passes raw url.Values around. 

type ateamValidateForm struct {
    KeySkills   string `form:"keySkills"`
    Rate        string `form:"rate"`
}
form, err := wire.DecodeForm[ateamValidateForm](c.Request)
Recommendation Adopt where forms decode into fixed field sets (A-Team validation, contact). Low priority — the current code works and is validated — but it is the library's stated answer to this exact shape.
Nice to have · explicitness, not bytes

Five htmx-free pages could declare HTMXNone

landing.templ, chat_page.templ, coaching_page.templ, dashboard_page.templ (pipeline), not_found.templ — zero hx-* attributes each; HTMXSrc left at ""

These pages already ship no htmx bytes (ScreenBase only emits the script when HTMXSrc is non-empty), so v1.19.3's layout.HTMXNone is a documentation win, not a payload win: it states the intent in types and guards against accidental reintroduction. The three real htmx pages (admin, ats dashboard, ateam form) correctly self-host the vendored runtime.

Governance note · facts changed under a parked ruling

KanbanBoard's park predates its hardening wave

Ruling: 2026-09-13 "let it age" · Library since: CSRFToken prop, column Tone/Action, optimistic pending register with honest failure revert (v1.18.0–.1), mobile overflow fix

The park decision remains correct — notably because the new optimistic-move behavior mutates the DOM client-side, which directly conflicts with CV's pinned F38 board contract ("the JS NEVER mutates the DOM; the SSE swap re-renders truth"). But the recorded rationale should note the new facts so the next board change starts from today's library, not v1.16's.
