00Summary

go-cqrs-lite is a production-grade CQRS + event-sourcing library that has reached genuine fleet-backbone status in eight months: 9,523 commits since 2026-03-15, 1,648 tagged module releases, 100 workspace modules, and direct imports in 48 of the LarsArtmann fleet's projects (58 checkout directories, 51 distinct after collapsing mirrors) — 30 of those directories already on the modern system/metaengine composition path. The core loop (command → decider → event store → projection → read model) is mature, exceptionally well tested (319k test LOC, 55% of the codebase; 7,340 test functions), and surrounded by unusual tooling maturity: a 217-rule architecture linter, an API-stability differ with golden files, a benchmark harness with statistical-rigor gates, and a catalog subsystem that renders the whole architecture into a self-contained HTML reference.

The library is mid-transition. ADR-0123 consolidates everything into a system.New composition root plus metaengine as the sole durable-I/O substrate, with a v5 module (core/v5, 29.5k LOC) being assembled while 18 legacy fleet consumers and ~20k LOC of deprecated-but-shipped modules (stack, idempotency stores, kv views) still ride the v4 train. Meanwhile the quality gate is red at HEAD with 255 error-severity findings — 235 of them file-size violations scattered repo-wide against the 350-line ratchet (one finding per file, test files heavily represented).

The bottom line Ship-grade core, honest docs, world-class testing — the two real risks are (1) the unfinished v4→v5 dual-train carrying ~20k LOC of deprecated surface plus 18 unmigrated fleet directories, and (2) a tripped quality gate whose 235 file-size findings are scattered across the repo — the ratchet is broadly tripped, not localized. Land the v5 cut, migrate the legacy twenty, and split the oversized files; the score goes to ~85 without inventing anything new.

The findings gate fails with 255 findings at error severity. 235 are file-size violations — one per oversized file, scattered across the whole repo (watermill, catalog, cmd/cqrs-lint, core/v5, signing, systemscenario, metaengine among them) against the repo's 350-line ratchet, with test files heavily represented. 02Architecture

A library, not a framework: 100 workspace modules composed via go.work, each independently versioned on the module proxy (1,648 tags to date). The runtime loop every module serves:

Command → Dispatcher → Handler → Decider (load → fold → decide → save → publish) → EventStore + Bus → Projection → ReadModel → Query

The two modules that matter (ADR-0123)

system/v4 (18,695 LOC, promoted out of experimental 2026-11-03) is the composition root: system.New(ctx, DomainConfig, DeploymentConfig) auto-wires event store, bus, projectionhost, deciders, queries, snapshots, timers, scheduling, health, docserver, and lifecycle. Developers declare domain types + folds; operators pick engines in one place.

metaengine/v4 (153,696 LOC incl. 18 sub-modules) is the cost-based storage planner: Store + Query[Q,R] with canonical OnRecord folds build read models that auto-project across interchangeable engines — memory, sqlite, turso, pebble, bbolt, badger, duckdb, postgres (production), plus experimental dgraph, bigtable, iroh. It also owns the Graph ADT (edge folds + reachability), planned tables, materialized views, DedupStore, and ServeSSE[V] for live read-model streaming. Per the I/O rule (owner directive 2026-10-24, extends ADR-0142), all durable data I/O goes through it.

sys, err := system.New(ctx,
