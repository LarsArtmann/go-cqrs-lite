Metadata: Pointer to Value

Change *Metadata to Metadata across the entire codebase — eliminating nil checks, lazy-init guards, and defensive copying.

01

Why

*Metadata exists to support lazy initialization — only allocating when a metadata option is used. But every production event should have metadata (at minimum correlation ID and source). The lazy-init pattern:

  • Requires 8+ nil-check guards across options.go alone (lines 20, 44, 100, 104)
  • Requires 12+ nil-check guards in consumers (tombstone, signing, aggregate projection, watermill, storage, catalog)
  • Makes it easy to forget metadata — no compile-time enforcement
  • Forces Metadata() to return a defensive copy on every call (event.go:171-184)
  • The "optimization" saves ~120 bytes on events that should not exist in production
Current Smell

Every WithXxx option repeats the same guard: if e.metadata == nil { e.metadata = NewMetadata() }. This is the type fighting its own design.

02

The Principle

Make impossible states unrepresentable. If metadata should always exist, the type system should enforce it. A value Metadata is always present — even if zero-valued. There is no nil to check, no guard to forget, no lazy-init to maintain.

*Metadata (current) Metadata (proposed)
Nil possible? Yes — 12+ nil checks in codebase No — zero value is always valid
Lazy-init guards 8+ in options.go alone Zero — always initialized
Copy semantics Defensive copy on every Metadata() call Value copy (Go default)
Forget metadata? Easy — no compile error Impossible — always present (zero-valued)
Allocation cost 0 bytes if nil ~120 bytes always (7 branded IDs + map header)

Target State

Interface & struct

type Event interface {
    // ...
    Metadata() Metadata
}

type ImmutableEvent struct {
    // ...
    metadata      Metadata
}

Option — no guards needed

func apply[T any](field metadataOption[T], value T) Option {
    return func(e *ImmutableEvent) {
        field(&e.metadata, value)
    }
}

Getter — simplified copy

func (e *ImmutableEvent) Metadata() Metadata {
    return e.metadata.Clone()
}

Consumers — check map only, never nil struct

// Before:
if md == nil || md.Custom == nil {

// After:
if md.Custom == nil {

NewMetadata becomes a value constructor

// Before:
func NewMetadata() *Metadata {
    return &Metadata{...}
}

// After:
func NewMetadata() Metadata {
    return Metadata{
        Custom: make(map[MetadataKey]string),
    }
}

mergeFrom becomes a value-returning method

// Before:
func (m *Metadata) mergeFrom(other *Metadata) { ... }

// After:
func (m Metadata) merge(other Metadata) Metadata { ... }

Breaking Change

Event.Metadata() changes return type from *Metadata to Metadata. This is a public API break. Any external consumer calling evt.Metadata() and checking for nil will get a compile error — which is good, because it forces them to remove their nil checks too. Pre-v1.0 is the right time.

Step-by-Step Plan

Phase 1: Core types (core/event/)

  1. metadata.go — Change NewMetadata() to return Metadata value. Add Clone() Metadata method. Change mergeFrom to merge(other Metadata) Metadata (pure function style).

func NewMetadata() Metadata {

func (m Metadata) Clone() Metadata {
    cp := m
    if m.Custom != nil {
        cp.Custom = make(map[MetadataKey]string, len(m.Custom))
        maps.Copy(cp.Custom, m.Custom)
    }
    return cp
}

        e.metadata = e.metadata.merge(m)

07

Risks & Mitigations

Risk Likelihood Mitigation
External consumers break on Metadata() return type change Medium Pre-v1.0 — no stability guarantee. Compile error is a feature — it forces nil-check removal.
JSON serialization difference — omitempty skips zero struct differently than nil pointer Medium Value Metadata{} serializes to {"correlationId":"","causationId":"",...} instead of being omitted. Verify with pebble/storage roundtrip tests. Add omitempty to all Metadata JSON tags if needed.
Map field Custom is nil on zero-value Metadata{} — consumers still need md.Custom == nil checks Confirmed Correct — Custom map nil-checks stay. Only struct nil-checks are removed. This is the right boundary: nil map = "no custom fields", nil struct = "impossible state" (eliminated).
mergeFrom method mutates receiver — becomes merge returning new value Low Pure function style is cleaner. Single call site in WithMetadata option.
Performance: ~120 bytes allocated per event even without metadata Low Negligible. Events are not allocated in tight loops. The []byte payload is always larger. Premature optimization.
Net Effect

Remove ~50 lines of nil-check boilerplate. Eliminate an impossible state. Simplify the Metadata() getter from 15 lines to 3. Make the API honest — metadata is always present.
