01

Why

*Metadata enables lazy initialization — only allocating when a metadata option is used. But every production event should have metadata. The lazy-init pattern:

  • Requires 8 nil-check guards in options.go (lines 20, 44, 100, 104)
  • Requires 12 nil-check guards in consumers (tombstone, signing, aggregate projection, watermill, storage, catalog, pebble)
  • Makes it easy to forget metadata — no compile-time enforcement
  • Forces Metadata() to return a defensive copy on every call (event.go:171-184)
  • Saves ~120 bytes on events that should not exist in production
Code Smell

Every WithXxx option repeats if e.metadata == nil { e.metadata = NewMetadata() }. This is the type fighting its own design.

03

JSON Wire-Format Analysis

Current behavior (pointer)

// serializableEvent in pebble/serialization.go:55-66
Metadata *event.Metadata `json:"metadata,omitempty"`

// nil pointer → key omitted from JSON entirely:
{"id":"...","type":"...","version":1,...}  // no "metadata" key

After migration (value)

Metadata event.Metadata `json:"metadata,omitempty"`

// Zero-value Metadata{} → all fields are zero → with omitempty on all fields:
{"metadata":{}}  // key PRESENT but empty object

Why this happens

Go's encoding/json treats omitempty differently for structs vs pointers. A nil pointer with omitempty is omitted. A non-nil zero struct with omitempty is included (because Go considers the struct "non-empty" even if all fields are zero). Verified by testing: 

// Test results:
Parent{Metadata: nil}          → {}                    // pointer nil: key omitted
Parent{Metadata: &Meta{}}      → {"metadata":{}}       // pointer to zero: key present
Parent{Metadata: Meta{}}       → {"metadata":{}}       // value zero: key present (same!)

Required JSON tag changes

The 4 ID fields currently lack omitempty. They MUST get it to avoid serializing "correlationId":null for zero values: 

CorrelationID id.CorrelationID `json:"correlationId"`
CorrelationID id.CorrelationID `json:"correlationId,omitempty"`

CausationID   id.CausationID   `json:"causationId"`
CausationID   id.CausationID   `json:"causationId,omitempty"`

UserID        id.UserID        `json:"userId"`
UserID        id.UserID        `json:"userId,omitempty"`

RequestID     id.RequestID     `json:"requestId"`
RequestID     id.RequestID     `json:"requestId,omitempty"`
Wire Format Change

Before: "metadata" key absent for zero metadata. After: "metadata":{} appears. This is backward-compatible for json.Unmarshal consumers (empty object unmarshals to zero fields). Pebble SQL and PostgreSQL storage both use logical roundtrip tests (value assertions, not byte matching). No test breaks.

Type Model Improvements

Discovery: Duplicated Tracing Fields

Both event.Metadata and command.Metadata share the same 4 core tracing fields:

Field event.Metadata command.Metadata
CorrelationID ✅ ✅
CausationID ✅ ✅
UserID ✅ ✅
RequestID ✅ ✅
Source ✅ ❌
IPAddress ✅ ❌
UserAgent ✅ ❌
Custom ✅ map ❌
Deferred — Separate Task

Extracting TracingMetadata (4 shared fields) into core/pkg/id/ or a shared package is a good refactor, but not in scope for this plan. It would require updating both event and command Metadata, all their option functions, all test assertions, and JSON tags. The pointer-to-value migration is already a big enough change. Extract AFTER the value migration is complete and stable.

Add Clone() to Metadata

Currently, the defensive copy logic lives entirely inside ImmutableEvent.Metadata() (event.go:171-184). Extracting it to Metadata.Clone() simplifies the getter and makes the copy semantics reusable: 

// metadata.go — new method
func (m Metadata) Clone() Metadata {
    cp := m
    if m.Custom != nil {
        cp.Custom = make(map[MetadataKey]string, len(m.Custom))
        maps.Copy(cp.Custom, m.Custom)
    }
    return cp
}

// event.go — simplified getter
func (e *ImmutableEvent) Metadata() Metadata {
    return e.metadata.Clone()
}

mergeFrom → merge (pure function)

// Before: mutates receiver
func (m *Metadata) mergeFrom(other *Metadata) { ... }

// After: returns new value
func (m Metadata) Merge(other Metadata) Metadata {
    result := m
    if !other.CorrelationID.IsZero() { result.CorrelationID = other.CorrelationID }
    // ... same logic, but returns result
    return result
}
05

Existing Code Reuse

command.Metadata — the template

command.Metadata already uses value semantics. Its NewMetadata() returns Metadata (not pointer). This is the pattern to follow. 

// core/command/metadata.go — ALREADY value-based
type Metadata struct {
    CorrelationID id.CorrelationID `json:"correlationId"`
    CausationID   id.CausationID   `json:"causationId"`
    UserID        id.UserID        `json:"userId"`
    RequestID     id.RequestID     `json:"requestId"`
}

func NewMetadata() Metadata { // value return!
    return Metadata{}
}

ImmutableEvent.Clone() — already does metadata copy

Clone() at event.go:216-237 calls e.Metadata() to get a defensive copy. After migration, this still works — Metadata() returns a value copy via Clone().

ContextEnricher — no change needed

The enricher pattern (core/event/enricher.go) returns []Option. Options still set metadata via apply() which takes *Metadata for in-place mutation. No change needed — the options close over &e.metadata.

Builder — no change needed

core/event/builder.go delegates to the same WithCorrelationID etc. options. No extra work.

Libraries — no new dependencies needed

The migration is pure Go stdlib (maps.Copy, slices.Clone, encoding/json). No new external libraries required. The existing go-branded-id and oklog/ulid handle ID types correctly with zero-value semantics.

Risks & Mitigations

Risk Likelihood Mitigation
JSON wire format change: "metadata":{} instead of absent key Confirmed Backward-compatible for json.Unmarshal. All storage tests use logical roundtrip (value assertions). Add omitempty to ID tags to avoid "correlationId":null.
Pebble stored data: existing events on disk have pointer-serialized format Medium Pebble is an embedded store for testing/development, not production. Existing data can be regenerated. If backward compat is needed, the json.Unmarshal handles both missing and {} correctly.
Breaking public API change: Event.Metadata() return type Low Pre-v1.0 — no stability guarantee. Compile error is a feature: forces consumers to remove nil checks.
Custom map nil-checks remain: md.Custom == nil still needed Confirmed Correct behavior. Nil map = "no custom fields". Nil struct = "impossible state" (eliminated by value type). This is the right boundary.
~120 bytes allocated per event always Low Negligible. []byte payload is always larger. Not in hot paths. Premature optimization.
WithMetadata merging semantics change: currently nil-assigns on first call Low New behavior always merges into existing (never-nil) metadata. Functionally identical — setting a field on an empty metadata vs replacing nil.
Net Effect

Remove ~65 lines of nil-check boilerplate across 24 files. Eliminate an impossible state. Simplify Metadata() getter from 15 lines to 3. Make the API honest — metadata is always present. Wire format change is backward-compatible.

Follow-up opportunities (NOT in scope)

  • Extract TracingMetadata — shared 4-field struct embedded in both event+command Metadata
  • OTEL trace ID enricher — ContextEnricher that extracts trace/span IDs from context.Context
  • ClientID as first-class field — promote from Custom map to typed Metadata field
  • Pebble double-serialization — optimize the marshal→unmarshal→re-marshal path for metadata
  • CommandBus + CommandOutbox — complete the command/event symmetry gap
