The Core Problem

143,676 lines of Markdown for 42,070 lines of Go (3.4:1 ratio). 923 LOC of dead ghost-bus code. 50 time.Sleep calls in tests. 76 planning docs — most stale. The library works, but the noise drowns the signal for every consumer and contributor.

Pareto Strategy

1% effort → 51% value: Delete docs, fix test flakiness, reconcile status files. These are non-breaking, shipable on master today.
4% effort → 64% value: v3 branch — delete ghost code, move modules, tighten types.
20% effort → 80% value: Transport adapters (gRPC/NATS/Redis), read-model indexes.

01Findings — What's Broken or Missing

Critical

Documentation bloat: 3.4:1 Markdown-to-Go ratio

612 .md files / 76 planning docs / 143K LOC

Stale planning docs from May/June confuse every new reader. Consumers cannot find the signal. This is the #1 trust killer — worse than any code issue.

Fix Prune to <1.5:1 ratio. Archive or delete 50+ stale docs. Create INDEX.md for active plans.
Critical

923 LOC of dead ghost-bus code

memory/bus.go (250), memory/command_bus.go (150), storage/pg_bus.go (265), event/reactive*.go (258)

Deprecated in v2 but still present. Every consumer sees two bus implementations and must figure out which to use. Watermill EventBus is the replacement and is already wired into all 4 stack presets.

Fix v3: delete all ghost bus files + their tests. watermill.EventBus is the only bus.
Important

50 time.Sleep calls in tests (flaky test risk)

27 test files across memory/, integration/, example/, storage/

Sleep-based synchronization is inherently flaky. Round 3 already hit this: migrating to async GoChannel broke TestFullCommandLifecycle. Fixed with waitForStatus() — but 49 more sleeps remain.

Important

event.Version is int, not uint64 (156 files)

event/event.go type definition + 155 consumers

Negative versions were never valid. The int type allows impossible states. This is the most invasive v3 change but the highest type-safety payoff.
