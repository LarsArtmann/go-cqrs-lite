## 0. Context — Where we are

The **Bundle layer is functionally complete and tested** (23 commits, 8 new modules, ~5,500 lines). A consumer can now write:

```go
bundle, _ := cqrssqlite.New("file:cqrs.db")
repo := stack.Repository[State](bundle, decider, "Order")
rms := stack.ReadModel[Todo, TodoID](bundle, "todos")  // readmodel.Store[T,K] over kv.Store
```

…without ever importing a backend. That's the overarching goal achieved _structurally_.

**What's not done (honest):**

- 21 lint violations shipped (readmodel 14, pebble 7) — undermines the "trustworthy modules" quality gate.
- No `CHANGELOG.md` for v2.7.0 — the release has no release notes.
- API stability golden file is stale (new exports in `command`, `query`, `pebble`, `snapshot`, `readmodel`).
- **SQLite & Postgres presets lose all read models on restart** (they use `kv.MemStore`). This is the single most surprising behaviour for a consumer who picked a _persistent_ preset.
- Postgres preset tests are **silently skipped in CI** — CI sets `DATABASE_URL` but the tests check `POSTGRES_TEST_DSN` (env var mismatch). The container runs but no preset test touches it.

## 1. The key architecture decision (made, with reasoning)

> **Decision: BUILD a SQL-backed `kv.Store` adapter. Do NOT just document the gap.**

Two options were on the table (from the status report):

| Option                                                                                                                                   | Pro                                                                                                                                                      | Con                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Document** that SQL presets have ephemeral read models (rebuild by projection replay); recommend Pebble for persistent read models. | Zero new code. Respects YAGNI.                                                                                                                           | Makes SQL presets second-class. "Pick SQLite, lose read models on restart" is surprising/buggy-shaped behaviour that destroys consumer trust. |
| **B. Build** `kv.Store` over SQL (reuse `storage/sql` dialect + `RunInTx`).                                                              | Coherent: `readmodel.Backend = kv.Store` for _every_ preset, uniform persistence. `pebble.KVAdapter` is the existing precedent — this is the SQL analog. | New abstraction (~250 LOC + tests). Iterator via `sql.Rows` is fiddly. Verschlimmbessern risk if rushed.                                      |

**Rationale for B:** `readmodel.Backend` is _defined_ as `kv.Store`. Leaving SQL without an implementation makes two of the four flagship presets (SQLite, Postgres) second-class. A consumer who picks `cqrssqlite.New(...)` reasonably expects persistence — losing read models on restart is the kind of "lies in the name" failure the project philosophy explicitly forbids. The interface is small (`Get/Set/Has/Delete/NewIterator/Batch/Closer`), maps cleanly to one SQL table + transactions, and has a proven sibling in `pebble.KVAdapter`. The risk is bounded and testable. **Build it.**

**Postgres LISTEN/NOTIFY bus** is the _only_ item I will approach with a kill-switch: if it turns into a rabbit-hole (concurrency, 8KB NOTIFY limit, re-fetch semantics), I ship a clean documented stub and defer the full version to v2.8.0 rather than ship something half-correct.

## 7. Guardrails (anti-verschlimmbessern)

1. **Never change a public type signature to satisfy a linter.** Fix the call site, not the API.
2. **SQL kv.Store reuses `storage/sql`** — do NOT invent a second dialect/tx layer.
3. **LISTEN/NOTIFY has a kill-switch** — ship a clean stub + ADR rather than a fragile impl.
4. **No new deps without budget review** (`scripts/check-module-layers.sh`).
5. **Every commit leaves build+test+lint green.** If a fix is risky, isolate it in its own commit.
6. **Don't touch unrelated modules.** The gopls "go mod tidy" warnings are pre-existing multi-module false positives (ADR-0007) — out of scope unless `go mod tidy` in that module actually changes something useful.
