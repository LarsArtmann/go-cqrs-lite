02Pareto Breakdown

The 1% → 51% of the result: consumer unblocking (Wave 0 + Wave 1)

#25 close, #26 retract, #21 finish + release. This is every issue where a consumer is actively blocked or poisoned: go-localsync loses command causation on every bus hop (#21, half-fixed but unreleased), any consumer pinning stack/postgres v4.2.0 gets an unbuildable graph with no upstream signal that the version is poison (#26), and #25 is a free close that shrinks the queue. One coordinated release wave carries both real changes: watermill/v4.7.0 + stack/postgres/v4.4.2. ~4.5h.

The 4% → 64%: linter trust (Wave 2)

#42 + #43. cqrs-lint fires findings on repos that do not import go-cqrs-lite at all (#42 — every BuildFlow non-consumer run) and flags TRUE doc sentences as stale version claims (#43 — false warnings on every run). Both are small, test-contained, release-independent, and they stop the tool from training users to ignore its output. ~4h. Cumulative: ~8.5h for 5 of 9 remaining issues.

The 20% → 80%: consumer-facing features (Wave 3)

#32, #35, #27, #28. The feature asks: O(1) event lookup for every SQL deployment (#32), request-attributed events with zero consumer glue (#35), a machine-readable latest-tag manifest that makes consumer sweeps one jq away (#27), and the documented upgrade pattern with an explicitly blessed tool (#28). Each maps 1:1 to an existing repo capability, so none is speculative. ~9h.

The rest → 100%: structural tail (Wave 4)

#36 (stack/metaengine split) is the only change that moves exported surface, so it goes last with the full new-module gate procedure (go.work, api-stability golden, module layers, cqrs-lint catalog) plus a hermetic consumer probe proving a plain-stack go.mod resolves without metaengine. Plus one optional, owner-gated extra: #27’s stale-module CI annotation (ask item 3). ~3h.

06Verification & Risks

Release mechanics (T07) source scripts/go-env.sh before every go command; #verify runs exclusively (never beside integration suites); release scripts take the machine-local verify-lock; wait for a clean tree before tagging (auto-commit daemon absorbs mid-phase edits — commit at phase boundaries).
Watch out: api-surface changes T14/T17/T25 add or move exported symbols → the api-stability golden must be regenerated in the same edit (cd cmd/api-stability && GOWORK=off go run . --update), and #36 additionally touches all four new-module gates (go.work, api-stability maps, check-module-layers, cqrs-lint catalog).
Watch out: wire-protocol compatibility (#21) New metadata keys must be write-only-when-non-zero and the read side must tolerate absence — in-flight messages from v4.5.x producers predate the keys. The parse side already tolerates missing fields; the compat tests (F012–F014) pin this.
Watch out: D005 regression risk (#43) The fix must keep detecting TRUE stale claims (existing TestD005_DetectsStaleDocVersion stays green). Chosen direction: positional attachment + skip multi-version lines (under-report instead of mis-report). The issue offers a PR; either take it or implement in-repo — the reporter asked which direction is preferred.
Watch out: #36 is the only surface move Deprecated forwarders keep v4.x compatibility (removal at v5 per repo convention). If the hermetic probe (F085) cannot prove a metaengine-free graph, stop and re-scope — do not ship a split that does not decouple.
