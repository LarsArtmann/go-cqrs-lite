Pareto Execution Plan

The 20% that delivers 80%.

Comprehensive execution plan for go-cqrs-lite, grounded in a live per-module isolation audit. The audit reshaped the plan: what looked like one broken module (signing) turned out to be 11 of 44 — all from one root cause. Below: the Pareto tiers, a medium-granularity plan, a fine breakdown (≤12 min/task), and an execution graph.

00Context & The Discovery

Headline finding (verified live): A full GOWORK=off go build ./... audit of all 44 modules found 11 fail per-module isolation. Root cause: the projection/v3 module — which TODO_LIST.md claims was "deleted" but is alive, in go.work, and implemented by the brand-new relational + graph tiers — is missing require directives across its consumers. The workspace hides it; per-module builds expose it. This is the same class of bug as signing (fixed earlier today), at 10× scale.

01Pareto Breakdown

1% effort → 51% value  P1–P3

Fix the isolation break, then make it impossible to recur. Three tasks: (1) add the missing projection/v3 requires to 11 modules, (2) add a CI gate that runs GOWORK=off for every module and fails on any break, (3) add a CI gate that fails on placeholder doc.go stubs. Together these turn "the library builds in isolation" from a claim into a guarantee.

4% effort → 64% value  P4–P7

Fix the documentation lies and validate the new tiers. The TODO_LIST claims projection/ was deleted — it wasn't; correct it. Add a doc-examples-compile check (catches the pebble/grpc.Dial drift class found in the doc.go review). Write integration tests for the two newest tiers (RelationalProjection, GraphProjection) that currently have no consumer validation.

20% effort → 80% value  P8–P15

Coverage, ergonomics, and hygiene. Raise coverage on the three lagging modules (graph, kv, codec). Honest labelling for stack/postgres (0% local is misleading). Spike the Drainer interface for real shutdown drain semantics. Surface Pebble backup + archive old reports. Fix the two known gopls infos.
