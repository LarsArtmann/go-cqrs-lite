★The TOP Things We NEED to Fix

Distilled to the absolute essentials. If you fix nothing else, fix these.

1

CBOR Canonical NaN — Fuzz Failure in CI

Critical Tasks 1.1–1.6 · ~57 min · codec/codec_fuzz_test.go:336 · seed 5f72aef8648194a5
The canonical encoder produces non-deterministic output for NaN map keys. This violates the canonical contract and fails the fuzz test in CI. Either reject NaN keys at encode time, or implement byte-level tiebreaking. Also investigate why it passes in isolation but fails in the full suite (likely init race or shared state).
2

Deep-Copy *eventOptions on Clone — Last v3 Blocker

Medium Tasks 1.7–1.9 · ~30 min · event/builder.go
The options pointer is shallow-copied on Clone, meaning a consumer can mutate the original event's metadata by modifying the clone's options. This is the last remaining [v3] breaking change. Once fixed, v3.0.0 is feature-complete with zero known breaking items left.
3

V3_MIGRATION.md Accuracy Pass — Broken Examples Ship to Consumers

Medium Tasks 1.13–1.15 · ~30 min · docs/migration/V3_MIGRATION.md
The migration guide references memory.NewMemoryBus() (deprecated) and lists pg_bus as ghost code (it's real). Consumers following this guide will hit compile errors. The last brutal review flagged stale entries.
4

PgxListener Concurrent-Close Race — Production Concurrency Bug

High Tasks 2.1–2.4 · ~40 min · stack/postgres/pg_listener.go:39-60
The PgxListener has a known concurrent-Close race condition. The code has a design rationale comment claiming channel-based synchronization makes it safe-by-design, but no -race test verifies this claim. Either confirm safe-by-design with a passing race test, or add a mutex guard.
5

Metadata Round-Trip Property Tests — Proven Bug Pattern

Medium Tasks 2.6–2.8 · ~32 min · event/, command/, query/
The Metadata Merge map-aliasing bug (found and fixed last session) proves these types need property-based testing. A rapid generator that creates arbitrary Metadata, marshals it, unmarshals it, and checks equality would have caught the Merge bug before it shipped. Three modules, same pattern.
6

Consumer Trust Smoke Test — "Would a Consumer Trust This?"

Medium Tasks 2.12–2.15 · ~46 min · new integration test
The quality gate for every module is "would a consumer trust this enough to import it?" — but no test verifies this from outside the repo. A smoke test that imports every module and constructs each of the 4 presets would catch broken constructors, missing exports, and import graph issues that per-module tests can't see.

The v3.0.0 Decision

Tag now or hold? All 10 v3 breaking changes are shipped and tested. The only remaining work is Tier 1 (bugs + docs, ~3h). I recommend: do Tier 1 tasks 1.1–1.16 (fix bugs + docs + verify), THEN tag v3.0.0 (task 1.17). Holding costs momentum; the bugs are real but small. The half-applied ADR limbo was worse than a clean break.
