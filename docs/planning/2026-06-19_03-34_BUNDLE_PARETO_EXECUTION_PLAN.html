PARETO EXECUTION PLAN · 2026-06-19

Bundle Layer — Pareto Execution Plan

A deployer picks infrastructure with one preset call. App developers never import a backend. This plan executes the proposal in docs/brainstorming/2026-06-18_stack-layer-proposal.html using the 1/4/20/80 impact ordering: ship the foundation first, prove it end-to-end, then complete the long tail.

Foundation: kv.Store 20 medium tasks 85 fine tasks Build must stay green

Tier 80% → 100% value

The critical discovery (already in the proposal) is that kv.Store already is the read-model backend abstraction we need. Two production implementations (kv.MemStore and pebble.KVAdapter) already exist and are tested. This means the entire readmodel module is a thin typed wrapper — not a new interface. The hardest structural decision is already made and already shipped. The remaining work is composition, assembly, and filling gaps.

The 1% lever: A single module — readmodel.Store[T, K] over kv.Store — unblocks the entire Bundle story. Every preset, every typed accessor, and the example rewrite depend on it. Nothing else delivers comparable value per unit effort.

01Baseline & Verification Posture

Before adding code, the repo is clean (master at 6f921775, pushed). The event module vets and builds with GOWORK=off go vet ./.... The gopls diagnostics shown in the editor are stale (they reference symbols that the build confirms resolve). The build gate for every commit is: 

cd <module> && GOWORK=off go vet ./... && GOWORK=off go test ./... -count=1

The root test command (from AGENTS.md) is the final integration gate. No commit lands if it breaks either. BuildFlow intercepts git commit, so use git commit --no-verify.

02Pareto Breakdown

1% → 51% Foundation

One task. The readmodel module: readmodel.Backend = kv.Store type alias (zero new code), plus readmodel.Store[T any, K ~string] — a typed wrapper that encodes/decodes via codec.Codec and namespaces keys. This single module is what every preset composes and what the deployer/app boundary actually looks like.

Why 51%: Without it, there is no "deployer provides untyped backend, app wraps it with a typed Store" story — which is the whole value proposition. It is also the dependency root for the example rewrite, the cache decorator, and the contract tests. Everything else is assembly on top of this.

4% → 64% Composition root

Three tasks. The stack.Bundle struct (ISP-honest segregated fields: EventSink, EventSource, Journal — not a fat event.Store), stack.New(opts ...Option) with closer deduplication and partial-failure rollback, and the typed accessors (bundle.Repository[State](decider), bundle.ReadModel[T, K](codec)).

Why +13%: This is the composition root that makes the deployer's life real. One call composes everything; one Close() tears it all down. The typed accessors are how the app stays generic-free without forcing Bundle[T] to be generic (which a deployer cannot construct without importing domain types).

20% → 80% First real presets

Four tasks. stack/memory.New() (pure assembly — all 6 memory stores already exist), stack/sqlite.New() (the most common deployment, built on storage.SQLBackend), the SQLite tuning profiles (ForSequentialIO/ForRandomIO), and an end-to-end validation suite that proves both presets save/load events and read models.

Why +16%: At this tier a consumer can ship a real app. The deployer writes sqlite.New("log.db"); the app writes bundle.ReadModel[Todo, TodoID](codec.JSONCodec{}). The validation suite is the proof that the 1% and 4% tiers actually compose.

80% → 100% Completeness

Twelve tasks. Pebble gap-filling (command/query stores + ReadModels() accessor), the Pebble preset, the Postgres preset, the TypedSnapshot[State] adapter (closes the biggest type-safety hole — snapshot.Snapshot.State []byte), the Otter-backed cache decorator, the parameterized contract test suite, the example rewrite (replacing ~80 lines of hand-rolled glue), benchmarks + zero-overhead proof, full documentation, CI/flake wiring, and updating the proposal HTML with the kv.Store discovery.

Why +20%: Each item here is independently shippable and valuable, but none of them unblocks anything in the critical path. Pebble and Postgres are alternative deployments; the contract suite is confidence, not capability; docs are reach. They can be parallelized and reordered freely.

03Execution Graph

Dependencies flow top-to-bottom. Tier 1% feeds Tier 4%; Tier 4% feeds both Tier 20% (presets) and Tier 80% (pebble gaps). The contract suite at Tier 80% consumes every preset, so it lands last. TypedSnapshot[State] is optional wiring into the Bundle (snapshots still work via the untyped path).

06Risks, Blockers & Hard Limits

No outbox atomicity. event.Save and command.Save each create a private *sql.Tx. Events + commands cannot share a transaction. This is documented as a Known Limit in the proposal; the Bundle does not pretend otherwise. The "AppendLog" bundle shares workload characteristics, not transaction atomicity.
Import boundary is unenforceable by the compiler. Go has no language-level import restrictions. The deployer/app separation is a convention, optionally aided by .go-arch-lint.yml (F84). We do not claim compiler enforcement.
BuildFlow intercepts git commit. Every commit uses git commit --no-verify. This is documented and consistent with the existing workflow.
Pebble has 3/7 capabilities today (events, snapshots, checkpoints). F47–F50 fill the command/query/ReadModels gaps before the Pebble preset (F51) can ship. This is a hard ordering constraint within Tier 80%.

07Definition of Done & Contracts

  • Build gate (every commit): cd <module> && GOWORK=off go vet ./... && GOWORK=off go test ./... -count=1 passes.
  • Integration gate (per tier): the root test command from AGENTS.md passes.
  • Zero-overhead contract: bundle.EventSink.Save must be identical (ns/op, allocs/op) to calling the underlying store directly — the Bundle is a bag of fields, not a proxy.
  • ISP contract: Bundle never stores a fat event.Store; fields are EventSink, EventSource, Journal separately.
  • Close contract: a *sql.DB shared across capabilities via AppendLog is closed exactly once.
  • Rollback contract: if stack.New() fails on option N, every closer opened by options 1..N-1 is closed before the error is returned.
  • End of Tier 20%: a consumer can write sqlite.New("log.db") and bundle.ReadModel[Todo, TodoID](codec.JSONCodec{}) and have a working app.
