## G) Top #1 Question I Cannot Figure Out Myself

**Should the middleware 3× deduplication use Go generics or code generation?**

The core problem: command middleware is `func(Handler) Handler` where `Handler = func(ctx, Command) error`, event middleware is `func(Handler) Handler` where `Handler = func(ctx, Event) error`, and query middleware is `func(Handler) Handler` where `Handler = func(ctx, Query) (any, error)`. The return type differs (`error` vs `(any, error)`), which means a single generic `Middleware[H, M]` cannot unify all three. Options:

- **Option A**: Generic per pair — `Retry[H any](config) func(H) H` works for command+event (same return shape), but query needs a separate `QueryRetry`. Still cuts duplication from 3× to 2× per concern.
- **Option B**: `any` return type — unify all as `func(any) (any, error)`, lose type safety.
- **Option C**: Code generation (go generate) — template the middleware per type. Zero duplication, but adds build step.
- **Option D**: Accept the 3× pattern — it's explicit, no magic, and each file is small (~30 lines per function).

Which approach do you want? This decision blocks the #1 priority item.
