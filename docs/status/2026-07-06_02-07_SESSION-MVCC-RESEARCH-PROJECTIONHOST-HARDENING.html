MaxOpenConns=1 research — definitive answer

storage/sqlite_helpers.go, TODO_LIST.md

Researched Turso's concurrency model via official docs and blog posts. Verdict: MaxOpenConns=1 is still the correct default. The Turso Database engine defaults to WAL mode, which — like SQLite WAL — serializes writes through a single exclusive lock. MVCC mode exists but is experimental, requires BEGIN CONCURRENT (not BEGIN), and needs application-level conflict-retry logic. Not actionable today.

Delivered Comprehensive comment on ConfigureTursoPool explaining WAL-mode rationale, read-concurrency tradeoff, and MVCC path forward. TODO_LIST.md entry with [BLOCKED UPSTREAM] tag and unblock criteria.

07#1 Question I Cannot Figure Out

Is the M1 checkpoint-failure behavior change safe for existing consumers?

The concurrent session changed processLive to return an error when checkpoint Save fails (previously: logger.Warn + continue). This is the correct fix for silent data loss — but it changes a runtime contract. A consumer whose checkpoint store is flaky (e.g. a remote Postgres with intermittent connectivity) will now see their projection worker die and restart on every checkpoint failure, instead of logging and moving on.

I cannot determine whether this is a breaking change for existing consumers without:

  • Knowing whether any consumer actually depends on the "swallow + continue" behavior
  • Understanding whether the restart loop (M1 error → backoff → restart → replay from last checkpoint → same failure) is better or worse than the old behavior for flaky checkpoint stores
  • Whether there should be a WithLenientCheckpoint option to preserve the old behavior for consumers who prefer availability over exactly-once checkpointing
Why this matters This is a library, not an app. Changing runtime contracts without an option flag or migration path violates the "would a consumer trust this enough to import it?" quality gate. The fix may be correct for most consumers but hostile to consumers with eventually-consistent checkpoint stores.
