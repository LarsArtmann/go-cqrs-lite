05What We Should Improve

The verify gate takes 4-6 minutes and has no checkpointing

When nix run .#verify hits a flaky test, it stops — all remaining phases (lint, arch, duplication, coverage, API stability, doc check) are skipped. This wastes the 4 minutes already spent. The gate should either (a) continue to the next phase on test failure (collecting all failures), or (b) have a nix run .#verify-remaining that picks up after the last failure.

Impact: 4-6 minutes wasted every time a flaky test triggers.

Fix: Change the && chain in flake.nix verify script to collect failures and continue. Or add || true to the Test phase and report at the end.

Timing-sensitive tests should use testutil.RaceEnabled thresholds

The TestLatencyMeasuredFromRealTraffic test uses a hardcoded 50*time.Millisecond bound. Under -race (which inflates timing 5-10x), this is too tight. The project already has the testutil.RaceEnabled pattern for this exact problem — it should be applied here.

Impact: Flaky verify gate runs. Wastes time investigating "failures" that are just timing jitter.

Fix: Change the assertion to use a relaxed bound under race: bound := 50*time.Millisecond; if testutil.RaceEnabled { bound = 150*time.Millisecond }.

database/sql is now a production dependency of metaengine core

metaengine.SQLExec references sql.Result and *sql.Row. This means the core planner package (which non-SQL engines like Memory, Badger, Dgraph import) now transitively depends on database/sql. This is stdlib (no external dep cost), but conceptually couples the planner to SQL semantics. The nix run .#check-arch gate passes, so it's within budget.

Impact: Architectural coupling. Non-SQL engine modules pull in SQL types they don't use.

Fix: Consider moving SQLExec to a metaengine/sqltypes/ subpackage. Low priority since it's stdlib and the dep budget passes.

The "stale GREEN" anti-pattern is now fixed but was recurring for 4+ sessions

Prior sessions (07-25 through 08-09) claimed verify was GREEN based on previous session runs without re-running it. This session actually ran the full gate and confirmed it passes. The lesson is now documented in AGENTS.md but the temptation to skip the 4-minute gate remains.

Fix: Always run nix run .#verify (or at minimum the specific phases for changed modules) before claiming GREEN. The gate is the ONLY source of truth.
