DTotally Fucked Up!

The painful parts. Honest assessment of what went wrong.

Critical ROADMAP.md lies about open work

The roadmap has 5+ checkboxes marked [ ] (open) that are actually DONE. This is the worst kind of doc drift — it makes the roadmap untrustworthy and hides real accomplishments.

  • "Code generator (cqrs-gen) v2 with struct tag scanning" [ ] → DONE (shipped v2.6.0, marked [x] in TODO_LIST)
  • "Event schema registry with validation middleware" [ ] → DONE (schema.Validator, ADR-0017, shipped v2.6.0)
  • "Custom metrics exporter (Prometheus format)" [ ] → DONE (entire prometheus/ module shipped v2.6.0!)
  • "Streaming event reads without materializing full slice" listed as open in Long-Term [ ] → interfaces DONE in v2.6.0 (only store impls remain)
  • "Distributed tracing span propagation" [ ] → mostly done (OTel enricher + baggage propagation shipped)
Impact

A reader trusting the roadmap would think 5 major features are unbuilt. They're shipped. This actively misleads planning and makes the project look less complete than it is.

Critical Design mistake shipped to a tagged release

pebble.DeleteEventsBefore shipped in v2.5.0 — a method that automatically deletes events based on age. This directly contradicts the core event-sourcing principle that events are immutable truth. Automatic event deletion is a footgun in an event sourcing library.

It was removed in v2.6.0 before any consumer could depend on it (24h window), but it should never have passed review. This is a design-judgment gap, not a typo.

Root cause

Retention/cleanup features feel reasonable in isolation but contradict the library's foundational invariant. No pre-merge check asks "does this violate event sourcing immutability?"

High ./... from workspace root is unreliable

Running go test ./... from the workspace root only tests 1 package (the root module), not all workspace modules. The canonical test command in AGENTS.md must enumerate all 24 module paths explicitly. This is fragile — adding a new module means remembering to update the command, or tests silently don't run.

Pre-merge invariant checklist

No design mistake like DeleteEventsBefore should reach a tag. Add a review checklist item: "Does this feature violate any core principle (immutability, no-delete, tombstone-only)?"

Workspace test command fragility

The explicit module-enumeration in the test command will silently skip new modules if forgotten. Consider a go.work-aware test wrapper or a generated command.

Deferred breaking-change debt is growing

5 v3-deferred + 2 v4-deferred breaking changes are accumulating (io.Closer removal, TransactionID, core immutability, HTTP-code move, query.Handler any-return, catalog splits). No trigger criteria for when to cut v3.
