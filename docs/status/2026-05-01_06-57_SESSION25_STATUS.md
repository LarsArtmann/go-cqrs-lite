## E) WHAT WE SHOULD IMPROVE 🔧

### Code Quality

1. **catalog/ root package at 72%** — lowest coverage in the project. Schema reflection and registry paths need more tests.
2. **NewEvent() version parameter** — Should accept `event.Version` not `int`. Currently inconsistent: `Version()` returns branded type but `NewEvent` takes raw `int`. All 131+ callers would need updating.
3. **D2 exporter lint** — 4 issues (exhaustruct, golines, wsl_v5). Quick fix.
4. **testhelpers coverage reports as 0%** — These are test utilities, not production code. Coverage tool counts them but they have no tests. Could exclude from reports.

### Architecture

5. **Projection checkpoint store should be SQL-backed** — `MemoryCheckpointStore` is fine for tests, but any real deployment needs persistence. Should be in `storage/` module.
6. **Event type safety** — Events are currently `interface{}` payloads (`[]byte`). A typed event registry would give compile-time safety. Could use Go generics.
7. **Outbox pattern incomplete** — `OutboxPublisher` exists but there's no background relay/polling mechanism. Just publishes to bus. Real outbox needs a relay.
8. **No transaction boundary abstraction** — `EventSourcedRepository.Save()` does store+bus, but no transactional boundary. Would need `BeginTx` abstraction for SQL.

### Developer Experience

9. **example/user not in CI** — Could rot without detection.
10. **No CONTRIBUTING.md updates** for the new D2 exporter or Version() change.
11. **No migration guide** for the Version() breaking change. Consumers need clear upgrade path.

### Testing

12. **No integration tests against real PostgreSQL** — All storage tests use go-sqlmock. Need at least one test with real PG for confidence.
13. **No race detector in CI** — `nix run .#test-race` exists but not in ci.yml.
14. **No benchmark tracking** — Benchmarks exist but aren't compared across commits.
