## Questions / Blockers

### Top #1 Question

**Should `command.Dispatcher` and `query.Dispatcher` be deduplicated into a shared generic helper?**

The two dispatchers are ~90% identical — same structure, same `Register`/`Dispatch`/`Use`/`Close` pattern. The only difference:
- `command.Handler = func(ctx, Command) error` → returns `error`
- `query.Handler = func(ctx, Query) (any, error)` → returns `(any, error)`

Options:
1. **Extract shared helper** in `dispatcher/` — generic over handler type, reducing duplication
2. **Leave as-is** — the duplication gives each module clear ownership and type safety
3. **Code-generate** from a template — ensures consistency without shared code

This is an architectural decision that affects the public API surface. What's your preference?

### Decision: Leave as-is

**Answer:** No — both dispatchers stay independent.

**Rationale:** The duplication gives each module clear ownership, type safety, and freedom to diverge. The `query` side has additional `RegisterTyped`/`DispatchTyped` helpers that don't apply to `command`. Extracting a shared generic helper would couple two modules that serve different CQRS concerns for marginal code savings.
