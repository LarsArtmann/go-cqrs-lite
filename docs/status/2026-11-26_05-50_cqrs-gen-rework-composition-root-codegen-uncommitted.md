## The two questions, answered from evidence

### 1. Why did the README examples not use go-branded-id?

Not a one-file slip, and not chronology (branded IDs landed 2026-04-25, a month before cqrs-gen
was created on 2026-05-26):

1. **House policy.** All four examples that declare event payloads keep ID fields as plain
   `string`, each with a written rationale and a `//branching-flow:ignore strong-id` directive:
   "payloads, read models, and queries are serialized data, not domain handles; brand at the
   boundary" (`example/goal-shaped-app/domain.go`, `example/metaengine-quickstart/main.go`,
   `example/mesh-demo/orders.go`, `example/taskmanager/events.go`). The cqrs-gen README copied
   that style.
2. **One real technical leg.** `catalog.SchemaFromType` rendered a branded-ID field as
   `{"type":"object"}` although the wire form is a string (probe: `UserID id.StreamID` → `"type":
   "object"`; plain `string` → `"type": "string"`). Typed payloads would have produced wrong
   AsyncAPI/OpenAPI schemas. Fixed this session (a6). The codec path was never the problem: JSON,
   CBOR and CBORCompact all round-trip `id.StreamID` as a plain string.
3. **No gate and no reason to care.** The tool is field-blind (it read only the marker string and
   the struct name), had no dependency on go-cqrs-lite (go-branded-id was `// indirect`), and no
   gate checks README example types (doc-check resolves qualified symbols, the compile harness
   covers `recipes.md` only, cqrs-lint does not lint markdown).

### 2. How can cqrs-gen deliver "100% of the benefits" to 99% of projects?

What the fleet actually does (63 repos requiring go-cqrs-lite in a `go.mod`, probed 01:10):

| Probe                                           | Adoption                                                                                           |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `command/v4` imported                           | 61/63 97%                                                                                          |
| `decider/v4`, `errorfamily`, branded IDs        | 81%, 79%, 79%                                                                                      |
| `metaengine/v4`                                 | 47/63 75%                                                                                          |
| `system.New` / `system.RegisterCommand`         | 59% / 49%                                                                                          |
| `cqrs-lint` config or invocation                | 52%                                                                                                |
| hand-written `system.Execute` Op wrappers       | 29 repos; 167 sites in the 16 largest                                                              |
| `command.RegisterTyped` / `query.RegisterTyped` | 19/63 30%                                                                                          |
| `systemscenario`                                | 38%                                                                                                |
| `catalog` declarations                          | 33% (373 `catalog.(Event                                                                           |
| OTel / scheduling / `ServeSSE` / `deriver`      | 25% / 21% / 19% / 8%                                                                               |
| benchkit                                        | 3%                                                                                                 |
| **cqrs-gen (markers, output, invocation)**      | **0/63** (three probe hits were a nested checkout, a test-only marker, and a lint-decline comment) |

So the honest answer has two halves:

- **The generator was a ghost.** Its documented invocations all failed, and it generated code for
  the seam ADR-0123 retires for new apps. Fixed in the working tree (a1–a5).
- **A generator can only move the wiring-shaped benefits.** It now removes registration boilerplate
  and generates catalog declarations. OTel, SSE, timers, sagas, bench and systemscenario adoption
  are not generator-shaped; they need composition-root defaults, the service template, and the
  cqrs-lint scorecard. "99% of projects" has no metric yet (e3, f21–f22).

Standing decision respected: ADR-0151 parks fold codegen behind an evidence gate; nothing here
generates folds. The fleet census found no consumer blocked on the Evolution declaration, so the
gate stays closed.
