## e) WHAT WE SHOULD IMPROVE IN THIS PROJECT

1. **Measurement-API-semantics checklist before writing size benches**: file size ≠ data size (mmap quantization, WALs, preallocation, sparse files). Every future storage bench should start by answering "what exactly does this number count?" — for pebble: SSTables vs WAL vs MANIFEST; for bbolt: mmap size vs page high-water mark; for SQLite: freelist vs VACUUM state.
2. **No estimated numbers in provenance chains**: if a doc states a byte count, it should be measured (`len(keycodec.MultimapKey(...))` is a one-liner) or hedged as "~45-ish, varies with key length". Fix the five "~41" sites.
3. **Bench evidence should be reproducible from the repo, not /tmp**: either check in the median script (a small `//go:build ignore` program next to the benches avoids the module-home problem entirely — I missed this option) or have the bench itself emit medians across `-count`.
4. **Margin guards, not just winner guards**: the matrix test should fail if any non-tight cell's margin falls under a floor, so constant drift degrades loudly instead of silently toward coin-flips.
5. **AGENTS.md gotcha discipline**: session-discovered footguns go into §Gotchas immediately (this session: pebble-flush, bbolt-mmap-size, test-only-dep auto-exemption).
6. **Decide the canonical pebble storage configuration** (flush-only vs compacted) and encode it in the bench; a `db.Compact()` call is ~3 lines.
7. **Per-file size breakdown in the storage bench output** so future readers can audit what the ratio counts without re-deriving it.
