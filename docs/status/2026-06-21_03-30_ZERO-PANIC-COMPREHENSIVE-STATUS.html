GTop Question

Should production nil-parameter guards and package-init panics also be eliminated?

The codebase has ~20 remaining panic() calls in production code. They fall into three categories:

  • Nil-param guards (7 pebble constructors) — panic("pebble: NewStore called with nil db")
  • Package init (4 codec/pebble CBOR mode creations) — panic("codec: failed to create CBOR mode")
  • Arithmetic invariants (5 event/types.go) — panic("Version.Decrement() on zero version")

Converting nil-param guards to (value, error) returns is a breaking API change. Package init panics are standard Go (like regexp.MustCompile in vars). Arithmetic panics are "make impossible states unrepresentable" design.

The question Do you want these converted too, or was the directive specifically about Must-named test helpers? Converting nil-param guards means changing every pebble.New*(db) signature.
