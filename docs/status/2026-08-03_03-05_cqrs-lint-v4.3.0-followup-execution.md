## d) TOTALLY FUCKED UP (nothing — but here's what we caught and fixed)

**Nothing was fucked up.** But two bugs were discovered and fixed during testing:

### Bug 1: `c008-ignore-fields` was NOT case-insensitive despite documentation claiming it was

- **Root cause:** `matchesAny(lowerName, ctx.RulesConfig.IgnoreFloatFields)` — the field name was lowercased but the config entries were NOT. So `"CostUSD"` field → `"costusd"` lowercased, but config `"costusd"` matched while config `"COSTUSD"` didn't.
- **Fix:** Added `lowerStrings()` helper, applied to config entries before comparison.
- **Test:** `TestC008_ConfigIgnoreFieldsCaseInsensitive` pins this.

### Bug 2: `ListenAndServeTLS` / `tls.Listen` / `net.Listen` did NOT set `HasServer=true`

- **Root cause:** Only `ListenAndServe` and `Serve` triggered server detection. The prior session's TLS fix gated the TLS signal correctly but didn't add these methods to the server-detection path. A project using `tls.Listen` or `ListenAndServeTLS` would not be detected as a server at all.
- **Fix:** Added `ListenAndServeTLS` to the unconditional server methods, and `Listen`/`NewListener` gated on `tls` or `net` package.
- **Test:** Three tests pin this (`TestDetectFeatures_TLSListenDetectsTLS`, `TestDetectFeatures_NetListenNotTLS`, `TestDetectFeatures_ListenAndServeTLSDetectsTLS`).

### What we did NOT fuck up but could have

- **The v4.3.0 tag is on `e350355b`** — a PRIOR session's commit. All 4 new commits from this session are untagged. If we want consumers to get the new fixes, a new tag (v4.4.0) would be needed. But the plan assumed v4.3.0 was the release and these were follow-up improvements.
- **The auto-commit daemon committed work mid-session** (4 commits), which means the git diff was clean when the status report was requested. This is expected behavior per AGENTS.md.

### Design issues

7. **The `routingMethods` set in e016.go is incomplete and will need maintenance** — I added 15 method names (`HandleFunc`, `Handle`, `Mount`, `Get`, `Post`, etc.) but there are dozens more router frameworks (`chi`, `gin`, `echo`, `fiber`, `gorilla`, `stdlib`). Missing one means a false positive. A more robust approach would be to match any method whose first arg is a string literal starting with `/`.

8. **The `versionVerbose()` function hardcodes the module path** — `"github.com/larsartmann/go-cqrs-lite/cmd/cqrs-lint"`. If the module path ever changes, this string lies. Should use `runtime/debug.ReadBuildInfo()` to get the real module path. (But that requires `init()` time and adds complexity.)

9. **The `TestVersionMatchesLatestTag` test depends on git tags** — In CI environments without full git history (shallow clones), this test may fail or skip. The `testing.Short()` skip helps but doesn't cover all CI scenarios.

10. **The `changelog` subcommand shells out to `git log`** — If git is not on PATH (unlikely but possible in some containers), it fails with a cryptic error. Should check for git availability first.
