   already says this (calibration-gate.sh pattern: planted fixtures, subprocess
   re-invocation, golden message shapes, mutation testing). My four behaviors

   check "did the artifact actually change" before building multi-factor
   theories. The binary-drift finding was real; it just wasn't the bug.

   don't remember it.
4. **Verify the paths you wire, not just the code you write.** Two chain
   insertions into `#verify`/`#verify-fast` are still execution-untested;
   wiring is code.
5. **Annotation style for CONSUMER-facing rendered docs is a UX ruling, not a
   technical one.** In-fence `// skip-validate` shows up in rendered READMEs
   (metaengine, system, transport/grpc…). The audit endorsed it, and I followed
   — but the invisible `<!-- skip-validate -->` above the fence achieves the
   same gating without visible noise, at the cost of not living inside the
   code block. Owner should pick per audience.
6. **Gate dependencies want pins, not branches.** `?ref=master` + flake.lock
   works until an innocent `nix flake update` silently changes parse behavior
   under the baseline. A tag/rev pin (or an explicit documented bump ritual —
   now in gotchas) makes the coupling honest.
7. **Concurrent-session etiquette:** scope fmt/commits to your own files;
   check `git status` for foreign WIP before ANY tree-wide operation.
8. **Persist machine-readable evidence next to reports** (the 12-21 report's
   /tmp lesson — still unlearned repo-wide: my session's JSON runs also live
   only in /tmp).

   claims-checklist exists precisely because humans (me) round-trip numbers
