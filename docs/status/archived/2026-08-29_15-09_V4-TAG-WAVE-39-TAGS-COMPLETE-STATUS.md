## e) WHAT WE SHOULD IMPROVE

1. **Release waves should be manifest-driven.** Today: ~40 hand-driven script invocations, 4 hand-written pin-bump commits, 7 CHANGELOG surgeries. A `wave.yaml` (module → version → gate evidence) + one runner would make the 08-29 wave a reviewable, replayable artifact — and version classification would happen at plan time from `git diff <tag>..HEAD` export scans, not from memory (see d4).
2. **tag-release.sh must compile TESTS, not just build.** The single most dangerous gap found today (d3). One line: run `go test -run ZZNONE -count=1 ./...` in the standalone verify.
3. **tag-release.sh needs a `--worktree` mode.** Concurrent sessions keep the main tree dirty for hours; the detached-worktree flow (proven today) should be first-class: script creates its own worktree at HEAD, cuts, pushes, cleans up.
4. **CHANGELOG needs the same rigor as api-stability.** A checker that flags `[Unreleased]` bullets whose cited symbols already exist in a _published_ tag ("shipped-work fiction") would have caught the 08-22 drift and today's leftovers automatically; the changelog-symbols gate checks honesty of citations, not staleness of claims.
5. **Concurrent-session protocol.** Two sessions edited the same docs all day (d6). Minimum: a `docs/SESSION_LOCK.md` heartbeat, or scope conventions (release session owns CHANGELOG + tags; docs-health owns status/archive moves). The dead links their rename shipped suggest rename+reference-update should be one atomic commit behind a link checker.
6. **Env pre-flight for long gates.** One `preflight.sh` (GOCACHE writable, GOTMPDIR space, GOTOOLCHAIN, /mnt dead-check) would have saved the poisoned matrix run (d2). The AGENTS cache gotchas exist because every session rediscovers them by failure.
7. **Version-bump classification belongs in tooling.** `git diff <tag>..HEAD -- <mod>` → exported-symbol scan → minor/patch verdict, surfaced at plan time. Today it was manual greps that the plan got wrong 8 times.
8. **Stop pausing for staged authorization on irreversible-but-batched work without giving the user the full menu upfront** — the staged B1→report→B2 dance cost a full round trip before the user said "GET SHIT DONE". Ask once for the whole run with checkpoints, not per batch.
