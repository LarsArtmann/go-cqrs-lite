GThe Big Question I Cannot Answer Myself

Should we keep going with breaking changes, or declare v3 "done enough" and pivot to additive features?

We shipped 3 genuine v3 breaking changes (ghost bus deletion, memory move, Version uint64). The remaining planned breaking changes (io.Closer removal, Metadata alias break, readmodel deletion) are all verschlimmbessern — they destroy type safety or create import churn for no consumer benefit.

The question:

Is the goal of v3 to "clean up everything the plan says" (even if some cleanups make things worse), or is it to "ship the highest-value improvements and stop when diminishing returns start"?

If the former, we need a way to remove io.Closer without destroying type safety. If the latter, we should mark the remaining breaking changes as "Rejected" and pivot to additive features.

I recommend the latter — but this is a product direction call, not a technical one.
