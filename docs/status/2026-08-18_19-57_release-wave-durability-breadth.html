feature

Durability breadth: 4 engines map tiers instead of rejecting them

metaengine/{pebbleengine,pgengine,bboltengine,badgerengine}/durability.go (new × 4)

  • pebble — strict = WAL + sync, normal = WithAsyncWrites(), relaxed = DisableWAL + async via new pebbleengine.WithDisableWAL() (engineConfig + constructor wiring included).
  • postgres — strict = synchronous_commit=on, normal/relaxed = off, appended to the DSN as a pgx runtime parameter so every pooled connection inherits it; a DSN that already sets synchronous_commit plus a tier is a config error (mirrors the sqlite pragma-conflict rule).
  • bbolt — strict/normal = sync-on-commit (normal documented as an accepted alias: no WAL, no middle tier), relaxed = existing WithNoSync().
  • badger — new Option type + WithAsyncWrites() (SyncWrites plumbing in the constructor); strict = sync, normal/relaxed = async — async is badger's floor because the value log is always written and replayed on open.
  • All mappings are translations of the authoritative stack/durability.go tier table. 16 new tests (4 per engine: translation table, invalid tier, factory round-trip per tier, DSN table for pg) — all GREEN in their dep-isolated modules, pgengine full suite GREEN (104s incl. container tests).
  • dgraph / duckdb / mysql / turso still reject explicit tiers with ErrUnsupportedDurability (turso deferred deliberately: remote libSQL URLs cannot honor per-session pragmas reliably).
