03Fleet Themes

Highest leverage

Bridges built, never crossed

benchkit/v4/system_factory.go:22 · metaengine/v4/sse_replay_test.go:293 · catalog/v4/d2/connections.go:23 · idempotency contract.RunTests

Four times the repo constructed the shared/modern path and then kept the hand-rolled one: benchkit's FactoryFromSystem exists but cqrs-bench still builds v5-doomed stack presets; the SSE test kit (ssetest/sseparse) is used by one example while metaengine tests speak raw TCP; go-output/d2 sits un-pinned beside 633 hand-rolled DSL lines; the idempotency contract suite has never certified the repo's own sqlstore. Under the owner's fleet lens this is the cheapest class to fix: the bridge is already paid for.

Fleet-wide

The golden path teaches gaps

example/taskmanager/http.go:63-65,344-349 · recipes.md §2.47

The example and recipe that fleet apps copy use 1 of ~60 httputil symbols, omit panic recovery and body-size limits, and hand-roll a health endpoint that ignores the system's own rich diagnostics. Every cloned app inherits the gaps; one example diff fixes the whole fleet-to-be.

Accidental matrix

Split-pin drift

go-sse v0.6.2/v0.7.0 · go-idempotency v0.3.2/v0.6.0 · go-atomic-write v0.6.1/v0.6.2

The same production code is tested against two versions of go-sse depending on entry point (metaengine resolves v0.6.2; the integration tier v0.7.0). go-sse v0.7.0 was cut from a chore commit with no CHANGELOG section, which is likely why no sweep caught it. One-command bumps per module; all three diffs verified non-breaking.

Cheap seams

One-liners left on the table

health.CheckFunc ≡ metaengine.HealthChecker · etag.New wrap · sse.LastEventIDFromRequest

The go-health bridge is signature-identical to the existing HealthChecker seam (zero new library deps); docserver repeat visits could be 304s with one etag wrap; malformed Last-Event-ID headers could stop silently replaying the entire journal. Each is a deliberate afternoon, not a project.

04Companions (inverse audits)

cqrs-htmx — fleet-best currency

528/551 resolvable pins at latest; zero production-module lag; new chassis on system.Standard presets and the systemscenario harness. The one red flag: usermgmt's stack/v4 + storage/sql usage is the single strongest coupling blocking the v5 stack deletion.

go-appkit — model v5 citizen

system.New composition root, systemscenario.Adopt, zero legacy stack/storage/idempotency imports in production. 10/57 pins lag by ≤1 week; the sqliteengine v4.7.1 pin predates the v4.8.0 EnforceCap deadlock fix it should not miss.
