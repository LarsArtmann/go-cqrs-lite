03Analysis vs the owner's question

Automerge is the project in this shard that most viscerally sells the owner's Git metaphor: a document literally is “a combination of a JSON object and a git repository”, with history, versions, branches, and merge-on-reconnect. On axis 1 and axis 3 it scores near the ceiling — the client owns the full history, offline is the default mode, and reconnection is a solved, principled merge with documented rules down to “the set of changes since some common ancestor”.

The break with go-cqrs-lite is what gets branched and rebased. In Automerge the unit of change is the CRDT operation, which is final the moment it is minted — there is no intent, no decision step, and therefore no place to re-decide a queued command against fresh server state. Convergence is guaranteed by making every conflict a merge: when two clients write the same property, Automerge “picks one of the concurrently written values” and demotes the loser to a conflicts object. That is precisely the outcome the owner's addendum rules out — in the go-cqrs-lite model a rejected command is a first-class Rejection surfaced to the user after rebase, not a shadow value parked next to the winner. Where the thesis says “only deciders mint authoritative events; a client-side decider may mint speculative local ones”, Automerge says every client mints final facts and the merge makes them true everywhere.

The invariant problem Because writes are never validated by anything but merge rules, domain invariants (e.g. “an order cannot ship while unpaid”) have no enforcement point. go-cqrs-lite's Decide/Apply seam — a pure function that rejects illegal intents — has no Automerge equivalent; the conflicts object is bookkeeping, not adjudication.

Three things are still worth lifting. First, the Repo/DocHandle split — an inert document plus a “live” wrapper that handles storage and network plumbing — is a clean shape for the go-cqrs-lite client runtime around its SQLite-WASM store. Second, the best-effort Go bindings mean a Go server could in principle participate as a peer; that is only useful for peer-shaped features (presence, shared canvases), because a peer has no authority to reject. Third, its 2‑3 × larger bundle than Yjs (~800 kB vs ~20 kB, both self-reported) is the concrete cost of carrying the whole version-control machinery client-side — useful context for how much machinery the owner wants to ship in the worker.

04Fit verdict

COMPETITOR

Automerge competes for exactly the slot go-cqrs-lite targets — the sync layer under a local-first app — and answers the owner's branch-rebase dream by making every client write a final fact that merges instead of an intent that re-decides. Adopt its branch/merge vocabulary and Repo/DocHandle runtime shape; do not adopt its write model, because it structurally cannot express server-authoritative Commands or Rejections.
