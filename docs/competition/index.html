00Summary

The sweep validates go-cqrs-lite’s founding bet: the industry converged on merge-based convergence, not decision boundaries. 17 of 22 projects mint facts client-side and cannot express a queued Command re-decided against server state — a Rejection is inexpressible in their model. Only Zero (optimistic local mutations, server re-decides and rolls back), Ditto (local write-validation boundary), and PowerSync (queued uploads) have any Command-shaped write path, and none of the three shares domain logic with the client.

The bottom line The owner’s Question has no off-the-shelf answer anywhere in the landscape — and the assembly kit for building it exists: Zero’s optimistic-effects rollback, PowerSync’s upload queue, Loro’s branch bookkeeping, Liveblocks’ fix-ops corrections, CouchDB’s revision trees. The read-side half is solved many times over (TinyBase proves it in 7–17 kB); the command-side half is go-cqrs-lite’s alone to finish.

The three exemplars share one limit: none shares the decision logic itself with the client. Zero’s server re-decides from scratch; Ditto’s validation is engine-internal; PowerSync’s queue drains into arbitrary server code. The Question’s logic-sharing clause (“share Commands & Events & Queries with the client, as long as they touch no protected resources”) remains unclaimed territory — which is precisely the client-safe decider seam of the 2026-11-22 report.

What the L4 tier of the contracts proposal (D40/D41) can lift, entry by entry:

+

+
