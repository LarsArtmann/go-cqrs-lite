Liveblocks Yjs

Liveblocks’ hosted persistence and sync for raw Yjs documents: client-minted CRDT updates, server-relayed, room-scoped permissions enforced server-side. The reference example of what the owner’s Question looks like when the write model is deliberately left out entirely — and offline is still a beta flag.

00The question this page answers

The owner’s lens (brief, 2026-11-22) “How can we make the browser OWN its data smartly, be as local-first as possible (i.e. including Commands), but at the same time be able to smartly branch-rebase (like Git) with a server as soon as the client has a connection again! All that transparently. We need Commands & Events that only happened on the client. And we need to share the logic for Commands & Events & Queries (as long as they do not access protected server resources) with the client, efficiently.”

Liveblocks Yjs’ answer: local edits apply instantly and merge automatically (CRDT), the server is a relay + persistence authority for room access — and that is the whole answer. There is no command, no validation of business meaning, no event concept; the client owns the document in memory and the provider owns it durably. Offline support exists but is explicitly experimental.

Landscape: offline reads/writes only via “Beta option: offlineSupport_experimental: true”; data size “Limited by memory” (2026-11-22). Not a user-exportable local database.
2 · Local commands CLIENT-MINTS-FACTS What syncs is “Yjs encoded updates” client→server (landscape, 2026-11-22) — the client authors CRDT ops directly; the provider judges shape and access, never business meaning. Same class as LiveStore’s store.commit gap (research report 2026-11-22), minus even the event-table schema layer.
3 · Reconnect rebase CRDT — automatic, invisible Conflict handling “Automatic via CRDT” (landscape, 2026-11-22); “Local edits apply immediately, syncing in the background” and “Keep working offline. Changes sync automatically when reconnected” (product page, 2026-11-23). No branches, no rebasing — convergence is total and semantics-free.
4 · Client-local Commands & Events NO — and offline itself is beta No command/event/query concepts exist in the product surface (fetched docs, 2026-11-23). The prerequisite — durable offline operation — is explicitly gated: offlineSupport_experimental: true (landscape, 2026-11-22). Anything CQRS-shaped would be hand-rolled on top of the Yjs doc.
5 · Logic sharing + protected resources TS/React SDK client-side; server-enforced room permissions Client is @liveblocks/client + framework bindings; server side is Liveblocks’ own infrastructure, not your code. The protected-resource notion is real and clean: “user permissions can be set per room… enforced on Liveblocks servers, so a read-only user can never modify a document, even with a modified client” (permissions doc, 2026-11-23) — default/group/user access levels.

02Liveblocks Yjs vs go-cqrs-lite

Dimension Liveblocks Yjs go-cqrs-lite
Write authority Nobody — CRDT convergence; only room access is enforced The decider — Decide + Rejection against current stream state
What syncs Yjs updates (ops) Events (immutable facts) + causation metadata linking each to its Command
Offline story Experimental flag; in-memory only L4 concept: queued Commands, server decide on reconnect (research 2026-11-22)
Protected resources Room ACLs on Liveblocks servers (read/write per user/group) Deciders with server-only resources stay server-side; pure deciders/folds are the shareable subset
Hosting Provider-run (proprietary) Self-hosted library, fleet-first, v4/v5 dual-support
Reconnect UX Perfect but semantics-free: everything merges Research target: Git-like branch/rebase of Commands onto authoritative facts — meaning preserved
Fit verdict: ORTHOGONAL A hosted CRDT persistence service for collaborative documents. Nothing in a Go CQRS library consumes or competes with it; it neither solves nor obstructs the Question’s command half. Its value here is calibration: this is the market’s default answer when you give up on write semantics entirely.

03What to steal

+
Server-enforced room permissions as the share boundary “Enforced on Liveblocks servers… even with a modified client” — the correct trust rule for the L4 tier: the client may share all pure logic, but access decisions are never computed client-side.
+
Honest experimental labeling Offline support ships behind offlineSupport_experimental rather than being marketed as done — the same discipline this repo applies with evidence-gated L4 (research 2026-11-21: parked behind a named consumer).
+
<1 ms local, 60 Hz remote refresh budget The landscape entry pins “<1ms local; other clients up to 60 times per second (16ms), configurable” (2026-11-22) — a concrete, honest two-tier latency budget for any client tier this repo designs.
