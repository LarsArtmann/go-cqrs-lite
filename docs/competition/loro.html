03Analysis vs the owner's question

Loro is what happens when a CRDT library takes the owner's Git metaphor seriously: full version history “like Git, even during real-time collaboration”, frontiers and version vectors as first-class API surface, checkout(version) time travel, and a docs section literally titled “Is Loro Right for You?” that tells you when to walk away. It is the best-engineered state-branching substrate in this shard — and its own “consider alternatives” list is the strongest independent argument for go-cqrs-lite's server-decided model: if your application requires strong consistency, a CRDT is the wrong tool. Most domain apps are exactly that.

Still, two mechanisms are directly stealable for the client-side branch/rebase machinery. First, pending-import tracking: Loro distinguishes “my import queue is empty” from “the document is synced”, models operations that arrived but cannot integrate yet as pending ranges, and persists them across restarts via exportPendingUpdates(). That is structurally the same problem as go-cqrs-lite's queued commands surviving a page reload: durable, inspectable, not-yet-integrated work, with an explicit “needs dependencies” state the UI can show. Second, version vectors as the rebase checkpoint: exchanging cheap version metadata before shipping bytes is exactly the “fetch base, then push delta” shape the reconnect protocol needs (§10.2: push queued commands, pull authoritative facts, replay).

Same wall as Automerge and Yjs Checkout is read-only time travel; there is no API for “re-run my pending changes against the new state and tell me which ones are now illegal”. Merge remains the only conflict outcome — no Rejections. And the port bench has no Go seat (TypeScript, Rust, Swift, Python), so a Go server cannot hold a Loro doc without new bindings; the ~970 kB WASM binary is also the heaviest in the shard.

Net: as a dependency for go-cqrs-lite, Loro is interesting only via its ideas. As a rival write model it concedes the thesis's home turf in its own introduction — strong consistency is precisely what Command re-decision buys.

04Fit verdict

PATTERN-TO-ADOPT

Loro is not credible competition for the write model (its docs disqualify itself for strong-consistency domains), but its version-control API — frontiers, checkout, durable pending imports, version-vector deltas — is the best blueprint in the landscape for the client-side branch bookkeeping that go-cqrs-lite's offline Commands will need.
