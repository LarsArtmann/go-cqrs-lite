# Policy (decided 2026-10-08, docs/adr/0152-fleet-first-module-topology-v5-dual-support.md):
#   - Untagging means STOP TAGGING. Existing tags are never deleted and stay
#     proxy-served; versions.json keeps recording the latest tag (tag truth).
#   - Entries are the trains with ZERO consumers in the first-party fleet
#     (2026-10-08 who-uses audit, Appendix B) plus internal tools and examples
#     that never needed release trains in the first place.
#   - Driver-tier rule: engines/drivers/transports TAG ON FIRST CONSUMER.
#     While listed here, a driver is capability-proven by its integration/v4
#     suites only. When a fleet app starts importing one, remove it here in
#     the same commit that adds the consumer, then tag.
#   - Exception: cmd/cqrs-lint/v4 keeps its release train (cross-repo consumers:
#     buildflow, gomend).
#
