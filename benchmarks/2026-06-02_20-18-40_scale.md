## Key Observations

- **Event creation**: 4M/sec sustained. The 3 allocs/event (ImmutableEvent + Metadata map + payload copy) is the ceiling.
- **Command dispatch**: 6.5M/sec with 100 registered handlers. Near-zero overhead per dispatch.
- **Query dispatch**: 8M/sec with 1,000 registered handlers. Scales linearly with handler count.
- **Event publish (MemoryBus)**: 43.7M/sec — the bus is NOT the bottleneck. Publish is cheaper than event creation.
- **Decider Load at scale**: 588K loads/sec for 10K aggregates with 50 events each. Each load folds 50 events — that's 29.4M fold operations/sec.
- **Projection processing**: 1.9M projection-events/sec with 100 projections subscribed. That's 100 × 100K = 10M event deliveries in ~5.4 seconds.
- **Full pipeline**: 160K aggregates/sec end-to-end (create → save → publish → project → query). This is the real-world throughput number.
- **Concurrent**: 6.7M commands/sec with 8 goroutines confirms the dispatcher is contention-free under parallelism.

## Bottlenecks Identified

1. **Listing at 10K aggregates**: 119 ops/sec, 6.3 MB/op — `InMemoryAggregateReader.ReadAll()` scans every event on each call. Needs caching.
2. **Projection registration**: 7.8K/sec — registration sets up subscriptions, acceptable for startup-time operation.
3. **Event save at scale**: 2.6M events/sec writing 10K aggregates × 100 events — memory store append is fast but the 302M allocs for 1M events is significant GC pressure.
