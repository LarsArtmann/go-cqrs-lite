# cqrs-gen — Code Generator

[![Go Reference](https://pkg.go.dev/badge/github.com/larsartmann/go-cqrs-lite/cmd/cqrs-gen/v4.svg)](https://pkg.go.dev/github.com/larsartmann/go-cqrs-lite/cmd/cqrs-gen/v4)

Derives the wiring around marked command, query and event structs: typed
constructors, typed registration for the composition root, and optional
catalog declarations. It writes one `cqrs_gen.go` into each package that holds
markers, so a wire name is stated once and nothing is hand-copied.

## Install

```bash
go install github.com/larsartmann/go-cqrs-lite/cmd/cqrs-gen/v4@latest
```

## Markers

A marker carries the **wire name** that will be registered. Two equivalent
forms are supported: a leading comment, or a struct tag on a blank `_` field.

```go
//cqrs:command user.create
type CreateUserCmd struct {
    *command.BasicCommand
    Name  string
    Email string
}

//cqrs:query user.get
type GetUserQuery struct {
    *query.BasicQuery
    UserID id.StreamID
}

//cqrs:event user.created
type UserCreated struct {
    UserID id.StreamID
}
```

```go
type CreateUserCmd struct {
    _    struct{} `cqrs:"command:user.create"`
    Name string
}
```

When both are present on the same type, the comment marker wins.

Three rules keep a package free of duplicated wire names:

- A marker value that names a package-level declaration **is** the reference:
  `//cqrs:query qryOpenTasks` uses `qryOpenTasks` wherever the generated code
  needs the wire name.
- Otherwise the generated code reuses an existing package-level constant with
  the same string value, so a package that already declares
  `const cmdCreateTask = command.Type("task.create")` keeps it.
- Otherwise the generator declares the constant itself:
  `CreateTaskCmd` becomes `CommandCreateTask`, `GetUserQuery` becomes
  `QueryGetUser`, `UserCreatedPayload` becomes `EventUserCreated`.

An event marker takes two optional parts, in any order:

- a direction for the catalog: `sends` (the default) or `receives` for a copy
  of another service's contract;
- the payload's schema version, `v2` and up: the generated constructor stamps
  it through `event.WithSchemaVersion` and the catalog declaration carries it
  as the message version. Without it the constructor stamps version 1, so a
  payload change is one marker edit and every construction site follows.

```go
//cqrs:event invoice.received receives v3
type InvoiceReceived struct {
    Ref string
}
```

## Usage

```bash
cqrs-gen .                 # every package below the working directory
cqrs-gen ./...             # the same, spelled the way the go command spells it
cqrs-gen --catalog ./...   # also declare every marked message for the catalog
cqrs-gen --check ./...     # CI gate: fail when a generated file is missing or stale
cqrs-gen --list ./...      # print the discovered markers, write nothing
```

Put `//go:generate cqrs-gen .` in one file of a package to regenerate it with
`go generate`.

### Generated output

For one package holding the three marked structs above, `cqrs-gen --catalog .`
writes this file, complete:

```go
// Code generated by cqrs-gen. DO NOT EDIT.

package users

import (
	"context"

	"github.com/larsartmann/go-cqrs-lite/catalog/v4"
	"github.com/larsartmann/go-cqrs-lite/command/v4"
	"github.com/larsartmann/go-cqrs-lite/event/v4"
	"github.com/larsartmann/go-cqrs-lite/id/v4"
	"github.com/larsartmann/go-cqrs-lite/query/v4"
	"github.com/larsartmann/go-cqrs-lite/system/v4"
)

const (
	CommandCreateUser command.Type = "user.create"
	QueryGetUser      query.Type   = "user.get"
	EventUserCreated  event.Type   = "user.created"
)

// NewCreateUserCmd stamps the user.create envelope onto the payload; options reach the library constructor.
func NewCreateUserCmd(
	streamID id.StreamID,
	payload CreateUserCmd,
	opts ...command.Option,
) (CreateUserCmd, error) {
	basic, err := command.New(CommandCreateUser, streamID, opts...)
	if err != nil {
		return CreateUserCmd{}, err
	}

	payload.BasicCommand = basic

	return payload, nil
}

// RegisterCreateUserCmd registers user.create on the composition root.
// decide runs against the state folded from the command's stream.
func RegisterCreateUserCmd[State any](
	sys *system.System,
	streamType id.StreamType,
	decide func(context.Context, CreateUserCmd, State, event.Version) ([]event.Event, error),
) error {
	return system.RegisterCommand[CreateUserCmd, State](sys, CommandCreateUser, func(ctx context.Context, cmd CreateUserCmd) system.Op[State] {
		return system.Execute(ctx, cmd.StreamID(), streamType, func(state State, version event.Version) ([]event.Event, error) {
			return decide(ctx, cmd, state, version)
		})
	})
}

// NewGetUserQuery stamps the user.get envelope onto the payload; options reach the library constructor.
func NewGetUserQuery(
	payload GetUserQuery,
	opts ...query.Option,
) (GetUserQuery, error) {
	basic, err := query.New(QueryGetUser, opts...)
	if err != nil {
		return GetUserQuery{}, err
	}

	payload.BasicQuery = basic

	return payload, nil
}

// RegisterGetUserQuery registers user.get on the composition root.
func RegisterGetUserQuery[R any](
	sys *system.System,
	handler func(context.Context, GetUserQuery) (R, error),
) error {
	return system.RegisterQuery[GetUserQuery, R](sys, string(QueryGetUser), handler)
}

// NewUserCreatedEvent builds the user.created event for a stream at schema version 1; options reach event.New.
func NewUserCreatedEvent(
	streamID id.StreamID,
	streamType id.StreamType,
	version event.Version,
	payload UserCreated,
	opts ...event.Option,
) (event.Event, error) {
	options := make([]event.Option, 0, len(opts)+1)
	options = append(options, event.WithSchemaVersion(1))
	options = append(options, opts...)

	return event.New(EventUserCreated, streamID, streamType, version, payload, options...)
}

// CatalogMessages returns the catalog declarations of every marked message in this package.
func CatalogMessages(opts ...catalog.MessageOption) []catalog.MessageConfig {
	return []catalog.MessageConfig{
		catalog.Command[CreateUserCmd](catalog.MessageID(CommandCreateUser), opts...),
		catalog.Query[GetUserQuery](catalog.MessageID(QueryGetUser), opts...),
		catalog.Event[UserCreated](catalog.MessageID(EventUserCreated), catalog.Sends, opts...),
	}
}
```

Per marked struct that is:

| Kind    | Generated declarations                                                                                                                                                       |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| command | `NewXCmd(streamID, payload, opts...)`: typed constructor that stamps the command envelope; options reach `command.New`                                                       |
| command | `RegisterXCmd(sys, streamType, decide)`: composition-root registration, no hand-written `Op` wrapper                                                                         |
| query   | `NewX(payload, opts...)`: typed constructor that stamps the query envelope; options reach `query.New`                                                                        |
| query   | `RegisterX[R](sys, handler)`: composition-root registration                                                                                                                  |
| event   | `NewXEvent(streamID, streamType, version, payload, opts...)`: typed constructor binding wire name to payload type and stamping the schema version; options reach `event.New` |
| event   | `RegisterXHandler(bus, handler)` with `--handlers`: subscribes and decodes with `event.DecodePayloadAuto`                                                                    |
| any     | `CatalogMessages(opts...)` with `--catalog`: `catalog.Command`, `catalog.Query`, `catalog.Event` entries                                                                     |

The wiring shrinks to one line per command, and construction to one call that
cannot pair a wire name with the wrong payload type:

```go
func registerCommands(sys *system.System) {
	must(users.RegisterCreateUserCmd(sys, streamType, decideCreateUser))
}

func create(streamID id.StreamID, sys *system.System) error {
	cmd, err := users.NewCreateUserCmd(streamID, users.CreateUserCmd{Name: "Ada", Email: "ada@example.com"})
	if err != nil {
		return err
	}

	return sys.CommandDispatcher().Dispatch(context.Background(), cmd)
}
```

A struct that embeds `*command.BasicCommand` or `*query.BasicQuery` is passed
to handlers by value and gets the typed constructor. Every other shape is
passed by pointer and keeps its own construction. A package that already
declares `NewX` keeps that constructor, because it may validate: the generator
never adds a second one.

### Legacy wiring

Apps that dispatch through a bare `command.Dispatcher` or `query.Dispatcher`
instead of `system.New` get typed handlers for that seam:

```bash
cqrs-gen --target=dispatcher ./...
```

## Flags

| Flag         | Default  | Description                                                              |
| ------------ | -------- | ------------------------------------------------------------------------ |
| `--type`     | `all`    | Kinds to generate: `command`, `query`, `event`, or `all`                 |
| `--target`   | `system` | Shape of command and query registration: `system` or `dispatcher`        |
| `--output`   | none     | Write one file for a single package instead of `cqrs_gen.go` per package |
| `--pkg`      | scanned  | Package name of the `--output` file; only valid together with `--output` |
| `--catalog`  | off      | Also declare every marked message for the catalog                        |
| `--check`    | off      | Fail when a generated file is missing or stale; write nothing            |
| `--list`     | off      | Print the discovered markers; write nothing                              |
| `--handlers` | off      | Also generate typed event subscription handlers                          |

Paths are directories or files. A path ending in `...` means every package
below the directory. `vendor`, `node_modules`, `testdata`, hidden directories,
test files, and files the build excludes (build tags, GOOS/GOARCH suffixes)
are never scanned; a directory given on the command line is always scanned.

## Errors instead of silent output

The generator exits non-zero, naming the file and line, when:

- a marker carries no wire name, or an option it does not understand;
- an event marker names two different schema versions, or one below 1;
- a marker sits on anything but a plain struct (a generic type, an alias,
  another kind of declaration);
- two structs claim the same wire name;
- a directory mixes several packages;
- a generated name collides with a declaration the package already has.

Generating without any marker prints a notice and exits 0; `--check` fails
instead, so a mistyped path can never pass a pipeline vacuously.

## Dependencies

The scanner and generator use only the Go standard library (`go/ast`,
`go/build`, `go/parser`, `go/format`). The command line is built on
[cmdguard](https://github.com/larsartmann/cmdguard). Generated code imports the
go-cqrs-lite modules its declarations need (`command`, `query`, `event`, `id`,
`system`, and `catalog` with `--catalog`), so those must be requirements of the
package's module. Output is always passed through `go/format`, so the
generated file is valid, gofmt-clean Go.
